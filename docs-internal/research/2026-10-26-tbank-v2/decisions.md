# T-Bank v2 — operator decisions

Walked item by item with the operator on 26.10.2026 (s198) over [brainstorm-agenda.ru.md](brainstorm-agenda.ru.md). Where the agenda
or a report disagrees, this file wins.

| ID | Decision |
|---|---|
| D1 | Same EDD product (`tinkoff-kupi-v-kredit`), new private repo `kalbac/woodev-vkredit`, same plugin folder `woodev-vkredit` and main file `woodev-vkredit.php`, version **2.0.0** so the update reaches every installed site. |
| D2 | Installed-site data stays exactly as in v1: gateway id `wc_tinkoff_kvk`, settings key `woocommerce_wc_tinkoff_kvk_settings`, order meta `_wc_wc_tinkoff_kvk_*`, the webhook URL format given to the bank — no migration. The two hooks misspelled `geteway` are renamed to the correct spelling; the old names are NOT kept as aliases and go into the removed/changed-hooks list announced with the release, as for CDEK, Russian Post and Yandex (skill rule, PR #1465). The five correctly named hooks stay. |
| D3 | Release 1 supports the classic checkout only, as v1 did; the product card says so honestly. A framework payment-method bridge for the Cart/Checkout blocks is the immediate NEXT task after release 1 (not "some day"), reusable by every payment plugin. |
| D4 | Product-page informer stays — merchants use it. The divisor 19 is the bank-recommended average (operator, from a T-Bank integration lead years ago), not invented: it becomes a gateway setting with default 19; the existing filter stays; a zero or invalid divisor never divides (falls back to the default); output escaped. Promo codes stay as in v1 + escaping + the `default` fallback code. A "Оформить кредит/рассрочку" button on the product card is wanted by some merchants — NOT in 2.0.0; discuss separately (card to file once the repo exists). Cart widget not in 2.0.0. |
| D5 | Release 1: no automatic Cancel/Commit/refund calls, as in v1; the order page and gateway description carry a short instruction on refunding from the bank cabinet. Most known merchants have auto-confirm ON (operator), so a signed application cannot be cancelled through the API. Merchants did have cancellation problems in the past (details not remembered) — recover them from the Support AI / FreeScout ticket history before the spec decides any cancel behaviour. |
| D6 | «Долями», T-Kassa (acquiring) and bank transfer are not in 2.0.0. After 2.0.0 the T-Bank line expands (`Woodev_Payment_Gateway_Plugin` registers several gateways; price from 5 000 ₽): one plugin vs several by buyer intent is a separate decision — card #1474. Operator idea for every future payment plugin + our carrier plugins: pay the order WITHOUT delivery online, delivery paid on receipt, stated at checkout — card #1475. Neither is in 2.0.0. |
| D7 | Gateway settings stay on the standard WooCommerce payment-gateway settings screen (WooCommerce → Платежи → Т-Банк), as in v1. Rule (operator): a payment plugin uses `woodev-settings` ONLY for extra options unrelated to the gateway settings; T-Bank 2.0.0 has none, so no `woodev-settings` tab and no adapter (gap G3 is not needed). The API password becomes a password-type field. |
| D8 | Licence not in force → the gateway is not offered at checkout and no NEW bank action starts; bank status callbacks for existing applications, order viewing and settings always work — exactly the carriers' `License_Gate` contract. Operator: this is the BASE DEFAULT for every Woodev plugin; any plugin without the gate must say so explicitly; plugins that need no licence key at all are the only natural exception. |
| D9 | Short three-step setup wizard on the framework `woodev/setup/` engine: (1) shop id, showcase id, API password; (2) connection check — one demo-mode test application on a button press; (3) switch to live mode with a checklist (domain, HTTPS, down payment, the callback address in the bank cabinet). The bank is called only on a button press, never on a schedule. No v1 migration screen (settings stay in the same key). |
| D10 | The payment module is not trimmed; #639 stays frozen (T-Bank 2.0.0 is the same Hosted/loans type and adds no data). A comment on #639 records the wave-0 findings: no Blocks payment bridge exists, and the T-Bank line (#1474) is the trigger to revisit. |
| D11 | Fix every v1 defect found (name swap, order lookup by our own order number, callback registered in demo mode too, escaping, raw callback body never logged, kopeck-exact amounts, the never-written order-card rows). Amount window: hidden below 3 000 ₽ and above 500 000 ₽ by default; a merchant setting «Принимать первоначальный взнос» (mirrors the bank cabinet) raises the ceiling to 1 000 000 ₽. RUB only. |
| D12 | Answers to the open bank questions (operator, from support experience — not measured): (Q2) the bank cabinet needs the shop DOMAIN only, e.g. `https://example.com` with NO trailing slash, in at least three fields: «Адрес сайта», «Success URL», «Fail URL» — the wizard's live-mode checklist and the docs say so; (Q1/Q6) the old `forma.tinkoff.ru` API host still works (the bank re-issued SSL for its domains; woodev.ru's two other T-Bank plugins — acquiring and bank transfer — still call old URLs successfully); (Q4) callback retry intervals exist — read the webhook section of the docs; (Q3) demo scenarios — read the docs; (Q6-sum) the bank rejects an application when the item sum differs from the order sum by even one kopeck — seen in support with tax rates, promo codes, kopeck shipping costs: release 2.0.0 must make the item list reconcile to the kopeck by construction and test those cases; (Q7) auto-confirm was usually on in support cases, but the operator is not sure — design must not depend on it. Live keys exist (from the T-Bank contact, no cabinet login); the operator will put them into a local gitignored env file. forma.tbank.ru timed out from the Mac (RU IP) on 26.10.2026 — the operator will check docs access. |
| D13 | Release 2.0.0 is not a bare port: the plugin has barely changed since its first release and is outdated as a product. Before the spec, prepare a list of improvements useful to merchants and their buyers, walked with the operator item by item. |

## Improvements for 2.0.0 (walked over [improvements.ru.md](improvements.ru.md), 26.10.2026)

| ID | Decision |
|---|---|
| I1 | Kopeck-exact item reconciliation with clean lines — already D12; in. |
| I2 | Bank refusal reasons: buyer gets a calm generic text; merchant gets the human reason and the fix in the debug log only (merchant-diagnostics rule) and in the wizard's connection check; no extra bank calls. In. |
| I3 | Order-page panel «Заявка в Т-Банке» (manage_woocommerce only): status in words, product, bank, term, monthly payment, credit amount, down payment, signing type, cooling-off end («не отгружайте до …»), «not committed — confirm in the bank cabinet», application number, the refund amount actually transferred + the note that the instalment fee is not refunded. Shows only what the bank returned. New meta keys under the existing `_wc_wc_tinkoff_kvk_` prefix (additive). In. |
| I4 | «Обновить статус» button in the order panel: one bank `Info` call per press, at most once per 30 s per order, manage_woocommerce + nonce, no scheduled polling. A SAFETY NET only — the bank callback stays the primary path. Works while the licence is not in force (checking an existing application is not a new action, like carrier tracking). In. |
| I5 | Late `signed` on an already cancelled order is not dropped: order → `on-hold` (not `processing` — stock may have been released), an order note, and the standard WooCommerce admin "needs attention" e-mail. In. |
| I5a | Measured from WC source (`wc_cancel_unpaid_orders()`, rig latest-stable): the timer cancels only `pending` orders created via `checkout`/`store-api`, only when stock management is on and `woocommerce_hold_stock_minutes` ≥ 1; filter `woocommerce_cancel_unpaid_order( bool, WC_Order )` can veto per order. Decision: two gateway settings — checkbox «Не отменять заказ по расписанию WooCommerce» (default ON) and «сколько держать заказ до ответа банка» (default 72 h until the bank's application lifetime is read from the docs). While ON and the order has a live application younger than that limit, the plugin vetoes WC's auto-cancel through the filter; past the limit WC cancels as usual. I5 stays the last safety net. No merchant notice about WC settings needed. |
| I6 | Thank-you page + «Мои заказы»: short state text (filling / banks reviewing ≤2 min / approved — sign / signed / declined — pay another way) and «Вернуться к заявке» until signed (re-`Create` with the same order number returns the same application; ≤1/min, ≤10 per order). On `approved` a customer note with the signing link (standard WC «Заметка к заказу» e-mail). One safety `Info` on return to successURL (≤1 per 5 min, ≤10 per order). No scheduled calls. Licence not in force → no «Вернуться к заявке» (new action); `Info` always works. In. |
| I7 | After a bank refusal the order goes to `failed` (not `cancelled`) so the buyer can pay another way. In. |
| I8 | Hint «the bank issues the fiscal receipt — do not issue a second one» in the wizard, the order panel and docs. In. |
| I9 | Per-programme (promo code) min/max amount window, on top of the global window (D11). In. |
| I10 | Short checkout text: what happens next and the bank's terms. In. |
| I11 | «Т-Банк: статус» column in the orders list — after 2.0.0 (card). |
| I12–I14 | Programmes per category/product, approvals analytics, monthly payment «from bank data» on the storefront — not taken. |

No API password exists — `d-docs.md` decides which features (status refresh, `Info`) remain possible; if `Info` needs the password, I3/I4/I6 fall back to webhook data only and the spec says so.
- Autonomous: the spec for 2.0.0 from D1–D13 + I1–I11, the plugin skeleton and implementation in `kalbac/woodev-vkredit`, every piece through a Codex critic. Not started: the Blocks bridge (#1476) until 2.0.0 ships.
- Left for the operator: framework release, plugin release and EDD upload (prepared, published only on his word); anything judged by eye is parked for his look.

Overnight target (operator): go as far as possible, up to a pre-release state. |
