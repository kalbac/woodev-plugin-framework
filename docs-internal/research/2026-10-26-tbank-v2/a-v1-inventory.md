| Redirect / iframe | **READ:** hosted payment interface is a redirect to the bank’s returned form URL; v1 does not embed an iframe in checkout (`woodev/payment-gateway/class-payment-gateway-hosted.php:110-130`; `includes/class-gateway.php:341-348`). |
| Customer return URLs | **READ:** `failURL` is the Woo order payment URL, `successURL` is order received URL, and `returnURL` is cancel-order URL (`includes/api/class-wc-tinkoff-api.php:43-46`). | Callback/IPN | **READ:** in production the plugin constructs `wc-api=wc_gateway_tinkoff_kvk_ipn_{md5(json_encode([shop_id, showcase_id]))}` and registers the corresponding `woocommerce_api_{endpoint}` action (`includes/class-gateway.php:47-72`). Thus a site at `https://shop.example` gives `https://shop.example/?wc-api=wc_gateway_tinkoff_kvk_ipn_<derived-hash>`; actual host and hash are shop-specific. The route has no request signature/HMAC check; callback fields are required and amount/order are checked, but status is fetched from T-Bank’s authenticated `/{order_number}/info` API (`includes/api/class-wc-api-ipn-response.php:150-165,268-299`; `includes/api/class-wc-tinkoff-api.php:146-160`). **READ:** this is route obscurity plus authenticated status re-fetch and amount comparison, not signed callback authentication. |
| Status to Woo order state | **READ:** API status `signed` is approved unless the optional cooling period is enabled and not complete; `approved` is held; `canceled` and `rejected` are cancelled; any other or failed/invalid status enters failed handling (`includes/api/class-wc-api-ipn-response.php:83-93,107-147`; framework dispatch in `woodev/payment-gateway/class-payment-gateway-hosted.php:508-545`). Base hosted behavior calls Woo `payment_complete()` for approved orders (Woo chooses its normal paid state), marks held orders `on-hold` by default, canceled statuses become Woo `cancelled`, and unrecognized statuses go through failure handling (`woodev/payment-gateway/class-payment-gateway.php:1420-1449`; `woodev/payment-gateway/handlers/abstract-payment-handler.php:310-327,375-390,400-414`; `woodev/payment-gateway/class-payment-gateway-hosted.php:508-545). Gateway explicitly allows `on-hold` as a valid payment status (`includes/class-gateway.php:74,89-95`). **UNVERIFIED:** no runtime/IPN test was run; cooling-period case follows inspected code only. |
| Product page widget/button | **READ:** `includes/product.php` adds a configurable informational notice at `woocommerce_single_product_summary` priority 25 when product price is at least 3000 (`includes/product.php:7-27`). `%payment_amount%` is estimated as floor(price / filtered rate 19); optional button function is not hooked (commented hook at `:11`, method `:30-39`). There is no cart widget. |
| Promo codes | **READ:** settings accept rows `{name, code, enabled}`; admin UI escapes field values (`includes/class-gateway.php:242-247,260-292`; `includes/html-promo-codes.php:48-60`). Checkout displays one enabled code as hidden input or multiple as radio choices (`includes/class-gateway.php:101-143`); selected code is added as `promoCode` to T-Bank request (`includes/api/class-wc-tinkoff-api.php:59-62`). |
| Demo/test mode | **READ:** environment setting exposes production and test (`includes/class-gateway.php:37-40`, settings field at `:202-255`). Test mode uses `/create-demo`, prefixes showcase ID with `demo-` for info lookup, and allows admins to select `demoFlow` and `initialStage` (`includes/api/class-wc-api-request.php:11-15`; `includes/api/class-wc-tinkoff-api.php:64-76,148-154`; `includes/class-gateway.php:145-178`). |

Treat bank refund/cancellation as unsupported by this plugin. **UNVERIFIED:** WooCommerce’s exact admin UX for a manual refund was not exercised. |
| Logging | **READ:** gateway logs exception messages on create failure (`includes/class-gateway.php:341-348`); framework API request logging is initialized by gateway base (`woodev/payment-gateway/class-payment-gateway.php:299-300`) and response handler logs sanitized-response method output (`woodev/payment-gateway/class-payment-gateway-hosted.php:367-372,831-842`). ## 4. Code red flags

Severity is a source-based impact estimate; none was dynamically reproduced.

| Severity | Concrete situation → issue | Evidence |
|---|---|---|
| High — security / privacy | With gateway debug logging on, a callback response is sent through `to_string_safe()`, but that method returns the full raw decoded response; customer/order PII can be logged. The callback itself has no signature/HMAC check; it relies on derived URL and re-fetching authenticated T-Bank status plus amount matching. | **READ:** `includes/api/class-wc-api-ipn-response.php:302-308`; response logged at `woodev/payment-gateway/class-payment-gateway-hosted.php:367-372,831-842`; callback route and validation `includes/class-gateway.php:47-70`; required fields/amount `includes/api/class-wc-api-ipn-response.php:268-299`. |
| High — stored/reflected output injection | An enabled merchant promo name is interpolated raw into checkout label HTML (`$name` at `%4$s`); a crafted stored name can inject markup/script in classic checkout. Product informer setting is also echoed after filters without HTML escaping (`includes/product.php:21-27`). | **READ:** `includes/class-gateway.php:133-135`; `includes/product.php:21-27`. Promo admin UI cleans with `wc_clean`, but that does not establish safe HTML output. |
| High — amount semantics | Loan credit amount and first-payment values are cast to integer (`intval`), so a fractional amount from T-Bank is truncated before display/use; e.g. 1234.99 becomes 1234. | **READ:** `includes/api/class-wc-api-ipn-response.php:194-213`. Core order total remains separate; impact on displayed credit figures only is the code-supported claim. |
| Medium — callback state/race | Handler refuses any callback once order no longer needs payment (`woodev/payment-gateway/class-payment-gateway-hosted.php:484-497`), and marks cancelled/rejected immediately (`:533-537`). If a late callback says `signed` after an earlier `canceled`/`rejected` response moved order to cancelled, a later valid approval is treated as duplicate and does not recover the order. | **READ:** cited flow. Real ordering/frequency **UNVERIFIED**. |
| Medium — callback contract mismatch | Callback validation requires `committed`, but does not validate its value; callback `status` is only checked for existence, while authoritative status comes from info API. A callback can therefore carry contradictory fields without being rejected (although bank status is re-fetched). | **READ:** `includes/api/class-wc-api-ipn-response.php:268-299`, `:150-165`. |
| Medium — request data correctness | Contact name fields are reversed: request maps billing first name into `lastName` and billing last name into `firstName`. | **READ:** `includes/api/class-wc-tinkoff-api.php:47-55`. |
| Medium — display arithmetic | Product page estimate divides price by filtered rate and floors it; an unset/zero filter value causes division by zero, while normal values are only a rough fixed-term estimate. | **READ:** `includes/product.php:21-25`. Zero-filter scenario is a concrete external-filter input; runtime behavior not executed. |
| Low — admin output | Promo code values/attributes are escaped in admin, but `checked()` is given saved data directly; no obvious high-impact finding there. No further issue logged. | **READ:** `includes/html-promo-codes.php:55-60`. |

## 5. WooCommerce Cart/Checkout blocks

**READ:** v1 registers no payment method integration for Blocks: plugin declares only `supported_features => ['hpos' => true]` (`woodev-vkredit.php:71-79`), does not define a Blocks integration class in its own files, and the bundled framework’s block compatibility checks require explicit `supported_features['blocks']['checkout'] === true` (`woodev/handlers/blocks-handler.php:47-66`). **Expected merchant view:** on a Checkout Block page this gateway is not offered as a selectable payment method; shoppers must use another available block method or the merchant must use classic checkout for this gateway. **UNVERIFIED:** exact WooCommerce notice/copy and behavior on a particular WC version were not tested.
