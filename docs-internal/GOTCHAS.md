### [js/*] — JavaScript language traps
- [js/jquery-event-worlds] `jQuery( el ).trigger( 'change' )` dispatches NO DOM event — jQuery walks its own handler registry and calls a native method only for a few types, `change` not among them — so `document.body.addEventListener( 'change', … )` never runs. On a WooCommerce checkout that is the MAIN path, not an edge case: select2/selectWoo (what §8's suggest takeover turns the locality field into) reports a user's pick with exactly that call, and WooCommerce's own address-field churn is jQuery-triggered too. The reverse also holds, which is why "just use jQuery" is incomplete: `writeAndFireChange()` dispatches a REAL native event, visible to a jQuery binding but only observable natively on a page without jQuery. Bind BOTH, idempotently, and re-try the jQuery half per mount pass (jQuery is absent at import under jest, present on every real checkout); double delivery of native events must then be harmless BY CONSTRUCTION — here the handler keys off a remembered transition, so the second call does nothing. **The cost is that unit tests cannot catch it:** #271's watcher had seven green mutation-checked jest cases, every one driving the field with `dispatchEvent( new Event( 'change' ) )` because that is the natural thing to write in jsdom, and the rig showed the field unchanged on the first try. Pin it with REAL jquery (a devDependency here) — the mutation deleting the jQuery binding passes all seven native-event tests → [gotchas/jquery-trigger-change-fires-no-native-event.md](gotchas/jquery-trigger-change-fires-no-native-event.md) (s66)
- [js/object-as-map] A plain `{}` is neither an insertion-ordered map nor a safe one for opaque external keys. `Object.keys()` returns integer-like keys in ASCENDING NUMERIC order BEFORE every other key — and this carrier's point ids are numeric strings, so an eviction pass walking it evicts the NEWEST entry while older ones survive, at the right total count, looking correct. Separately, `pool['__proto__'] = value` sets the prototype and creates no own property, while `'__proto__' in {}` is `true` on an empty object, so a point with that id is never even recorded as seen. Use `Object.create( null )` plus an explicit order array (ES5 here), or `Map`, which fixes both at once.
