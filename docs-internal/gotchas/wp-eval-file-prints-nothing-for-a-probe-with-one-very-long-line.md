# `wp eval-file` prints NOTHING for a probe that carries one very long line

**Namespace:** `[rig/probes]`
**Discovered:** 2026-10-05 (s153, #1091)

> **Measured on:** the macOS rig's wp-env CLI container (PHP 8.1, the bundled wp-cli phar).

## What happens

A probe is generated by a script and piped into the container. It carries a payload inline — a
base64 string of a page's content — and `wp eval-file` exits `0` with an **empty stdout**. The probe
did not run: no post was created, nothing was echoed. The only trace is a deprecation on stderr,
which most probe runners discard:

```text
Deprecated: strncmp(): Passing null to parameter #1 ($string1) of type string is deprecated
in phar:///usr/local/bin/wp/vendor/wp-cli/eval-command/src/EvalFile_Command.php on line 81
```

Bisected on the payload: a 3000-character line runs, a ~5600-character one (4216 bytes of content,
base64-encoded) does not.

## Root cause

`EvalFile_Command::execute_eval()` (read from the phar) does not `include` the file. It reads the
text, runs it through `Utils\replace_path_consts()` — a regular expression that rewrites `__FILE__`
and `__DIR__` — and `eval()`s the result. On a line that long the expression gives up and returns
`null`; the command then evaluates `'?>' . null`, which is nothing, and reports success. The file
itself is intact — it is the single LINE that is too long, not the file.

## Fix

❌ One statement carrying the whole payload:

```php
$content = base64_decode( 'PCEtLSB3cDp3b29jb21tZXJjZS9jaGVja291dCAtLT4…5600 characters…' );
```

✅ The payload in short lines:

```php
$b = '';
$b .= 'PCEtLSB3cDp3b29jb21tZXJjZS9jaGVja291dCAtLT4…';   // ≤ 200 characters each
$b .= '…';
$content = base64_decode( $b );
```

✅ Or skip the preprocessing altogether — `wp eval-file probe.php --use-include` includes the file
instead (measured: the same 6000-character line prints its answer). `__FILE__` then names the probe
file itself, which is what a probe wants anyway.

And make the probe runner show stderr whenever stdout comes back empty — an empty answer from
`wp eval-file` is otherwise indistinguishable from «the probe had nothing to say».
