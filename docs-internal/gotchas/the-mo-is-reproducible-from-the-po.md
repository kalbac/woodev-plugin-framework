# Gotcha: [i18n/catalogue] — The committed `.mo` IS `wp i18n make-mo` of the committed `.po`, so a catalogue edit is a reviewable diff
> Tags: i18n, gettext, po, mo, tooling, measurement | Session: s104

## What happens

A `.mo` is a binary blob in the diff, so the instinct is to leave the catalogue alone: regenerating
it might sweep in an unknown amount of drift accumulated since it was last built. That instinct is
what kept #646's Russian labels unshipped until it was actually measured.

**Measured 29.08.2026, and it is not drifted:** compiling the UNCHANGED `.po` reproduces the
committed `.mo` byte for byte.

```bash
MSYS_NO_PATHCONV=1 docker exec -w /var/www/html/woodev-framework \
  de59f74e6d3d19d18a7f7b6608fda7e7-cli-1 \
  sh -c 'wp i18n make-mo woodev/languages/woodev-plugin-framework-ru_RU.po /tmp/mo-out;
         md5sum /tmp/mo-out/woodev-plugin-framework-ru_RU.mo woodev/languages/woodev-plugin-framework-ru_RU.mo'
# 54d952df8bc6fd80efdbd1efaff3449a  /tmp/mo-out/...mo
# 54d952df8bc6fd80efdbd1efaff3449a  woodev/languages/...mo
```

Therefore a `.mo` diff after adding three entries **is** those three entries and nothing else, and
the control is free: run the compile on the unchanged file first, compare hashes, then edit.

## Root cause

`msgfmt` is deterministic for a given `.po`, and nobody has hand-edited this `.mo`. There is no
local `msgfmt` on this machine — `wp i18n make-mo` inside the rig's `cli` container is the tool.

## Fix

Adding an entry, safely:

1. Compile the unchanged `.po` to a temp dir, `md5sum` against the committed `.mo`. **If they differ,
   stop** — the assumption above has expired and the drift must be understood first.
2. Insert the new entries **before the first `#~` line**. Obsolete entries live at the end of a `.po`
   by gettext convention, and appending after them is malformed.
3. Recompile in place with `wp i18n make-mo`.
4. `git diff --numstat` on the `.po` — it must be pure insertions.

⚠ **The `.pot` is deliberately NOT regenerated by this procedure.** That is #567's deferred
release task (operator, 29.08.2026) and `wp i18n make-pot` would sweep in the whole backlog.

⚠ **A `.po` merge script is a different animal.** The one used in s103 silently dropped 92 obsolete
`#~` entries and the result still looked well-formed — gotcha
[a-po-merge-that-drops-obsolete-entries-still-looks-well-formed](a-po-merge-that-drops-obsolete-entries-still-looks-well-formed.md).
`make-mo` is not that; it only compiles.
