## The four defects nobody had filed

1. **A boolean setting's tooltip was dropped on the floor** — `ControlField`'s toggle branch
   bypasses `withAnatomy()`. Three of the tab's fields are booleans, so #373 was unbuildable until
   this was fixed.
2. **`disabled_reason` overwrote `description`** in `Field_Schema` — and #375/#377 both rely on
   "disabled with a reason" while still needing the authored description.
3. **`description` rendered as escaped text**, so the `<a href>` the card's own example prescribes
   would never have been a link. Now `RawHTML`, with the contract stated at `register_setting()`:
   developer-authored only, never interpolate runtime data — that is what `disabled_reason` is for,
   and it stays escaped.
4. **Cross-handler `show_if` had no server-side enforcement.** `Composite_Settings_Handler` split
   the submitted map by owning child BEFORE evaluating conditions, so a condition naming a sibling's
   setting scored the empty string and the hidden field saved anyway. Found by the Codex critique
   of the plan, before a line of Block 2 was written.

## What the rig found that no suite could

The «Поля» section renders fields from two handlers, and the composite collected them child by
child — so both field-type axes rendered at the top of the section, detached from the fields they

Fixed in `get_settings()`, pinned by a test confirmed to fail against the old implementation.

Everything else on the rig was verified live: the three migration paths, the two axes with three
values each, provider keys appearing and disappearing without a save, the picker returning real
suggestions for «Моск», and no console errors.

## Codex works on this machine — the two-month claim was wrong

Measured, not assumed. In an **Orca terminal** Codex has a real shell: it ran `git rev-parse`, and
reproduced a spec file's first heading byte for byte — the same probe that produced a confident
**fabrication** in s74. Only `codex exec -s read-only` from the Bash tool fails, because that path
explicitly asks for the broken windows sandbox, while the interactive TUI in a project marked
`trust_level = "trusted"` never engages it. **Same binary both times** — an earlier draft of this
finding blamed the desktop build and was wrong.

The inline bundle, the canary line and the review-through-GitHub workaround are all obsolete.

Codex earned its keep immediately: it took the plan apart against the real tree and was right on
four of six points, including the two that would only have surfaced on the rig. It then implemented
the composite fix itself, test-first, and reviewed Block 1 — where it found the DaData predicate
asking only whether the active provider CAN serve addresses while the runtime chain also requires
it to be configured, a dead end where the keys you need are hidden exactly when you need them.

## The 27B review — a separate track that paid for itself twice

The operator ran a local 27B model over the repo on his Mac. Verified every finding against current
`main` in a dedicated Orca worktree: **20 confirmed · 6 for the operator · 5 refuted · 3 not
evaluable**, filed as #383–#402 with reproductions.

It found a **critical IDOR**: a Subscriber can read and delete any user's saved payment cards,
because the AJAX endpoints check a nonce and nothing else, and the nonces are handed to every
logged-in user. Also a stored XSS and the license key in plaintext logs.

Then #386 from that batch **fired here, hours after being confirmed**: `Shipping_Integration`'s
constructor dereferenced its optional parameter, and Block 1 gave the fixture the repository's
first carrier integration — turning a documented-but-untravelled path into the one WordPress takes
on every request. The integration suite died in bootstrap; that is why 110 green tests had never
noticed.

The lesson worth keeping: what made the 27B findings valuable was **independence**, not model size.

## Two self-inflicted incidents, both recorded

- **Two agents in one file.** Codex was fixing defects in the location registry while a worker's
  brief required editing the same file. The worker ran `git checkout --` and erased Codex's
  finished, uncommitted work, then reconstructed it by inference. The reconstruction proved faithful
  — a mutation check reproduced Codex's own recorded red result — but that was luck. The cause is
  the dispatch, not the command: an agent cannot know what another agent is editing.
- **The same trap, on the author of that gotcha, an hour later.** Wanting to inspect a file's line
  endings, I ran `git checkout main -- .` — which overwrites rather than inspects. Fifty files
  reverted, nothing lost, because the block had just been committed. `git show <ref>:<path>` reads
  a revision without touching the tree.

Also corrected a claim that had escaped into the handoff and three briefs: **this tree is LF**, not
CRLF. `.gitattributes` sets `eol=lf` and `git ls-files --eol` confirms it. A CRLF file here means a
tool flipped it — Serena does, on every `replace_content`.
