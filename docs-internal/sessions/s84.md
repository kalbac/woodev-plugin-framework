## The critics earned their keep — three of five first drafts were wrong

This is the part worth remembering. Every card that went to a critic came back with something real:

- **#394.** The worker fixed four call sites and missed a fifth *in a file it was already editing* —
  `class-payment-gateway-direct.php:742-746`, a customer-facing `wc_add_notice()`, i.e. the
  highest-exposure sink of the five.
- **#383, round 1: REJECT.** `manage_woocommerce` is a FEATURE capability, not authorization over a
  user object. `shop_manager` holds it and is not entitled to edit an administrator, so the IDOR was
  narrowed, not closed. Round 2 added `current_user_can( 'edit_user', $user_id )`. The re-critic
  then found a user-existence oracle — `get_userdata()` ran before the denial, so an attacker could
  tell a real user id from a fake one — plus four `@since 2.0.3` tags that should have been 2.0.2.
- **#395, rejected three times.** It gets its own section below — it is the only card s84 did not
  merge, and the reason is worth reading.
- **#412/#415.** Approved, but the critic also disproved two things the brief had asserted as
  suspicious, by measuring instead of arguing.
- **#389.** Approved, and then found the landmine: nothing in the repo registers `is_multi` at all,
  and `control-field.js` resolves `type === 'boolean'` to a single `ToggleControl` regardless — so
  the first UI edit of a boolean-multi setting would silently collapse the stored array.

The brief line that produced most of this: **"you are licensed to contradict this brief; if the
code disagrees, the code wins."** It surfaced a fourth unguarded AJAX handler nobody had listed, a
pre-flight check that existed but was never consumed, and a "the baseline is stale" that turned out
to be a real infrastructure gap.

## Six traps in our own tooling, all found the expensive way

Recorded as gotchas; the wiki section `orchestrating-agents-with-orca.md` carries the brief template
they imply.

1. **A worktree's test suite is not the primary checkout's.** Two workers reported 2475/6114 with
   71 skipped against a briefed baseline of 2475/6128 with 66. One critic called the baseline
   stale; another root-caused it correctly. Five `Contract/Yandex*` tests — **release-blocking data
   contract guards** — skip in every worktree because `plugins-reference/` is gitignored and was
   absent from `.worktreeinclude`. Fixed in #424. Compare the SKIP count, not the assertion count.
2. **A local `npm run build` cannot prove assets parity.** PR #422 went red on the parity job after
   two agents independently measured zero diff in the worktree. First diagnosis (warm webpack
   cache) was wrong and had already been merged as a gotcha; corrected in #425 after measuring all
   four candidates. The real cause: `node_modules` is SHARED by symlink, webpack resolves it out of
   the project, and every module request becomes `../../../../node_modules/...` — changing module
   ids and therefore the content hash. Fixed by rebuilding at a detached HEAD in the primary
   checkout. **Generated bundles are built in the primary checkout, never in a worktree.**
3. **Launching Codex takes four steps, not one.** `worker-start --agent codex` produced a bare
   PowerShell terminal three times out of four, which executed the brief as a here-string until it
   hit a ParserError. Reliable: `terminal create --command codex` → ESC the `codex-update-prompt`
   → `dispatch --inject` → `terminal send --text "" --enter`, then read the buffer back.
4. **Three agents is this machine's cap.** At six, free RAM hit 0.4 GB of 15.3 and a starting Codex
   died on `VirtualAlloc`. Even at three, jest OOM'd once, and `phpcs` twice failed in ways that
   read as code defects — once OOM, once with five PHPCS *internal* exceptions blaming innocent
   files, which were `shell_exec()` fork failures. Every brief carried a warning about this, and
   every agent that hit it reported honestly instead of claiming a green gate.

5. **`.phpunit.result.cache` makes a run unreproducible.** `phpunit.xml` sets
   `executionOrder="depends,defects"`, so the run order comes from that cache and the suite shares
   process state. The same worktree reported **45 errors and 6 failures** on one run and exactly
   **2 failures** after `rm -f .phpunit.result.cache`. It is also what made a worker's
   "reproduces in isolation with none of my files loaded" feel true when it was not.
6. **A `class_exists`-guarded global test stub is won by whichever file loads first — for the whole
   suite.** Two new `PaymentGateway*` test files declared `WC_Order::get_id()` returning `0`, sorted
   ahead of the established stub returning `123`, and silently broke an untouched test three
   directories away: `get_id() === 0` fails `update_order_meta()`'s `$order_id > 0` guard, the meta
   write never happens, and the assertion that fails is about an empty array in a file nobody
   touched. The `--filter` run is what settles this class of question — it removes ordering from
   the argument entirely.

Also confirmed: every fresh worktree starts dirty with seven CRLF-only files. Told not to run
`git add -A`, every worker left them alone.

**The coordinator lesson from trap 6:** the worker classified those two failures as "pre-existing,
unrelated". "Pre-existing" is a claim about `main`, and only a run on `main` settles it. Four
measurements — filtered and full, on both trees, cache cleared each time — took ten minutes and
turned a misreport into a root cause plus two gotchas.

## The one that would not close — #395

Four worker rounds, four critic passes, three REJECTs, and every rejection was correct:

1. The redaction seam was **opt-in**, so any request class that did not implement the hook logged
   its secret by default — and the URI filter ran AFTER the mask, so a filter could append a
   secret to an already-masked string.
2. The matcher was **too literal**: only `name=` exactly, so `token%5Bprimary%5D=` — the shape
   `http_build_query()` actually emits, and this codebase builds the licensing path with it —
   sailed through, as did `licenseKey` and `apiKey`. Bodies were trusted outright while the
   docblock said they were redacted.
3. The matcher was rewritten to canonicalize names but still read only the FIRST bracket segment,
   so `a[token]=SECRET` — a secret under a non-secret name — still leaked. And the same regex,
   now running over body text, **corrupted valid JSON** that happened to contain `token=` inside a
   string value.

The pattern only became visible across three rounds: **a regex over a raw string keeps losing to
the format.** Round 4 was briefed to stop extending it and start parsing — `parse_str()` plus a
recursive walk plus `http_build_query()` for query strings, `json_decode()` plus the same walk for
JSON bodies — and it did, keeping the (now gap-fixed) regex only for `WP_Error` free text and
non-JSON bodies.

Round 4 carried one deliberate disagreement with its brief: it declined to return a fixed redacted
marker for unknown/XML/form bodies, arguing that currently-green tests assert real sibling params
survive in the log. **The fourth critic settled that argument by running it** — it invoked the
method with a `print_r`-shaped body and got `super-secret-token-value` back verbatim, because the
regex cannot match `[token] => secret`. So: REJECT again, and the worker's own earlier observation
was the tell it did not follow — the `print_r` licensing body is safe only because
`Woodev_Licensing_API_Request` masks itself before the backstop ever sees it.

Round 5 added `UNPARSEABLE_BODY_MASK` and the fifth critic rejected it the same way — by invoking
it. Two leaks left: `is_form_encoded_body()` infers the form type from the body's own syntax, so a
URL-shaped string carrying `token=SECRET` and a newline free-text body get parsed with the secret
intact; and a valid JSON scalar that IS the secret passes through unchanged. Round 6 was in flight
at handoff.

**PR #433 is open with CI green and must not be merged.** The verdict is in a comment on it.

The lesson from this card is not about redaction. It is that **the last two rejections were settled
by calling the method and pasting the return value**, after three earlier rounds had been argued
from reading. A critic that runs the code is worth several that read it.
