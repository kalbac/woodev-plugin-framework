## The two decisions I made for the operator

**#650, which 400 wins.** Hoisting only the country READ would have been a regression: a malformed
country handed to `provider_for_level()` resolves to `null` and returns 200 + empty on the
"level unserved" branch, replacing today's 400. So the format check moves up with the read — placed
AFTER the `$provider_override` membership check, so the only competing pair keeps its order:
**unknown provider still beats invalid country.** The override is an explicit admin instruction and
"that id does not exist" is the more actionable answer. `provider_by_id()` stays country-blind, and
its comment now records that as settled: the mismatch is already refused later by
`provider_serves_level()` against the REAL scope, so the response keeps its true `within_status`
instead of the coarser `unserved_level` a country-aware resolution would force.

**#646, miles by locale or by WooCommerce's unit settings.** By locale, unchanged. `woocommerce_dimension_unit`
describes the merchant's CATALOGUE; a distance to a pickup point is a reading for the SHOPPER.
Binding them shows miles to a Russian shopper in a shop that enters dimensions in inches, and denies
them to a US shopper in a shop selling in cm. So *when* miles are chosen did not change — only
*where* it is decided: an explicit, filterable `distanceUnitSystem` flag in PHP. Both decisions are
written on their cards with the reasoning, so he can overrule either from the card alone.

## The critic earned its place three times

Codex, three rounds, each round one real defect that no gate could see.

1. **#646 shipped rule 1's first half only.** English `m`/`km`/`mi` msgids with no catalogue entry
   move a ru_RU storefront from `м`/`км` to `m`/`km` — the old hardcoded JS branch was, by accident,
   the translation channel. Fixed: `_x()` with a context (a bare one-letter msgid is unresolvable
   for a translator), plus the `.po` entries and a recompiled `.mo`.
2. **#361 called `unserved_level` a widened search.** It is not: that status means no provider serves
   the level at all, and `perform_suggest()` returns `suggestions: []` from its `null === $provider`
   branch before any scope is built or any provider called. Nothing was widened because nothing was
   searched — the message beside that empty listbox was simply untrue. **The card said this in its
   own decision list and my brief asked for all four statuses anyway. My error.**
3. **Three findings in round 3**, all fixed: `/location/list` never carried `within_status` into the
   shared `emptyText` (no built-in renderer reads `options.list`, but the renderer registry is OPEN);
   the generator's Rule-2 check only tested for an `abstract-` PREFIX, so
   `abstract-abstract-shipment-handler.php` passed the very rule it violates; and an
   `always_show_on_settings` test asserted `true` for an UNDISMISSED notice — true under both
   implementations, a test that could not fail.

Every fix was mutation-checked: the production code was broken, the test confirmed red, then restored.
