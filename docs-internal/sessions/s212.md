**Rig smokes (Haiku 5.5, four runs):**
- Round 1 found the tab showing ZEROS on every uncached range. Cause: `wpdb::prepare()` inserts numbered `%N$s` string placeholders
  unquoted (gotcha `wpdb-prepare-inserts-numbered-string-placeholders-unquoted`), so each uncached query failed. The runner then turned
  the DB error into a cached zero result. The unit tests used a fake `wpdb` and never executed the SQL. Fixed: quoted placeholders, no
  reused numbered placeholder, DB errors become a WP_Error 500 and are never cached.
- Round 3 found an answer cached by an older build surviving a deploy → `Analytics_Cache::SCHEMA_VERSION` added to the cache key. It also
  found a custom range URL without `compare` falling back to the default window → a default `compare` is now always passed (gotcha
  `wc-date-throws-on-a-half-filled-custom-range`, section «The silent variant»).
- Round 4 (`ddf478fd`, functional only): report menu entry present with the flag; a user without `manage_woocommerce` sees no entry and a
  direct load is refused; the list page and the analytics tab make no invalid-JSON calls.
