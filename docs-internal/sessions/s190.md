## Facts learned (EDD Software Licensing 3.8.14, read from the installed source)

- **Changelog filter.** The update API passes `_edd_sl_changelog` through `strip_tags` that keeps only `p li ul ol strong a em span br`,
  then `wpautop`. Headings vanish, so a version line must be `<p><strong>…</strong></p>`.
- **Staged rollouts.** They are built into SL, with no extension needed.
  - The bucket is `crc32(licence key + site URL) % 100`: stable per site and never growing by itself.
  - Bucket 0 is never eligible, so «100 %» still misses about 1 % of sites. To release to everyone, turn rollouts off.
  - Only the update API is gated. Account downloads and receipt links always serve the newest file.
  - The version rule runs last and overrides the percentage rule. Enabling it with an empty version blocks everyone.
- **`_edd_readme_location` is unused.** Filling it would let a readme.txt override the description and changelog tabs.
- **Banners and icons.**
  - Banners come from `_edd_readme_plugin_banner_high/low`: 1544×500 and 772×250.
  - Update icons come from the featured image (`sl-small` / `sl-large`).
  - `woodev-core` hard-codes `wp_version` 5.9 in the API response, which is display-only.
- **Other meta.** `edd_product_notes` appears in the purchase e-mail and the receipt only, and EDD's sanitizer turns `&` into `&amp;`.
  The update API's description tab is `post_excerpt` when one is set.

## Lessons (process)

- **A worker that answers in its terminal never fires the watchdog.** The waiter must diff the terminal's `· done HH:MM` marker.
  A regex on a line that has scrolled out of the tail missed two finished workers for about 30 minutes.
- **Long payloads.** A ~14 KB base64 payload sent with `orca terminal send` arrived corrupted. Upload such files in 1500-char chunks
  through `terminal create --command`, then compare sha256.
- **Product-card copy is for buyers.** His review of v3: no instructions, buttons, migration or requirements. Saved as a memory, and
  the v4 text was approved.
