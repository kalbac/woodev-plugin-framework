## What was done

- **#768 — the Title and Description fields were inert, and the title was `null`.**
  `Shipping_Method::init_form_fields()` shows both to the merchant; the base assigned neither and
  nothing read either option. `WC_Shipping_Method::get_title()` is a bare `apply_filters()` with no
  fallback, so the method sat nameless in the zone table. Measured, not inferred: pre-fix
  `get_title()` returns **`null`**. The v1 framework DID assign it
  (`plugins-reference/woocommerce-yandex-delivery/woodev/shipping-method/class-shipping-method.php:68`);
  the v2 rewrite dropped the line, and every plugin that reached a browser assigned `$this->title`
  itself, so no fixture ever executed the branch.
- **`description` now has somewhere to go.** `WC_Shipping_Method` has no `$description` property at
  all; `WC_Shipping_Rate::set_description()` does exist (WC 9.2.0+) and the Store API publishes it
  per rate — but `add_rate()` never sets it, so `apply_rate_attributes()` applies it afterwards.
  Its `desc_tip` was corrected: the block order form renders it, the classic one does not.
- **#766 — the rate carried five keys and threw on ordinary data.** `to_array()` now emits the whole
  `$args` array (so `taxes`/`calc_tax`/`price_decimals` and third-party keys survive), holding back
  the two attributes `add_rate()` would discard. The constructor no longer throws on an empty
  `label` or a numeric `cost` — both are shop data on the checkout path — and degrades with
  `_doing_it_wrong()` instead. The identifiers still throw.
- **#767 — the signature probe.** `scripts/signature-probe.mjs`, source-only, no WordPress:
  fatals (final override, narrowed visibility, static mismatch, incompatible OR omitted return
  type), unimplemented abstracts, parameter divergence, and separately the shadowed-base-private
  case. `npm run probe:signature`, 7 jest tests, docs in `migration/signature-probe.md`.

## Key decisions

- **The `description` fork on #768 was closed by measurement, not by asking.** The question was
  whether to wire the field or delete it. WooCommerce has a real, current slot for it — so it is
  wired, and the tooltip was corrected to say where it actually appears.
- **The probe reports 11 fatals, not the card's 13, and was NOT tuned to agree.** The abstracts
  match exactly (8/8) and the shipping method matches exactly (3/3). The main class is 6 and the
  integration 2. Verified three ways: each fatal reproduced on a real `php` with a minimal `A`/`B`
  pair; the counts re-derived independently by a second scanner and by hand; and the seventh
  main-class candidate identified — `includes()`, which is `private` on the base and therefore not
  a conflict at all. **s116's dismissal of `get_checkout_handler()`/`get_webhook_handler()` was
  wrong** and they ARE counted: an omitted return type is a fatal regardless of what the method
  returns at runtime. Why s116 got 13 cannot be established — that script was never committed.
- **Codex was the critic and found two real defects; both were verified before acting on them.**
  Neither was accepted on the critic's word, and verifying sharpened one of them (below).

## Bugs fixed

- **Bug fixed** — `guard_rate_label()` did `(string) $this->get_title()`. `get_title()` fires
  `woocommerce_shipping_method_title`, which has no type guard, so an object return fatals **on the
  checkout path** — the exact failure the guard exists to prevent. Now discarded unless it is a
  string. Falsified: the pre-fix version dies with `Object of class stdClass could not be converted
  to string`.
- **Bug fixed** — the DTO stringified a numeric cost. `(string) 1.0e20` is `'1.0E+20'`, and
  `wc_format_decimal()`'s **string** branch strips everything outside `[0-9.-]` and returns
  **`1.02`**; handed the same value as a **float** it formats correctly. So the cast was destroying
  a value WooCommerce would have handled. A number now passes through untouched; `NAN`/`INF` are
  the only floats that degrade. Codex raised this as a precision concern — the mechanism came out
  of checking the claim, not of accepting it.
- **Bug fixed** — CI's `test-js` went red on the probe's first commit while jest was green locally.
  `plugins-reference/` is **gitignored**: a local checkout and every agent worktree have the donor
  plugins, CI never does. The acceptance test now skips on absence, and the probe names what it
  skipped and exits 0. Verified both ways by moving the directory aside.

## What cost time, and is now written down

- **My own `cd` into the worker's worktree persisted across Bash calls**, so `git checkout -b` made
  the branch in the wrong tree and `cp` answered «are the same file» — which reads as a junction
  and sent me looking for corruption that did not exist. No damage: `main` was untouched. Gotcha
  filed; the fix is `git -C` and absolute paths.
- **Serena's `replace_symbol_body` flipped `class-shipping-method.php` to CRLF**, as its gotcha
  says — and my check for it, `grep -q $'\r'`, was itself eaten by the shell and reported "clean".
  A false measurement on top of a known trap. Node script now, never an inline escape.
- **`worker-start --agent codex --model gpt-5.3-codex` returns HTTP 400** — that model is not
  available on a ChatGPT account. The real id is visible in the Codex composer line:
  **`gpt-5.6-terra`**. The retry then failed on `Agent startup blocked: codex-update-prompt`, which
  Orca now detects rather than answering blindly; the four-step recipe cleared it.
