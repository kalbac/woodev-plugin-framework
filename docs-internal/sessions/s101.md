## #598 + #605 — the dev autoloader (PR #607)

- **`woodev/account` and `woodev/competitor` were absent from `composer.json` →
  `autoload.classmap`.** Ten classes unreachable for Composer by any route: the classmap did not
  list them and PSR-4 structurally cannot map WordPress file naming. Measured 0 → 10 entries,
  1630 → 1640 classes. The card named only `competitor`, because that is the one
  `dump-autoload` warns about — it complains about PSR-4 near-misses, never about a directory
  nobody told it to scan.
- **Gate added, because the asymmetry is the cause:** `woodev/class-map.php` is generated by
  scanning the tree and cannot drift; `autoload.classmap` is a hand-typed list and silently can.
  The new `ClassMapCompletenessTest` method walks every FQCN in the generated map through the
  registered Composer `ClassLoader`. Falsified by reverting the fix — it names exactly those ten.
- **#605:** a docblock in `ScriptHandlerLogFieldTest.php` held RAW control bytes where the author
  meant the escape sequences as text. PHP ran it; `git` and `grep` classified the file as binary
  and skipped its contents. One test file was invisible to every grep sweep in the repo.
- **Decision — item 3 of #598 answered but NOT acted on.** `tests/unit/handlers/` is the only
  nested test directory whose namespace breaks PSR-4, and renaming it **reds 55 tests** for an
  unrelated pre-existing reason. Filed as **#606** rather than smuggled into the PR.
