## Orca bots — what was learned (source: `stablyai/orca` `src/main/bots/`, `skill-guides/orca-cli/references/bots.md`)

- A bot = home `~/.orca/bots/<name>/` with `SOUL.md` (its first paragraph becomes the «For:» description), `MEMORY.md` (≤ 200 lines
  loaded; nightly tidy-up; owner `Rule:/Decided:/Prefers:` lines change only on his words), items, Look around (claude/codex only,
  read-only, enforced at tool level), Home Chat that persists. Bots hand code to workers (`worker-start --worktree new-child`).
- `orca bot create --offer` works only FROM a bot's chat → the first bot on a computer is created in the UI; later ones are offered
  by that bot as a card. No CLI for group rooms or a bot's effort — UI only.
- A workspace «belongs» to a bot through lineage: `orca worktree set --worktree <sel> --parent-worktree folder:<bot home>`
  (cross-computer: `--environment Homelab … --parent-environment local`). Done for every plugin and the framework checkout.
- bot:Woodev (Homelab) refuses an owner approval relayed from another session and has no EDD write path → EDD uploads stay with a
  `homelab-ai` worker (the 9765 route), now owned by bot:Plugins.
