## What shipped

**PR #858 — #853, flush the new-order counter cache on export. MERGED (`829dc78`).**

The card's proposed fix was wrong, and the reason was not visible from the card. `export()` already
fires `shipment_exported`, but `Abstract_Shipment_Handler::hook()` prefixes every forward hook with
`$hook_prefix` — a **plugin-supplied constructor argument** defaulting to `''`. There is no fixed
hook name the framework could subscribe to, and `Orders_Provider` carries no prefix either (its
`id` is not bound to the handler's `hook_prefix` by anything).

Decided by the coordinator before dispatch, so the worker would not invent it:

- ✅ an **unprefixed, framework-level twin action** `woodev_shipping_order_exported` fired alongside
  the prefixed one; `Orders_Registry::add_hooks()` subscribes itself to it.
- ⛔ **not** a new optional `Orders_Provider` argument — a shared framework obligation must never be
  an optional parameter a plugin author can forget; a forgotten key leaves the badge silently stale.
- ⛔ **not** a call from the shipment handler into the admin registry.

Both card questions closed by measurement rather than built for: there is **no reverse transition**
(`cancel()` never deletes `carrier_order_id`, nothing under `woodev/**` does), and there is **no
bulk export path** (`export()` has exactly one caller), so no cancel-path flush and no deferral
mechanism were built.

**PR #859 — #829, status badges. MERGED (`1d3f8e9`) after the operator accepted them.**

`.order-status.status-*` table, carrier's `raw_label` moved from a second visible line into a hover

## Measured

- **The palette measurement on card #829 was INCOMPLETE.** It was taken by grepping
  `assets/css/admin.css`; re-measured via `getComputedStyle()` on a real `.order-status` element on
  WooCommerce's own orders screen (WC 11.1.0) it also carries `white-space: nowrap`, gets its
  horizontal room from an inner `<span>`'s `margin: 0 13px`, and sits on `margin: -0.25em 0`. Fixed
  in `0316a26`; gotcha `a-grep-of-a-vendor-stylesheet-is-an-incomplete-measurement`.
- **An empty `carrier_order_id` IS counted as exported, end to end.** Proven, not inferred: the
  worker's unit test pins that `Woodev_Order_Compatibility::update_order_meta()` passes `''` through
  in both HPOS and legacy branches, and the coordinator measured the missing link on the rig — HPOS
  on, WP 7.1 / WC 11.1.0, probe order 171: an empty-string meta value **creates a row and `EXISTS`
  matches it**. `Orders_Query::is_exported_meta_clauses()` tests presence, never value. → **#860**.
- **Seeded orders carry no customer and no address.** Both seeders
  (`class-test-orders-seeder.php`, `class-realistic-orders-seeder.php`) call neither `set_billing_*`
  nor `add_product()`, so «Покупатель» is empty in every row, «Доставка» shows no destination and
  «Оплата» is `0,00 ₽` throughout — three of six columns cannot be judged visually. → **#861**.
- **The table does NOT collapse to cards on a phone.** At 390px all six columns remain and the table
  scrolls horizontally inside its card; the badge runs off the edge.
- **The tooltip is unreachable on touch by any path.** Ariakit's hovercard trigger documents that it
  *purposely ignores mobile touch*, and the `focus-visible` fallback does not fire for
  touch-originated focus. No `pointer: coarse` handling anywhere in the stack.

## After the alarm — the second wave (#862, #861)

The operator parked the session at 90 % of the 5-hour window and set a 6:30 alarm. It fired, the
environment was re-verified rather than trusted, and a second wave went out: **#862** (labels) and
**#861** (seeders), disjoint file sets.

**#862 — the card's own premise was half wrong, and the coordinator corrected it before dispatch.**
It claimed the labels live in four places. Measured: **two are definitions**
(`Delivery_Status::labels()` and its declared mirror `DELIVERY_STATUS_LABELS`), the other two are
**docblocks quoting the old label** — they still had to change, as prose. The same measurement found
that **nothing gates the mirror**: the only test asserts each label is a non-empty string, so the
byte-for-byte claim in the docblock has no enforcement. Recorded as a correction comment on the card
and filed as **#867**.

**#861 — the code was right and the rig still wrong.** After the merge the rig reseeded (seed options
`4` and `3`), but the count went 134 → 238: the seeders ADD, they do not revisit orders made by an
older version. **129 of 238 orders still had no customer**, so the card's whole purpose — make the
table judgeable — was not achieved on the one rig that matters. Backfilled by hand from the seeder's
own `customer_pool()` (rig state only, nothing deleted, nothing committed) and filed as **#868**.

**The deferred half of #862 was disproved, not implemented.** The column width was deliberately left
until #861 landed, so it could be measured against real data rather than an empty fixture. Measured:

| column | empty fixture | real data |
|---|---:|---:|
| **Статус** | 147 | **146** |
| Покупатель | 178 (empty) | 253 |

«Статус» did not move. The "column takes too much" impression came from its empty neighbours. The
operator agreed to close that half as unnecessary.

**What the same measurement DID find** was a real defect invisible until then: `wc_price()` separates
thousands with a space, so **every** amount wrapped onto two lines once orders had real totals — 50 px
of content box against 59 px of text. Fixed in **#865** / PR #866 with a dedicated class, because the
shared meta class also renders the postal address (which must wrap) and `:nth-child()` would shift
when #824 adds a column.

## Traps this half paid for

1. **`check --wait` was OOM-killed three times** and its death is indistinguishable from an empty
   timeout. The workers were alive every time (`worker-list` says so). The trough was a transient
   `phpstan` peak — `php` alone held 1.83 GB — and passed on its own. Gotcha
   `an-oom-killed-check-wait-reads-as-an-empty-timeout`.
2. **Backticks inside a double-quoted bash string ran as command substitution** in a `gh issue
   comment` body and silently ate one word. Reposted from a file. Known trap, hit again.
3. **`grep -c "compiled successfully"` returned 0 on a successful build** — ANSI colour codes sit
   between the two words. The check lied, not the build.
4. **`orca worktree rm` without `--force` is the audit that matters**: it refuses on a dirty worktree
   and prints what was left uncommitted. Both workers this half left only the seven known CRLF files
   — the "built but not committed" failure from the first half did not recur, because the brief
   forbade building at all.
