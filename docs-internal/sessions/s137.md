## Ключевые решения и находки

### Редирект старого слага — не `admin_init` (#820)

Редирект настроек (`Settings_Page_Registry::maybe_redirect_legacy()`) висит на `admin_init`, и
скопировать его было бы ошибкой: для слага, который никто не регистрирует,
`wp-admin/includes/menu.php:375-382` отдаёт 403 **до** `admin.php:180` (`do_action('admin_init')`).
Шов — `admin_page_access_denied`. Сравнивается `global $plugin_page` (значение уже через
`plugin_basename()`), иначе закладка `%2Fслаг%2F` давала 403 — это нашёл критик Codex, а зонд на
риге подтвердил до и после. Готча `admin-init-never-fires-for-an-unregistered-admin-page-slug`.
Фикстура `realistic` объявляет `legacy_page_slug = wc_realistic_shipping_orders`.

### #842: проверка не должна конструировать методы

Первая версия бралa id из `WC()->shipping()->get_shipping_methods()`, то есть конструировала все
методы доставки на каждой админ-странице под WP_DEBUG. Критик Codex — MAJOR. Решение координатора:
у плагина есть собственное объявление (`get_shipping_method_classes()` + фильтр
`woodev_shipping_plugin_method_classes`), а id выводятся статически через `$class::get_method_id()`.
Вынесено в общий хелпер, которым пользуется и `register_shipping_methods()`, так что разойтись они
не могут.

### #900: не повторять ядро руками

Codex сначала обходил `$wp_plugin_paths` вручную и сравнивал ключ карты (сырой `WP_PLUGIN_DIR`) с
`realpath()`-нутым `$plugins_dir` — при двойном симлинке (или симлинкнутом предке: `/tmp`, `/var`,
бинд-маунты) это никогда не совпадало. Критик Sonnet доказал это вызовом настоящего метода на
реальных симлинках и опроверг довод воркера, что `plugin_basename()` сломает #885. Итог — ядровый
`plugin_basename()` как запасной путь.

### #818: вариант 3 вместо рекомендованного 1

Замер воркера: отказ писать запись (вариант 1) превращает `get_shipping_method( $id )` в TypeError
для рано сконструированного метода, а `assert()` в проде выключен. Потребитель из карточки
(`class-shipping-admin-order.php:486`) устарел. Критик подтвердил.

### #905: минимальная правка без решения

`class-admin-pages.php` перебирает `get_registered_instances()` для страницы лицензий, поэтому
менять, КТО регистрируется, — это решение оператора; регистрация не тронута. Раунд 1 только убрал
лог. Codex к тому моменту упёрся в лимит (до 18.09 00:22), поэтому критиком был Opus 5, и он нашёл
MAJOR: без коллизии подписанная команда для `plugin_id=0` уходила первому плагину с id 0, а «сервер
такое не подпишет» было допущением. Раунд 2: общий предикат `has_store_product()` и отказ
`unknown_plugin` на шаге 9 диспетчера — строже и старого, и нового поведения. Риг: старый код
дописал строки в `debug.log` (1138 → 1141), правка — нет.

### Правило оператора: download id `0` не бывает

При приёмке #905 (17.09.2026): **плагина без `plugin_id` не бывает** — даже бесплатный и не
требующий лицензии свой id имеет. Значит отказ диспетчера для id ≤ 0 — не «ужесточение на всякий
случай», а верное поведение. Следствие: пять фикстур из семи возвращают `0`, и именно поэтому
`LicenseCommandEndpointTest` внедряет синтетический `plugin_id '9999'` через рефлексию, то есть
боевой маршрут «конверт → диспетчер → плагин» на фикстурах не проверяется вовсе → **#910**.

## Что пошло не так

- **Бриф первого критика без полного пути к `orca`** — его `worker_done` упал на сломанном
  симлинке; отчёт пришлось пересылать. Во всех следующих брифах путь был.
- **Мак уходил в сон дважды.** OrbStack завис (`curl -m 20` вернулся через 900 с, `docker ps` не
  отвечал), Sonnet-воркер закоммитил, но не отправил `worker_done`. Перезапуск OrbStack — с
  разрешения оператора (он перезапускает и контейнеры open-warehouse-saas). Попытка ждать через
  `timeout` провалилась молча: на macOS его нет. Готча
  `after-the-mac-sleeps-orbstack-hangs-and-every-rig-call-hangs-with-it`.
- **Отчёт воркера #820 завысил число тестов** (18 вместо 11) — поймано подсчётом в диффе.
- **Рабочий каталог координатора уехал в ворктри** после `cd` в команде — известная готча, дальше
  только абсолютные пути.
- **Воркер #888 распараллелился на подагентов** («5 parallel investigations per branch») — при
  64 ГБ это не ударило, но это обход лимита из готчи
  `a-worker-can-fan-out-to-background-forks-past-the-concurrency-cap`.
- **Codex упёрся в лимит использования** посреди волны: критик #905 так и не стартовал, статус агента при этом `live`, а поверх висел диалог «Approaching rate limits». Остановлен `worker-stop` после доказательства по экрану, критик переназначен на Opus 5.
- **Воркер #905 доказывал красноту через `git stash`** — стек общий для всех деревьев; проверено,
  что он пуст и ничего не задето.
