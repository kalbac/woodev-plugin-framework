## Decisions the operator made (S1–S9 in the spec)

1. **One tab «Доставка»**, three sections «Локация» / «Поля» / «Карта» — not three tabs.
2. **Field type = the existing `field_mode`** (`typeahead` / `ajax-select2` / `related-list`);
   «region gates settlement» is a consequence of `related-list`, not a mode. Both his notes
   (select2 needs a data adapter; the related-list region is selectWoo over a preset list, only for
   providers that can enumerate) were already how the code behaves — verified in
   `location-select-modes.js` and the `CAPABILITY_LIST` gate.
3. **«Подсказки для адреса» lives in «Локация»** (availability computed from the same section);
   «Поля» carries no suggestion-related option.
4. **Postcode = one select with three values** (`show` / `hide for pickup` / `remove`); address
   mirrors it with two (my call, he left it to me).
5. **Field-order preset applies to all shipping countries of the store**, on by default, via
   `woocommerce_get_country_locale`.
6. **«Карта» = three store options no carrier can override** (placement, replace-address,
   close-on-select); `refresh_checkout` stays the carrier's. His principle, quoted in the spec:
   the carrier is the default authority; the store wins only where the rule must be common —
   «иначе ансамбль разрозненных опций».
7. **Third-party field managers: restore what we own, note it in admin.** His words: he does not
   guarantee behaviour under third-party plugins, but reserves the right to override any value
   that is not WooCommerce's default, because his plugin's stability comes first.
8. **Sections derive their visibility from what plugins supply** — no new declaration;
   `supported_features` is WC-compat metadata and NOT the D9 seam (the input document's hint is
   retracted).

## Measurements that changed the design

- **T5 closed the good way.** WC 11.0.1 on the rig: `CartCheckoutUtils::get_country_data()`
  maps locale `priority → index` and the block bundle sorts by it; `hidden` is honoured too. So the
  preset reaches BOTH checkouts and is not disabled on the block one. Conversely
  `CheckoutFields::get_core_fields()` hard-codes the block form's fields —
  `woocommerce_checkout_fields` never reaches it. Hence the spec's «two instruments» rule
  (locale for both, late unset for classic only) and the new gotcha.
- Settings surface has **no `disabled` field state** today (`Field_Schema` emits `description`,
  `show_if`, `constant_managed`, `sensitive`) — D11 needs one; plan Task 1–2.
- `Settings_Provider` binds ONE handler per tab; sections from three handlers need a composite —
  plan Task 3.
- `Shipping_Plugin::needs_location_provider()` defaults to `false`, so the tab cannot hang off the
  location registry — a separate registrar is needed (plan Task 4).
- `replace_address` / `close_on_select` are `Pickup_Handler` **constructor args** today; the spec
  removes them (clean-break) — the fixture's ctor call at `:736` and
  `WOODEV_TEST_PICKUP_SELECTION_CLOSE` go with them (plan Task 8).
