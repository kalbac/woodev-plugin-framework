## The theme: every "obvious" answer was wrong, and only a measurement said so

Five times this session a plausible answer was refuted by an actual measurement — twice mine, once
a critic's, twice the operator's. The pattern is the same every time: **an inference written down as
a fact closes the question for the next reader.**

1. **The obvious fix for #517 was a no-op.** Wiring `onAbandon` into the select modes writes the
   marker — but `settlementTextIsKnownUnresolved()` compares it to the field's live `.value`, and a
   `<select>` never carries the customer's typed text. Predicted before dispatch, confirmed by the
   worker with a jsdom integration test. The card was two halves, not one.
2. **The critic's BL-1 was real but via a different path than the coordinator guessed.**
   `writeSilently` was cleared on all five call sites; the actual hole was that neither
   `clearDescendants()` nor `clearCountryScope()` clears `entry.unresolved[level]`.
3. **The critic's MJ-1 was wrong, and the worker was right to refuse it.** `clearedByEdit` has one
   writer, keyed on the level whose own field fired `change` — unreachable for a `<select>`. A
   later, independent critic adjudicated in the worker's favour in writing.
4. **`select2:close` fires BEFORE `select2:select`** — measured on the rig, four reproductions. That
   inverted round 2's guard and, worse, exposed that its two tests hand-dispatched the *fictional*
   order. Gotcha `select2-close-fires-before-select2-select`.
5. **The operator refuted two of the coordinator's claims about the CDEK reference.** See "What the
   operator caught" below.

## #528 — the merchant opt-in, and why #517 alone was half a feature

The operator asked the question nobody had: *the field still isn't filled, so how does the order go
through?* Measured by submitting: WooCommerce answers **`Shipping Город (Location Provider) is a
required field`**. Unlocking the address was necessary and not sufficient.

His design, adopted: a checkbox **«Разрешить использовать города не из списка»**, default OFF,
visible only for «Список с поиском». ON → select2 `tags` with `insertTag` gating the tag row to the
zero-result case (the CDEK shape); a tag pick is not a record pick. OFF → the whole #517 abandon
mechanism is gated off and the lock stands, because letting the customer fill a street that will be
rejected server-side is worse than an honest lock.

Critic MAJOR, fixed and re-verified live: the opt-in was not level-scoped, so the REGION widget also
received `tags` (`[true, true]` → `[false, true]`), letting a customer free-type a region into
`billing_state` — permanent order data, and exactly what the operator had ruled out.

  `preloaded`, not `popular` → gotcha `search-a-reference-by-behaviour-not-by-feature-name`.
- **`desc_tip`/`tooltip`, not `description`** — a standing convention that existed only in his head
  and in the code. Now in `AGENTS.md` → Conventions.
