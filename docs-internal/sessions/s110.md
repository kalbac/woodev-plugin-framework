## Decisions

1. **The warning level is armed per-sniff, not per-file.** Silencing 19 sniffs with one argument to
   avoid 1397 line-length reports cost visibility into 16 other sniffs. The exclusions now carry
   reasons, as the ~80 error-level ones already did.
2. **A deliberately-silenced rule must still be measurable, and that needs its own ruleset file** —
   proven necessary, not chosen for tidiness. See the gotcha.
3. **A one-off legitimate violation gets an inline `phpcs:ignore` with a reason, never a global
   exclusion.** A global exclusion disarms the sniff for all future code; the point of the card was
   that a rule enforced by nothing is not a rule.
4. **#701 and #689 are held identically** — open, with a stated entry condition — so the board does
   not encode the same situation two ways.

## Gotchas recorded

  merged stream, naming files nobody touched. It fooled the coordinator and then the Codex critic
  within the same hour, and the warnings are one-shot, so a re-run "clears" a problem that never
  existed.
- `a-phpcs-rule-silenced-by-exclude-pattern-cannot-be-revived-from-the-cli` — plus `tab-width`
  swinging the same line-length count between 1002 and 1393, and `--` being illegal inside an XML
  comment.
- `a-source-asserting-test-breaks-on-mechanical-reformatting` — 633 `array()`->`[]` cost 47 test
  failures from two causes, one of which (`parse_url` -> `wp_parse_url` inside PRIVATE methods) no
  grep over test files can find.
