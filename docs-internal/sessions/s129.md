### #842 — диагноз на карточке был неверен

Записано было «фикстура регистрирует два метода, провайдер объявляет один». По коду и замеру:

- строка `woodev_test_pickup_shipping` **не встречается в дереве вообще**, и среди
  зарегистрированных в WooCommerce методов её нет;
- сеялка пишет только объявленный id (`METHOD_ID = 'woodev_test_shipping'`);
- три заказа с ним (18, 19, 22, от 19.08 и 01.09) **не имеют ни маркера, ни статусной меты**, то

Единственный потребитель `get_method_ids()` — `Order_Row_Builder::resolve_type()`, то есть неполный
список **не выкидывает строки, а портит колонку типа** («неизвестно»). Карточка переименована под
это: настоящий предмет — контракт для автора плагина, который ничем не гейтится.

### #841 — упирается в отсутствующее поле дескриптора, и это общий предшественник с #834

### #841 — серверная половина (PR #846)

`carrier_order_id_meta_key` у `Orders_Provider`, аргумент `is_exported` в `Orders_Query` по
ПРИСУТСТВИЮ и с привязкой к маркеру, REST-аргумент, трансляция для CPT, объявления в обеих

|---|---|---|---|

### Мёртвый селект правила — и почему «просто убрать» было бы хуже

Его вопрос: «зачем этот селект если нет выбора кроме равен» у «Пункт выдачи» и «Трек-номер».

Сначала проверил у WooCommerce: **у них нет ни одного фильтра с одним правилом** — везде пара
(Includes/Excludes, Is/Is Not). Значит наш одинокий «равен» — наша самодеятельность.

Убрал `rules` совсем: селект исчез, ошибок нет, ссылка строится, адрес стал чище
(`has_tracking=no`). Выглядело как чистая победа — и было ловушкой. Спросил у компонента:

```js
getActiveFiltersFromQuery( { has_tracking_is: 'yes' }, rules: [ { value: 'is' } ] )  // => [ { … } ]
getActiveFiltersFromQuery( { has_tracking: 'yes' },    rules: [] )                    // => []
```

**Компонент ключует активные фильтры по правилу.** Без правила фильтр не читается обратно из
адреса: применил — таблица фильтруется, а блок пуст, ни изменить, ни снять. Откатил.

Оператор отклонил и CSS-вариант («скрывать через css это костыль»), и был прав. Настоящий ответ
нашёлся в том, что **селект правила рисуется только там, где заголовок просит токен `{{rule /}}`**,
а ключ адреса строится из массива `rules`. Оставляем правило, убираем токен — контрола нет,
возврат по адресу цел. Обе половины фальсифицированы: вернул токен — красный кейс, убрал
правило — два красных.

на его ветке, чтобы риг её отдавал. Карточка **#849** заведена именно под эту приёмку.
