## Решения оператора (07.10.2026)

- **Город отправителя — снова в каждом методе СДЭК** (ключ v1 `sender_city`). Общий город во вкладке был решением агента, не
  его; спека говорила «на зону». Шаг миграции «самый частый город → общий» удалён.
- **Упаковка:** «Доставка» → «Упаковка» = коробки магазина, ОДИН список на сайт, применимы к любому перевозчику (название,
  размеры, макс. вес, вес коробки, стоимость числом или `%`, вкл). Перевозчик сам объявляет свои предустановленные коробки
  (название и размеры обязательны, вес — по желанию) и **способ стоимости у каждой коробки**: считает перевозчик / фиксированная /
  задаёт магазин. Способ упаковки — по умолчанию во вкладке перевозчика, в методе переопределение «как в настройках плагина».
  «Как упаковывать товары, которые не поместились» — оставить (отдельно / в одну коробку), рядом со способом.
  Мой вариант «гибрид» он принял, потом уточнил: коробки магазина общие для всех, переключатель «для этого перевозчика» не нужен.
- **Сначала свои коробки** — когда подходят обе; цена выбор не определяет. (Критик уточнил: сначала меньше посылок, свои при
  равенстве — это и имелось в виду.)
- **Тестовый режим:** строка «В тестовом режиме используются встроенные ключи СДЭК. Ваши ключи сохранены.» — один раз под
  тумблером; заблокированные поля должны выглядеть заблокированными.
- **Сверка настроек 2.2.5.5:** вернуть «Статус доставленного заказа» (во фреймворк), «Логирование» (в новую секцию
  «Дополнительно», выкл = только ошибки), «Не показывать в корзине», «Префикс номера заказа», «Формат этикеток»; автообновление
  статусов — только кнопка «обновить сейчас»; тип карты, поиск на карте, «регион только для СДЭК» — не возвращать; спорное
  (подстановка индекса, перезагрузка формы, очистка адреса) — решать замером на риге.
- **«Отправка» и «Выгрузка заказов»** — делить по смыслу: данные отправления → «Отправка», процесс → «Выгрузка заказов».
- **Наложенный платёж за границу:** если валюта заказа ≠ валюте страны получателя — не выгружать, понятная ошибка.
- **Беларусь, стоимость доставки при наложенном платеже** (СДЭК игнорирует поле): рекомендация «отдельной позицией» —
  **не подтвердилась** (официальный плагин СДЭК так не делает, в документации нет) → **вопрос к оператору открыт**.
- **Коммит подключения миграции** (`831298d`) — оставить.
- ⚠ В начале сессии `AskUserQuestion` вернул «ответы», которых он не давал, и я по ним действовал → правило в памяти:
  решения — текстом, ждать его сообщения.

## Решения координатора (обратимые)

- Коробки v1 переносятся у всех магазинов, но **включёнными только у тех, кто в v1 упаковывал в коробки**; у остальных —
  выключенными (поведение не меняется).
- Старые коды коробок СДЭК (`S`, `L`, `500GR`, `1KG`, `15KG`) — не переносятся: под новыми кодами другие размеры
  (сверено с живым каталогом `apidoc.cdek.ru`, таблица в `docs/cdek-api/contract.md` плагина).
- Миграция: чтение единиц веса/размеров WooCommerce не переводилось на проверенное чтение — эти опции автозагружаемые, сбой их
  чтения означает неработающий сайт (находка критика C3c, оценена по живому магазину как недостижимая; не 4-й круг).
- Поиск города в методе — стандартный выпадающий список WooCommerce (selectWoo, AJAX), не свой JS. Фреймворк перезапускает
  инициализацию в модальном окне метода (`wc_backbone_modal_loaded`); методы СДЭК на риге открываются страницей, не окном.
