## Инструментальное

- **Orca не супервизирует kilo.** `--inject` набирает бриф, kilo его получает и работает, а Orca
  объявляет `agent_prompt_stalled`, закрывает диспатч и отзывает capability — `worker_done` летит
  в отказ. **Оператор проверил через UI Orca** (путь, недоступный агенту): поведение идентично, то
  есть дело не в способе запуска. Рабочий обход — диспатч **без** `--inject`. Карточка **#559**.
- Отброшено замером, а не рассуждением: `--timeout-ms 240000`, ожидание `tui-idle`, свежий
  терминал, kilo 7.5.5, `autoupdate: false`, повторный инжект.
- `"autoupdate": false` в `~/.config/kilo/kilo.jsonc` убрал стартовый диалог обновления, который
  съедал инжект и сжёг три задачи через предохранитель Orca.
- Две мои ошибки в диагностике kilo, обе исправлены заменой на замер: «терминалы Orca это WSL»
  (нет — я сам написал `--command "bash"`, а `bash` на Windows это `System32\bash.exe`) и
  «протухла TUI-сессия» (нет — TUI routes модель через провайдера `openai/…` с мёртвым oauth
  вместо `kilo/…`).
