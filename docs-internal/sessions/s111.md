## What was done

**The measurement that unblocked two cards at once.** #708 and #709 both ended with "measure the
volume in `plugins-reference/` before choosing". Both answers are **zero**, and not because the grep
was wrong: those plugins bundle framework **1.3.3 / 1.4.0** and ship no
`woodev/shipping-method/checkout/` at all, so they cannot contain any v2 symbol. That makes the
break free under ADR-005 — but for a structural reason, not a hit count. Gotcha
`plugins-reference-predates-every-v2-api`.

**#708 — CLOSED (PR #717). The card's own recommended option was incomplete, and the fixture proves
it.** The card recommended "require a takeover field only when its condition is true for the current
country". The fixture declares TWO takeover fields, both `set_required(true)`, with **different**
conditions: `billing_company` takes over BY/KZ/UZ (RU excluded by #294), `billing_address_2` takes
over RU/BY/KZ/UZ. So on RU that option fixes the first and leaves the second blocking checkout
forever. Measured on the rig, the deeper cause: `woocommerce_checkout_company_field = hidden` and
`woocommerce_checkout_address_2_field = hidden`, so WooCommerce renders neither regardless of
anything the framework decides.

The invariant restored is therefore wider than ownership: **`validate()` must not enforce OUR
`required` on a field `inject()` never put on the form.** A takeover field's `required` now needs
BOTH its condition owning the field AND a new `field_rendered_by_woocommerce()` seam confirming WC
kept it. WC unavailable means not enforced: an un-enforced field is recoverable, an order that can
never be placed is not. The worker independently confirmed the two-condition measurement before
building, and used a protected seam rather than mocking `WC()` to avoid the Brain Monkey pollution
trap.

**#707 — HALF fixed (PR #719), card deliberately left OPEN.** The card framed it as "2 of 85 RU
regions". A live `suggest()` sweep across all nine DaData countries says otherwise: Moscow, St
Petersburg, **Sevastopol** and **Baikonur**; **5 of 8** sampled Belarusian cities, **5 of 8** Kazakh,
**3 of 7** Uzbek; none in KG/AM/AZ/GE/MD/TJ/TM. In BY/KZ/UZ the id is an OSM relation, not FIAS, and
DaData puts the same one in `fias_id` and `region_fias_id`.

The fix needed no new invariant. `Location_Record::is_within()` is already reflexive, and
`Dadata_Provider` drops the self-key from `ancestors()` **because of it** — its docblock says so.
Two call sites simply bypassed the contract. Both now ask `is_within()`.

⚠ **What killed the card's option 2** (namespace keys per level): it changes the key FORMAT, and
keys are persisted in the popular-settlements table and the customer record. The reflexive route
needs no migration at all — which is why the card had no recommendation and now does.

**#694 / #695 — CLOSED (PR #718).** §16 of `SHIPPING-PLANS.md` carried the retired "one page per
provider" and justified it by claiming to mirror §15, which decided the opposite; the shipped code
followed §15. That citation was never true, not merely stale, and the docs now say so. Both root
planning files moved to `docs-internal/archive/`, seven inbound links repointed. Three cards filed
from the reconciliation's own "live remnants" table: **#712 #713 #714**.

⚠ **#712 turned up something for the operator:** the generic warehouse scaffold **predates** §17 —
approved 04.06.2026, merged 08.06.2026, three weeks before §17 reversed the decision it implements.

**#709 — CLOSED (PR #720).** The card's option 1 ("single source, derive the rest") is wrong on one
of the four mechanisms: `Selection_Scope::type_for_method()` answers *which KIND of point*, not
*whether* it is pickup, and its own docblock calls that plugin-owned domain knowledge. So
`is_pickup_shipping()` became the single source for the other **three**, and `type_for_method()` is
**reconciled** instead — a `WP_DEBUG`-gated, once-per-request `_doing_it_wrong()`, one-directional
because `pickup_method_ids()` spans every plugin's methods while one scope speaks only for its own.

⚠ **The trap that shaped it, and which the card did not mention:** `Pickup_Field::create()` bakes
its id list into a STATIC condition-spec at declaration time, while `pickup_method_ids()` needs
`WC()->shipping()`, which is not loaded then. So the derived default had to be LAZY — a new
`is_pickup_method` operator resolved at evaluation time. `Checkout_Condition` and the JS mirror stay
untouched: the sentinel always resolves to a concrete `in` spec before either sees it.

The fixture's `get_delivery_type()` flipped `courier` → `pickup`, because three of the four
declarations for `woodev_test_shipping` already agreed and only the source of truth dissented. That
is what made #652 scenarios 3 and 4 unplayable. ⚠ On the rig `woodev_test_shipping` now hides
address/postcode and shows the pickup button; the mu-plugin's method is partly redundant.

**#116(a) — CLOSED (PR #716).** The seven `@since 3.0.0/4.0.0/5.2.0` docblocks were UPSTREAM version
numbers; all four files entered at the initial import `01dfbe7`. They read ABOVE the released
`2.0.1`, so anything comparing versions concludes the API is unreleased — `2.0.2` would be untrue
the other way. Normalised to `1.0.0`, which this codebase already uses for "present from the start"
in 151 places. Rule 5 gains a standing clause so inherited code has an answer next time.

## Decisions

1. **#708 — ownership AND presence**, not ownership alone. Rejected the card's option 1 (symmetry
   with `inject()`) because a takeover field must still be requirable where takeover actually
   happens, and option 3 (`_doing_it_wrong()`) because a runtime no-op beats a declaration-time
   scold.
2. **#707 — the card's option 1 by meaning, but as "stop bypassing the invariant"**, not as a new
   special case. Options 2 and 3 rejected on the grounds above.
3. **#707's #538 half is NOT ours to decide.** From the data, "publishes no ancestry" and "is its
   own region" are the same empty array, and #538 deliberately fails open there, pinned by its own
   test. Left green, fork recorded on the card.
4. **The own key is a region candidate only when there are no ancestors.** Offering it alongside
   real ancestors costs a second live provider call whenever the first throws, since failures are
   never cached. An existing test caught that — it was not foreseen.
