### Block B — both closed

**#270 — CLOSED (PR #729). The rig fixture knows three cities now**: Москва (52 points),
Санкт-Петербург (4, real SPb coordinates), Краснодар (**exactly 1** — the single-point-in-a-city
shape #150 has never had). Unknown localities still return empty, so #162's guarantee did not
regress into "everything matches". Verified against the live rig by probe, not only by unit test.
The SPb/Krasnodar English alias spellings are **unverified guesses** and are flagged as such.

**#140 — CLOSED (PR #730), done by the coordinator — and the card's diagnosis was wrong.** The card
says two competing stubs race on load order. Measured first: there are **four**, and three of them
are namespace-scoped *deliberately*, so no global-versus-namespaced race existed. The two real
problems were different: `LocationControllerTest` and `PickupControllerTest` share one namespace, so
they were two declarations of one class with the first file loaded winning; and **a namespace-scoped
double cannot satisfy a global `\WP_REST_Request` parameter type** — that, not a race, is why the
REST callbacks had no type declaration and why SP-5's attempt fatally broke four tests. One global
union stub in `tests/bootstrap.php` (beside the `WP_Error` stub already shared there for the same
reason) removed both. Type hints restored on **13** callbacks, not the 5 the card names —
`Location_Controller` had the same defect on 8 more. Parameters only: these return
`\WP_REST_Response|\WP_Error`, and a union return type needs PHP 8.0 while the target is 7.4.

**#111 — audit merged (PR #733), card REOPENED.** A systematic sweep of 207 class-map entries, 15
non-class PHP files and every JS/CSS asset found only **four** provably dead files, all deleted; the
audit table is `reviews/2026-09-02-111-dead-file-audit.md`. The near-miss is the valuable part:

references a nonexistent near-identical name, which reads as a half-done rename rather than dead
code, so they were not touched.

## The #150 measurement — the rig does not run the fixture at all

#270 gave Краснодар exactly one point specifically so #150 became testable. It did not, and the
reason is worth more than the card:

**`WOODEV_TEST_PICKUP_LIVE_YANDEX = true` in the rig's `wp-config.php`, and that flag wins over
everything** — ahead of the Pochta flag and ahead of `WOODEV_TEST_PICKUP_STRATEGY` entirely. The
modal serves **300 real Yandex.Market points around Moscow**, never the 52 fixture ones. So #270's
work is correct, unit-tested and **invisible on the rig as configured**, and #150 stays unreachable.

Also measured: the `test-cdek` provider *does* know all three cities (`test-cdek:44` / `:137` /
`:435`), so the provider was never the obstacle. And with the bulk source forced on and the customer

diagnosed**; the rig was restored instead. Card **#734** (`Инбокс` — it asks him to decide whether
the rig stays on live Yandex), gotcha
`the-rig-runs-the-live-yandex-point-source-so-a-fixture-change-may-never-reach-it`.

## Two rules fixed where sessions actually read them

Both of these were already written down as gotchas. Neither had changed the rule, and both cost time
again this session. That pattern is the lesson.

**Serena ignores `tests/**` — recorded s105, still absent from the rule in s112.** The s105 gotcha
names the root cause in its own first paragraph: *"CLAUDE.md and AGENT-RULES.md state the rule
without an exception"*. Nobody edited those files, so my #270 brief repeated the bare "never `Read`
a `.php` file" line and the worker spent its opening moves proving Serena would not serve `tests/`.
The exception now lives in `AGENT-RULES.md` and `CLAUDE.md` with the full ignore list read off
`.serena/project.yml`: `tests/** docs/** .github/** .ai/** .serena/** .claude/**`.

**A PR body closes cards through a negation — recorded s111, fired again in s112 with the brief
warning about it.** PR #733's body said "Does **not** close #111"; GitHub matched `close #111` and
closed the card. My brief had carried the rule verbatim. The fix is not a louder prohibition: the
author had a real thing to say and the natural English for it puts the forbidden verb beside the
number. The gotcha now gives the **positive template** to copy (`Refs #111 — <what remains>`) and
the one-line `gh issue view <N> --json state` check after every merge, which is the only thing that
actually catches it.
