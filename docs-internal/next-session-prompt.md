# Что доказано замером

Скрипты переигрываются: `research/2026-09-25-839-join-growth-evidence/` и
`research/2026-09-26-919-subquery-seam/`. Разбор — `sessions/s139.md`.

1. **Коллапс области эквивалентен СТРУКТУРНО, не только перебором:**
   `clauses_bind_their_own_provider()` берёт только лист `marker EXISTS` либо AND-группу с ним, значит
   `filter ⇒ scope`, значит `scope ∧ filter ≡ filter` для ЛЮБОЙ строки — включая невыразимые перебором.
2. **`ShippingOrdersQueryRowSemanticsTest` — гейт, а не зеркало:** мутации боевого файла дают 6/30,
   6/30, 6/30, 18/30 падений, а «область не снимается никогда» — 30/30 зелено.
3. **Отрицательные фильтры `3M + B`** (было `4M + 2B`); фикстура s128 12 → 8. Позитивная колонка та
   же, **кроме `M = 0`**: `N + 1` → `1` (сторож NO_MATCH; обе формы не матчат ничего).
4. ⚠ **`3M + B` НЕ имеет запаса:** стена s128 — 12 джойнов при 2+2, а `3M + B` даёт те же 12 при
   `M = 4`. «Оставить как есть» было выборочным чтением и снято.
5. **Подзапрос #919 неэквивалентен, цена ни при чём** (1 джойн без привязки, `2M` INNER с привязкой
   против `3M + B` LEFT). Не проходит КВАНТОР: фильтр — существование по ПРИСУТСТВУЮЩИМ перевозчикам, а
   вычитание множества — «ни один присутствующий не замаплен»; `NEW ⇒ OLD` всегда. Расхождений 4/16/64
   при вселенных 16/64/128, **необъяснённых 0**; с привязкой 2/8/36, все многомаркерные.
6. **Многомаркерные заказы ПРОИЗВОДИМЫ плагинами** (`edostavka` пишет маркер на КАЖДЫЙ пакет,
   `yandex` — при экспорте, требуя лишь НАЛИЧИЯ своей доставки; фреймворк не пишет вовсе), а **подзапрос
   не доходит через поддержанную поверхность** — значит SQL-хук на обоих хранилищах, **и он ослепляет
   гейт**. Ссылки `file:line` — на #928.

# Ловушки

1. **`relation` в корне НЕ различает обёртку `AND` от одиночной необёрнутой части** (одиночная обычно
   сама группа), и «обёртка есть, если ЛЮБОЙ ребёнок равен области» тоже неверно. Готча
   `a-relation-key-does-not-tell-the-and-wrapper-from-a-single-meta-query-part`. **Приёмка — ОБЕ
   формы:** держи тесты, подменяй боевой файл (`git checkout main -- <файл>`, прогон, вернуть).
2. **Codex отдаёт `ok: true`, читается `live` и не делает НИЧЕГО** — 401 видно только в буфере
   терминала, `check --wait` сжёг весь таймаут. `projection.liveness` — это PTY, не агент. **#926.**
   Проверяй БУФЕР после старта, не `stage`.
3. **`CURRENT-STATE.md`, `SESSION-LOG.md` и ЭТОТ файл — все у своих гейтов:** добавление обязано что-то
   вытеснить, и поймают тебя в самом конце сессии. #930.
4. **`check` повторяет СТАРЕЙШУЮ неподтверждённую доставку** — хартбиты надо ack'ать, иначе вердикт не
   всплывёт; literal-переводы строк в отчёте требуют `strict=False`.
5. **`orca worktree rm` СОХРАНЯЕТ ветку воркера** (`preservedBranch`) — удалять отдельно, сверив, что
   содержимое в `main`.
6. **В брифе всегда `--testsuite=Unit`**, полный путь до `orca` в `Orca.app/Contents/Resources/bin/`,
   запрет интеграционной сьюты.
