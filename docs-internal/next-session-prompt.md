# ⛔ Первое и главное: сессия открывается обсуждением, кода не писать

Оператор придёт со **своей идеей** про поля «Населённый пункт» / регион / адрес и про провайдеров,
поставляющих данные о населённых пунктах. Он опишет её сам, полностью. От тебя нужно:

**подтвердить, отклонить или дополнить — с доказательствами, а не из вежливости.**

Правила этого разговора, все выстраданные:

- **Не бросаться в код и не предлагать спеку, пока идея не разобрана.** Есть навык
  `superpowers:brainstorming` — он для этого и существует, взять его.
- **Короткие сообщения, ОДИН вопрос за раз.** Он это прямо просил.
- **Сверить термины прежде чем строить дальше.** Три открытые карточки называют разными словами
  разные вещи; таблица терминов — §1 брифинга (ниже).
- **Отклонять можно и нужно — но замером или ссылкой на код, не рассуждением.** За s63–s66 замер
  четыре раза опроверг постановку карточки, и один раз (s66) — мою собственную правку. Его догадку
  проверять так же, как свою.
- **Не соглашаться раньше времени.** «Реши сам» у него означает требование замера, а не свободу
  выбора.

# ⚠️ Ловушки, до первой команды

Ловушки 1–10 из хэндоффа s65 **все ещё в силе** (пикер на `/classic-checkout/`, Serena+CRLF, Codex
только инлайн-бандлом, город на риге руками, wp-env из корня, jest только `npm run test:js --
--roots`, мутировать любое число, не `git checkout <файл>` для откатa мутации). Ниже — то, что
добавила s66.

**11. jQuery `.trigger('change')` НЕ создаёт нативного DOM-события, а select2 сообщает выбор
именно так.** Делегированный `document.body.addEventListener('change', …)` его не увидит. В s66
это стоило целой правки: семь зелёных мутационно-проверенных тестов дергали `new Event('change')`
— в jsdom это естественно написать, — и риг на первой же попытке показал, что слушатель не
срабатывает вовсе. Привязывать в ОБОИХ мирах; двойная доставка нативного события должна быть
безвредна **по построению**. Готча `jquery-trigger-change-fires-no-native-event`.

**12. jQuery 3+ делает `.then()` асинхронным, поэтому ready-колбэк съедает лишний тик таймеров.**
В jest-харнессе для `checkout-field-classic.js` нужно **три** генерации таймеров (`runAllTimers`),
а не две: `jQuery.ready` на таймере → `readyList.then(…)` на втором → `setTimeout(…,0)` takeover'а
на третьем. С двумя проходами takeover не запускается, поле остаётся `<input>`, и все проверки
опций молча сравниваются с пустым списком.

**13. `jquery` — devDependency этого репозитория.** Докблок `pickup-mount.test.js` утверждал
обратное до s66, и именно это делало слепое пятно (11) комфортным. Для пути, где продюсер события
— библиотека, хотя бы один тест обязан идти через настоящую библиотеку.

**14. Модульное состояние в `pickup-mount.test.js` живёт между тестами** — файл требует модуль один
раз наверху, `jest.resetModules()` в `beforeEach` его не перезагружает. Тест, зависящий от «записи
ещё нет», должен брать СВОЙ `fieldId`, иначе его вердикт решает предыдущий тест.

**15. На классическом чекауте `#shipping_method` лежит ВНУТРИ `tr.shipping td`.** Отсюда: нынешний
якорь §8 (вставка после этого `<ul>`) — это уже `woocommerce_review_order_after_shipping`. Не
путать с `woocommerce_after_shipping_rate` (внутри `<li>` тарифа) — это и есть отсутствующее место.

## 2. #274, пункты 2 и 3 — НУЖЕН ВЫБОР ОПЕРАТОРА, всё расписано в карточке

**Пункт 3 — постановка в карточке неверна, поправка замерена (см. ловушку 15).** «Второе место» не
отсутствует — оно занято; не хватает `after_shipping_rate`. На этой теме оба места окажутся в одной

рекомендация (**(б)** — список мест настройкой поля, дефолт «как сейчас») — в комментарии к #274.
Реализация варианта (б): 4 PHP-файла (`Field::mark_pickup_slot` → `Checkout_Fields::from_array` →
`Checkout_Config::build` → дескриптор в JS) плюс `placeSlot`/`mountOne`/`syncTriggerLabel`, которым
надо перестать работать с ПЕРВЫМ найденным якорем и кнопкой (`querySelector` → `querySelectorAll`).

**Пункт 2 — требует серверной части, но развилки нет.** Адреса после перезагрузки у клиента нет:
`Pickup_Selection` хранит только id, `get_js_config()` адрес не отдаёт. **Оба эталона оператора
хранят данные точки, а не только id** (Яндекс — массив в `chosen_yandex_pickup_point`, Почта — свои
данные под `get_short_formatted_address()`), значит ответ уже дан эталоном: положить адрес рядом с
id в ту же сессионную карту в момент подтверждения (сервер держит полный `Pickup_Point` там, где
зовёт `remember()`) и отдать в конфиг. Ни одного лишнего запроса к карьеру. Форма значения в сессии
меняется — это внутреннее, чистый clean-break: ключ сессии не трогается.

# Что нового знаем после s66

- **Постановка карточки может быть неверна в самом МЕХАНИЗМЕ, а не в деталях.** #272 называл
  виновником takeover-конвертер и предлагал не отправлять `change`; виноват каскад, и никакого
  `change` там не летит вовсе — предложенная правка не изменила бы ничего. Проверять механизм
  замером, а не только премису.
- **Риг может поправить не карточку, а ТВОЮ ПРАВКУ.** См. ловушку 11: семь зелёных мутационных
  тестов и нерабочий слушатель. Мутационная проверка доказывает, что тест различает две реализации,
  но не то, что он воспроизводит продакшен.
- **Ущерб задаёт расписание ЧУЖОГО актора.** Трёхсекундное окно между обнулением и ответом
  источника пересеклось с 50-миллисекундной сериализацией формы WooCommerce — и транзиентный сбой
  UI стал постоянной порчей сессии. Спрашивать, кто ещё читает это состояние до того, как придёт
  ответ.
- **Флаг, убирающий слой UI, глушит все ветки, которые через него докладывали.** Форма
  `if ( panels ) { … } return;` читается как защита, а ведёт себя как потерянный исход. Перечислять
  не то, что слой РИСОВАЛ, а то, для чего он был единственным местом.
- **Слой без единого теста ломается на каждой загрузке годами.** У `checkout-field-classic.js` не
  было ни одного jest-теста до s66.
- **Карточки не попадают на доску сами.** Ни одной из четырёх карточек s66 на доске №6 не было —
  `gh project item-add` обязателен, auto-add выключен.
