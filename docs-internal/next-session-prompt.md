# Что доказано замером

Подробности и переигрываемые скрипты — `research/2026-09-25-839-join-growth-evidence/README.md`;
разбор сессии — `sessions/s138.md`.

1. **Закон роста джойнов агрегатного фильтра доставки** (`M` — со статусной картой, `B` — без): без
   фильтра `N`; `delivery_status=unknown` и `..._not=<canonical>` — **`4M + 2B`**; позитивный —
   `N + участники`. «4 перевозчика (2+2) / unknown» = **12**, те самые из s128; двойной join маркера
   это слагаемое `N`.
2. **На HPOS листовая клауза = один join; на CPT `WP_Meta_Query` склеивает алиас между ПОЗИТИВНЫМИ
   `OR`-сиблингами** — позитивный фильтр там дешевле. **Стена на CPT — планировщик, не число
   джойнов** (12 по `wp_postmeta` не заканчиваются, 8 по `wc_orders_meta` — 4 мс), так что HPOS-only
   не убрал бы ни одного. Готча `on-hpos-a-leaf-meta-clause-is-always-one-join-on-cpt-wp-meta-query-shares-aliases`.
3. **Коллапс области эквивалентен перебором:** 16 / 64 / 128 заказов, ноль расхождений. Граница
   оттуда же: для позитивных `IN` снимать область не эквивалентно, привязывать к маркеру — сужение.
4. **Админский маршрут вправе обслуживать плагин без товара в магазине**
   (`class-plugin-license.php:130-178`, закреплено `LicenseCommandDispatcherTest.php:1279-1292`) —
   поэтому половина #907 не сделана сознательно.

# Ловушки

1. **`orchestration check` повторяет СТАРЕЙШУЮ неподтверждённую доставку, пока не подтвердишь** —
   опрос без `--ack` читает один хартбит и выглядит как молчащий воркер. Тело отчёта с
   literal-переводами строк делает `check --json` невалидным JSON: `strict=False`.
2. **`API Error: Connection lost mid-response` убивает ХОД воркера, а не работу** (дважды, второй раз
   ровно на `worker_done`). Контекст терминала цел — `terminal send` «продолжай, не переделывай».
3. **Codex может стартовать с четвёртой попытки, и Orca при этом списывает задачу** (три неудачных
   старта → circuit-break, `worker_done` отклоняется). Агент при этом работает: бриф — `terminal
   send --enter`, отчёт — ФАЙЛОМ. Codex теперь 0.157.0.
4. **`orca worktree rm` не удаляет ворктри с одним изменённым файлом** (обычно Serena). **`--worktree`
   обязателен с обеих сторон:** `--name` для новой, `name:<wt>` при переиспользовании терминала.
5. **В брифе всегда `--testsuite=Unit`** и **полный путь к `orca`** — критику тоже.
