при `200 OK` тоже считается сбоем (нашёл критик, закрыто с тестами на оба вида порчи).

**#406** — три круга с критиком. Сначала правило держалось только в браузере: частичное REST-

**колбэком**, тем же путём, что `get_active_provider()`, включая фильтр. Проверены все восемь
подмножеств `{policy, record, provider}`, правило само снимается при возврате провайдера и при

# 🔑 Главное про инструменты: Orca-оркестрация

Полный рецепт, правила размещения и ловушки — **`docs-internal/wiki/orchestrating-agents-with-orca.md`**.
Флаги `orca` **никогда не вспоминать по памяти**, бинарь отдаёт свой гайд сам:
`orca skills get orca-cli`, `orca skills get orchestration`.

Форма: **воркер = Sonnet 5, критик = Codex, свою работу не принимает никто.** Воркер держит контекст
в своём терминале, оркестратор читает только `worker_done` — это прямой ответ на то, чем закончилась
s82 («контекст раздутый»).

**Три вещи, на которых я споткнулся — все три мои как оркестратора:**

1. **Путь Serena в брифе.** Я вписал во все брифы `D:/Projects/woodev_framework` — это ГЛАВНЫЙ
   чекаут. У воркеров git был в своём ворктри, а правки Serena летели в моё дерево. Двое из трёх
   наступили. Ничего не потеряно только потому, что моё дерево было закоммичено. В бриф подставлять
   **путь самого воркера** и требовать проверить, что активация взялась. Готча
   `serena-activate-path-must-be-the-worker-s-worktree`.
2. **`input_accepted` в receipt — не доказательство запуска.** Трое из пяти агентов приняли задачу и
   не выполнили ничего: промпт лежал в поле ввода неотправленным, а `worker-show` показывал `ready`.
   Стоило двух девятиминутных окон ожидания. **Все случаи — запуск Codex** (его MCP-старт съедает
   Enter). Лечится `orca terminal send --terminal <h> --text "" --enter`. Готча
   `input-accepted-is-not-proof-a-worker-started`.
3. **Переиспользовать воркера — нужен и `--worktree`, и `--terminal`**, иначе
   `terminal_worktree_mismatch`. `--model`/`--effort` с `--terminal` не сочетаются.

Замерено, а не предположено: хуки агентов **включены**, но **у Codex падают** (`PostToolUse hook
(failed)`) — отсюда `session_not_reported` в `worker-read`; лечится `orca agent hooks prepare-codex`.
Управляемых аккаунтов Claude нет, Codex на системном oauth. Недельный лимит Codex — **0%**.

**Не взяли:** артефакты (за флагом, аудитории нет), автоматизации, Linear (доска — GitHub Projects),
эмулятор. **Встроенный браузер** пробовали один раз — первый же `snapshot` админки уронил соединение
с рантаймом; рантайм оправился, воркеры не пострадали, но отлаживать его при живых воркерах — плохой
размен. Риг остаётся на chrome-devtools MCP. Пробовать заново — только когда воркеров нет.

# ⚠️ Ловушки, всё ещё в силе

1. `ReflectionProperty::setValue()` — guard `setAccessible()` по версии PHP.
2. WooCommerce определяет страну свежего гостя ГЕОЛОКАЦИЕЙ с фолбэком `US`.
3. `Woodev_Setting::get_value()` кэширует — хендлер строить ПОСЛЕ подмены `get_option`.
4. JS-тесты ИЗ BASH (`npm run test:js -- --roots "<rootDir>/tests/js"`), никогда `npx jest`.
5. `billing_city` на риге — select2 старого демо §8, источник ничего не отдаёт.
6. Бэктики в `--body "$(cat <<'EOF' …)"` съедает bash — тело писать через `--body-file`.
7. **Закрывающие ключевые слова GitHub исполняются из ТЕЛА коммита буквально.** Гейт `.githooks`
   это ловит; в этом клоне уже включён (`git config core.hooksPath .githooks`).
8. **Кросс-хендлерный `show_if` работает и на сервере**, но опираться на него для КОРРЕКТНОСТИ
   нельзя — зажимать значение при чтении, `show_if` только прячет контрол.
9. `docker exec … wp eval-file` — путь внутри контейнера требует `MSYS_NO_PATHCONV=1`, иначе
   MSYS подменит `/tmp/x.php` на windows-путь и wp скажет «does not exist».
10. Читать чужую ревизию: `git show <ref>:<path>`, `git ls-files --eol` — они не трогают дерево.
    `git checkout --` и `git add -A` при живом воркере — как терять чужую работу.
