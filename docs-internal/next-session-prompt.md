# Что НЕ проверено — и почему (это важно для планирования)

**#158: фикстура рига не даёт проверить треть функциональности.** Все её точки одного типа `PVZ`,
нет совпадающих координат, мало точек, нет недоступной. Поэтому на риге **не наступают**: фильтр
типов (появляется только со второго типа), таббар совпавших точек, кластер с бейджем, заблокированная
кнопка выбора с причиной. **Если визуальный этап будет трогать эти поверхности — сначала расширить
фикстуру, иначе правки будут вслепую.**

Также не проверено: стратегия `viewport`, поиск по своему адресу, #150 (город с одной точкой),
ширина ≤782px, заказ end-to-end.

# Три вещи, о которые легко споткнуться

1. **Зелёные тесты ничего не говорят о том, что видит покупатель.** За две сессии риг нашёл семь
   дефектов при полностью зелёном наборе. Причина повторялась: **фикстура беднее продакшена**.
   Тест-хелпер отдавал форму `Placemark` там, где прод получает от `ObjectManager` голый объект;
   конфиг-фикстура не содержала ключей, которые реально эмитит PHP. Любое изменение, чей отказ
   выглядит как «криво» или «пусто» — проверять в браузере.
2. **Консоль браузера прячет ошибки ymaps.** Исключение внутри кросс-доменного скрипта приходит как
   голое `Script error.` без стека, и инструмент чтения консоли показывает чистоту при мёртвой
   отрисовке. **Скриншот консоли от оператора решил задачу за минуту** — если отладка буксует,
   попросить его.
3. **Город на риге сбрасывается.** §8 и `update_checkout` затирают `billing_city`; ставить его после
   того, как `jQuery.active` дойдёт до нуля, и проверять, что значение удержалось. Иначе bulk-запрос
   уйдёт без локали, и вы будете чинить уже починенное.

# Как работать

`superpowers:subagent-driven-development` себя подтвердил: исполнитель Sonnet 5 → критик Codex
`gpt-5.6-luna` inline-бандлом → правки. **Ревью находило существенное на каждой из 23 задач.**
Два приёма, добытых практикой:

- **В бандл критика класть саму спеку и явные границы задачи.** Без спеки он разворачивался на 180°
  между заходами; без границ требовал внутри одной задачи работу трёх соседних.
- **Сводное ревью на границе фазы окупается** — оно поймало пустой `modalId` в проде, который оба
  поточечных ревью пропустили, потому что каждое смотрело только свой диф.

Своя песочница codex на этой машине сломана (готча `codex-shell-sandbox-broken-windows`) — только
inline-бандл: заголовок с правилами проекта + текст задачи + спека + `git diff`, и
`codex exec -m gpt-5.6-luna -s read-only`.

# Решения, принятые против буквы плана (не пересматривать без причины)

1. **`contrastFor()` — стандартный WCAG.** План требовал «WCAG, порог 0.179», но его же ожидаемое
   значение для зелёного СДЭК `#0a8c37` этому противоречило (там чёрный даёт контраст 4.82 против
   4.36 у белого). Исполнитель подогнал формулу под тест — развёрнуто обратно.
2. **Деградация модалки не разрушительная.** Панели живут в том же контейнере, что и карта; один
   неудачный запрос не должен выносить работающий интерфейс. Тот же принцип — у состояния загрузки:
   оно наложением, а не заменой тела.
3. **`type`/`controlType` в поле настройки — по конвенции кодовой базы**, а не по сниппету плана,
   который противоречил сам себе.
4. **Добавлен шов `searchResults`** — план поручил разметку результатов поиска T15, их источник T19,
   а связать их не поручил никому.
5. **`pickup-panels.js` не раздроблён** при 1403 строках: из них 619 кода и 589 докблоков.
