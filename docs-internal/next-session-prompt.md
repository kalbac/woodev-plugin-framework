# ✅ Что сделано

**#404 + #407** — «Предустановленный список» у НП доступен, только когда у региона тоже список.
Зажим **при чтении**, сохранённое значение не переписывается и возвращается, когда условие снова
выполняется. Проза #407 признана ложной: блокировки поля НП в коде нет, подсказка переписана под
реальную причину — `LIST_HARD_CAP` режет список на 500.

**#405** — типизированный `Location_Provider_Exception`, `suggest()` сигнатуру не менял. Ветка
`502 upstream_error` в контроллере существовала, но не срабатывала — теперь срабатывает. Битый JSON
при `200 OK` тоже считается сбоем (нашёл критик, закрыто с тестами на оба вида порчи).

**#406** — три круга с критиком. Сначала правило держалось только в браузере: частичное REST-
сохранение обходило проверку, снятый с регистрации провайдер сравнивался сырой строкой, публичный
`set_default_locality_record()` шёл мимо валидации. Итог: валидация резолвит провайдера
**колбэком**, тем же путём, что `get_active_provider()`, включая фильтр. Проверены все восемь
подмножеств `{policy, record, provider}`, правило само снимается при возврате провайдера и при
«Отключено».

# 🔑 Главное про инструменты: Orca-оркестрация

**Ничего про Orca писать в стартовом сообщении не нужно — среда объявляет себя сама.** Скиллы
`orchestration`, `orca-cli` и `computer-use` установлены глобально (s83,
`orca skills install --skill … --agent claude-code`), так что они всплывают в списке скиллов
каждой сессии. **Вызывай скилл, а не вспоминай флаг** — его гайд версионно совпадает с бинарём.
Диспатченному воркеру Orca вдобавок сама вставляет преамбулу о том, кто он и кто координатор.

Раньше стоял только `orca-cli`, поэтому про оркестрацию сессия не знала вовсе — это и была
настоящая причина, по которой оператору приходилось объяснять окружение вручную. Если скиллы вдруг
пропали — переустановить, а не обходить хуком (я начал строить `SessionStart`-хук, оператор
справедливо назвал это костылём, хук удалён).

Полный рецепт, правила размещения и ловушки — **`docs-internal/wiki/orchestrating-agents-with-orca.md`**.

Форма: **воркер = Sonnet 5, критик = Codex, свою работу не принимает никто.** Воркер держит контекст
в своём терминале, оркестратор читает только `worker_done` — это прямой ответ на то, чем закончилась
s82 («контекст раздутый»).

**Три ловушки, на которых я споткнулся — все три мои как оркестратора.** Детали в готчах, здесь
только суть:

1. **Путь Serena в брифе** — вписал корень репозитория, и правки двух воркеров полетели в моё
   дерево. Подставлять путь САМОГО воркера и требовать проверить активацию.
   → `serena-activate-path-must-be-the-worker-s-worktree`
2. **`input_accepted` — не доказательство запуска.** Трое из пяти агентов ничего не выполнили,
   промпт лежал неотправленным. Лечится `orca terminal send --terminal <h> --text "" --enter`.
   → `input-accepted-is-not-proof-a-worker-started`
3. **Переиспользовать воркера — нужен и `--worktree`, и `--terminal`**, иначе
   `terminal_worktree_mismatch`. `--model`/`--effort` с `--terminal` не сочетаются.

Замерено: хуки агентов включены, но **у Codex падают** — отсюда `session_not_reported` в
`worker-read`; лечится `orca agent hooks prepare-codex` (прогнал, проверится на следующем запуске).
Управляемых аккаунтов Claude нет. Недельный лимит Codex — **0%**, он реально простаивает.

**Не взяли** (с причинами — в wiki): артефакты, автоматизации, Linear, эмулятор. **Встроенный
браузер** уронил рантайм на первом же снапшоте админки — риг остаётся на chrome-devtools MCP,
пробовать заново только когда воркеров нет.

# 🧰 Ворктри настроены — новый воркер работает сразу

**Ворктри лежат в `.orca/worktrees/` внутри проекта и готовы к гейтам без единой установки.**
`orca.yaml` шарит `node_modules` симлинком, `.worktreeinclude` копирует `vendor`, `.mcp.json`,
`.wp-env.override.json` и `.claude/settings.local.json`. Замерено: 2475 unit / 1260 jest / phpstan
чисто в свежем ворктри против 411 с на `composer install`.

**Больше НЕ пиши воркеру в бриф «сделай composer install и npm ci» — это уже неверно.**

`vendor` копируется и НИКОГДА не шарится: готча
`sharing-vendor-breaks-composer-autoload-in-a-worktree`. Всё остальное — устройство, ловушки,
почему это безопасно внутри репозитория — в `wiki/orchestrating-agents-with-orca.md`.

# ❗ Что осталось недоделанным по просьбе оператора

**Панели Settings в десктопном приложении НЕ пройдены** — оператор просил помочь именно с ними.
`orca computer` умеет их водить (скилл теперь установлен), но **только когда нет живых воркеров**:
это управление его рабочим столом. Начинать этот заход надо на пустой машине и с его согласия.

Две поправки, которые он сделал мне по ходу — обе стоили ему времени:

1. **Инструмент изучать по продуктовым докам** (<https://www.onorca.dev/docs>), а не по агентскому
   срезу бинаря. Именно там нашлись `orca.yaml` и `.worktreeinclude`, которых в скиллах нет вовсе.
2. **Не выдавать ключи из `orca-data.json` за названия настроек в UI.** Я сопоставил их с
   придуманными подписями — три пункта из пяти он просто не нашёл: две в интерфейс не выводятся,
   третья живёт на доске агентов, а не в Settings. Не подтверждено доками — так и говори.

# ⚠️ Ловушки, всё ещё в силе

1. `ReflectionProperty::setValue()` — guard `setAccessible()` по версии PHP.
2. WooCommerce определяет страну свежего гостя ГЕОЛОКАЦИЕЙ с фолбэком `US`.
3. `Woodev_Setting::get_value()` кэширует — хендлер строить ПОСЛЕ подмены `get_option`.
4. JS-тесты ИЗ BASH (`npm run test:js -- --roots "<rootDir>/tests/js"`), никогда `npx jest`.
5. `billing_city` на риге — select2 старого демо §8, источник ничего не отдаёт.
6. Бэктики в `--body "$(cat <<'EOF' …)"` съедает bash — тело писать через `--body-file`.
7. **Закрывающие ключевые слова GitHub исполняются из ТЕЛА коммита буквально.** Гейт `.githooks`
   это ловит; в этом клоне уже включён (`git config core.hooksPath .githooks`).
8. **Кросс-хендлерный `show_if` работает и на сервере**, но опираться на него для КОРРЕКТНОСТИ
   нельзя — зажимать значение при чтении, `show_if` только прячет контрол.
9. `docker exec … wp eval-file` — путь внутри контейнера требует `MSYS_NO_PATHCONV=1`, иначе
   MSYS подменит `/tmp/x.php` на windows-путь и wp скажет «does not exist».
10. Читать чужую ревизию: `git show <ref>:<path>`, `git ls-files --eol` — они не трогают дерево.
    `git checkout --` и `git add -A` при живом воркере — как терять чужую работу.
