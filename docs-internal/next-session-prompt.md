Реализованное решение (менять не надо, для контекста):

- `is_pickup_shipping()` — ЕДИНСТВЕННЫЙ источник правды для булева вопроса; из него выводятся
  `Pickup_Field::create()` (2-й параметр стал необязательным) и `set_requires_pickup_methods()`.
  Явный список по-прежнему переопределяет.
- `Selection_Scope::type_for_method()` **НЕ выводится** — другой вопрос («какой тип пункта»). Её
  ловит сверка `_doing_it_wrong()` под `WP_DEBUG`, один раз за запрос.

⚠ **Ловушка, которой не было на карточке:** `Pickup_Field::create()` запекает список id в
СТАТИЧЕСКИЙ condition-spec в момент ОБЪЯВЛЕНИЯ, а `pickup_method_ids()` требует `WC()->shipping()`,
которого тогда ещё нет. Поэтому дефолт резолвится ЛЕНИВО, новым оператором `is_pickup_method`.

# Что доказано замером

1. **Рекомендация карточки #708 была НЕПОЛНОЙ, и видно это только на фикстуре.** Два
   takeover-поля объявлены с РАЗНЫМИ условиями: `billing_company` — BY/KZ/UZ, `billing_address_2` —
   RU/BY/KZ/UZ. На RU вариант «требовать только когда условие истинно» чинит первое и оставляет
   второе блокировать заказ навсегда. Плюс на риге `woocommerce_checkout_company_field` и
   `..._address_2_field` = `hidden`. Инвариант шире: **`validate()` не имеет права требовать поле,
   которого `inject()` не ставил на форму** — нужны И владение, И присутствие.
2. **`plugins-reference/` не отвечает на «сколько потребителей у этого v2-API»** — там фреймворк
   **1.3.3/1.4.0** и нет `shipping-method/checkout/` вовсе, ноль там структурный. Готча
   `plugins-reference-predates-every-v2-api`.
3. **Схлопывание ключей у DaData — три страны, а не два города:** РФ — Москва, Питер,
   **Севастополь**, **Байконур**; BY — 5 из 8; KZ — 5 из 8; UZ — 3 из 7; остальные шесть — ноль.
   Полная таблица и метод — в готче `dadata-collapses-region-and-settlement-into-one-key`.
4. **Инвариант для #707 уже был в коде** (`is_within()` рефлексивен, провайдер выбрасывает
   собственный ключ ИМЕННО поэтому) — это убивает вариант 2 карточки: миграции БД не нужно.
   ⚠ Собственный ключ подставлять кандидатом ТОЛЬКО при пустом наборе предков.

# Ловушки

1. **Тело PR закрывает карточки в обход хука `commit-msg`.** GitHub видит ключевое слово рядом с
   номером и ИГНОРИРУЕТ отрицание вокруг него: «why this does not close #707» закрыло #707. Хук
   проверяет сообщение коммита, а поле описания PR — нет. Готча
   `a-pr-body-closes-cards-that-the-commit-msg-hook-would-have-refused`.
2. **`gh project item-list` молча обрезает по `--limit`.** На доске **338** элементов, и вызов с
   `--limit 300` показывает карточки как «не на доске». Та же готча.
3. **RAM — настоящий потолок агентов, а не квота.** Третий воркер (Fable) умер на
   `agent_prompt_stalled` при 1,6 ГБ свободных из 15,3, ретрай не взлетел. После освобождения
   воркера память НЕ вернулась выше ~2 ГБ: её держат языковые серверы и контейнеры. Мерить перед
   волной.
4. **`worker-read` и `terminal read` всю ночь отдавали ПУСТЫЕ буферы** при живых воркерах.
   Признаки жизни: ЗАГОЛОВОК терминала (воркер ставит его сам, спиннер крутится) и
   `git status --short` в ворктри.
5. **Serena `replace_content` переворачивает EOL** — проверять `git diff --cached --stat`.
   **Bash-heredoc рвётся** на длинном тексте с кириллицей: доки писать инструментом записи.
