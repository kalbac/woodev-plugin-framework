# ⚠️ Ловушки, до первой команды

**1. Пикер живёт на `/classic-checkout/`, а НЕ на `/checkout/`.** Второй — блочный чекаут
(адаптер это SP-11, не сделан): там нет ни `form.checkout`, ни поля `carrier_pickup_point`, ни
кнопки. Проба возвращает правдоподобное «фичи нет», и это читается как сломанная сборка, а не
как неверный URL. Товар для корзины — id `12`, `?add-to-cart=12`. Готча
`rig-checkout-url-is-the-block-checkout`.

**2. Serena: «сервер поднялся» ≠ «работает».** Нужен ручной `activate_project('woodev_framework')`,
проверять **символьным вызовом** (`find_symbol Woodev_Plugin/get_file` → `class-plugin.php:1040-1047`).

**3. Serena вписывает CRLF в PHP-файлы, которые репозиторий держит как LF.** Для правок
существующего PHP используй built-in `Edit`. Проверять `file <путь>` — там не должно быть
«CRLF line terminators». Готча `serena-replace-content-eol-flip`.

**4. Codex на этой машине не поднимает свою песочницу, и половина ревью выглядит как всё ревью.**
В s65 первый прогон честно написал, что шелл не стартовал и он не видел ни дифа, ни тестов, — но
вердикты по прочитанному выдал уверенно, и их легко принять за полный проход. **Гоняй его только
инлайн-бандлом** (`--prompt-file` из Bash, не через PowerShell — тот срезает одинарные кавычки) и
**требуй цитировать конкретные имена тестов**; если не цитирует — прогон не состоялся. Перезапуск
бандлом дал 8 находок, которых в первом прогоне не было в принципе.

**5. Город на риге надо задать руками, иначе пикер пуст:** в консоли страницы
`$('#billing_state').val('77').trigger('change')` → дождаться → `$('#billing_city')` (это
зависимый select, опции пустые на загрузке — при необходимости добавить `new Option`) →
`.val('Москва').trigger('change')`.

**6. wp-env — ТОЛЬКО из корня репозитория.** `MSYS_NO_PATHCONV=1` обязателен для путей внутри
контейнера. `wp config list` из корня — единственный честный способ узнать состояние рига.
Команды идут 15–120 с; это медленный риг, а не зависание.

**7. Достоверный jest только так:** `npm run test:js -- --roots "<rootDir>/tests/js"`. Никогда
`npx jest`. `<rootDir>` в **PowerShell** ломается — запускай из Bash.

**8. Экран рига через MCP ловит только медленные окна — меряй пробой, а не таймингом.** И
отдельно: **отличай серверное восстановление от клиентского**, читая атрибут `value` в разметке,
а не `.value` после отработки скриптов. В s65 именно атрибут был доказательством.

**9. Любое число в тесте мутируй соседним значением.** Тест, который пишет только РАЗНЫЕ ключи, не
проверяет порядок вытеснения; тест на непрозрачный ключ, написанный строчными буквами, не
проверяет непрозрачность.

**10. `git checkout <файл>` для отката мутации уничтожает незакоммиченную работу.** Копируй файл
через `cp` и возвращай через `cp`.

# Задачи — в этом порядке

## 1. PR #269 (#176) — нужна ручная проверка оператора

Выбранный ПВЗ теперь переживает перезагрузку чекаута. Хранится в `WC()->session` картой
`[ключ плагина][локация][код типа] = id точки`, **оба ключа объявляет домен** через новый сем
`Selection_Scope`; восстановление — серверное, через фильтр `woocommerce_checkout_get_value`, JS не
тронут ни строкой.

**Что я проверил сам** (`/classic-checkout/`, живой Яндекс, ветка PR): регион 77 → выбор точки →
перезагрузка → id **в атрибуте `value` серверной разметки**; регион 78 → перезагрузка → пусто,
метка кнопки вернулась к «Выбрать пункт выдачи»; обратно 77 → та же точка, метка «Выбрать другой
пункт выдачи».

**Что ригом НЕ проверено, и это написано в PR:** выбор точки в Питере — оба источника гейтят
выдачу по `FIXTURE_LOCALITY = 'Москва'`, точек для 78 нет вовсе; и очистка карты при создании
заказа — покрыта только юнит-тестами.

**Оператору стоит посмотреть:** не мигает ли поле и метка кнопки на загрузке, и как ощущается
уход на курьера и возврат к самовывозу (выбор при этом намеренно НЕ стирается).

## 2. Закрыть #178 и #143

**#178** («`WC()->session` против своего стора») — вопрос разобран по исходникам WC 11.0.0, вывод
в спеке §2 и в готче `guest-session-write-needs-the-cart-cookie`. Коротко: асимметрия гость/
авторизованный реальна (`save_data()` пишет только при `has_session()`, которую авторизованному
даёт `is_user_logged_in()`, а гостю — корзинная кука), но **на чекауте недостижима**, поэтому
дуальный стор для ПВЗ не нужен. Закрывать с русским комментарием.

**#143** — готча `session-key-vs-order-meta-prefix` советовала удалённый класс `Pickup_Selection`.
После мерджа #269 такой класс снова существует; надо переписать рекомендательную часть готчи под
него и закрыть карточку.

## 3. #265 — под `ownsChrome` обе ветки отказа немые

`finishSelection()`: `if ( ! result )` и `if ( ! result.allowed )` оба идут через `if ( panels )`, а
под `ownsChrome` панелей нет — покупатель не видит ни отказа домена, ни транспортной ошибки.
Рекомендация в карточке: `modal.showNotice( message )`. Строки есть: `selectFailed`, `stalePage`,
причина отказа — в `result.reason`. Образец, как это тестировать, — семейство #260 (реальный
`WoodevModal` в `pickup-mount.test.js`).

## 4. Свип по мелким багам карты — 171, 163, 150, 165, 155

Пять карточек, каждая мелкая; по отдельности не стоят цикла PR+проверка, вместе — один заход.
Часть визуальные → PR оставить оператору.

Оператор выполняет на проде `wp option get woodev_license_authority_keys --format=json` и сверяет

# Где мы по программе

Карта/ПВЗ — это **SP-5**, одна из одиннадцати подзадач шиппинг-модуля
(`specs/2026-06-25-shipping-module-decisions.md`).

| Фаза | Подзадачи | Статус |
|---|---|---|
| A | SP-1 настройки, SP-2 auth+секреты | ✅ |
| B | SP-3 слой полей, SP-4 DaData (отложен → #127), **SP-5 карта/ПВЗ** | ✅ |
| C | SP-6 расчёт+упаковка, SP-7 отгрузка, SP-8 трекинг, SP-9 письма, SP-10 админка заказов | ⚪ |
| D | SP-11 адаптер блочного чекаута | ⚪ |
| E | пилотная миграция: Яндекс → СДЭК → Почта | ⚪ |

**Техдолг и улучшения карты (181, 159, 152, 148, 182, 174, 173, 151) осознанно НЕ трогаем до
пилотной миграции** — пилот покажет, какие из них реальны. Следующая подзадача по зависимостям —
**SP-6** (расчёт стоимости + упаковка), она открывает всю фазу C.

# Что нового знаем после s65

- **Проверять надо не только «верна ли премиса», но и «полон ли ущерб».** Карточка #176 говорила
  «покупатель молча теряет выбор». Правда была хуже: замена адреса пишет в РОДНЫЕ поля WC, которые
  персистятся сами, поэтому страница выглядела так, будто выбор цел, а заказ не оформлялся.
- **Половина ревью выглядит как всё ревью.** См. ловушку 4.
- **Пустая строка из доменного сема — это отказ отвечать, а не значение.** Принятая за ключ, она
  сваливает все безымянные локации в одну корзину, и чтение, которое тоже не смогло ответить,
  достаёт точку из чужого города. Отвергать надо и на записи, и на чтении.
- **Экшен рядом с фильтром должен нести результат фильтра, а не его вход** — и гейтиться на
  финальном вердикте. Фильтр вправе перевернуть вердикт и вправе вернуть исправленный объект,
  который браузер потом и возьмёт.
- **Эталон часто лежит в его собственных боевых плагинах, и они решают задачу по-разному.** СДЭК
  держит карту `[city_code][type]`, Почта — один слот со сторожем по ФИАС. Это объяснило требование
  «домен объявляет свой primary key» лучше любого рассуждения.
