# 🚧 Что осталось в работе — #395 / PR #433

**Ключ лицензии в debug-логе.** Шесть кругов воркера, пять вердиктов критика, **все пять REJECT** и
каждый по делу. Полный разбор по кругам — `sessions/s84.md`.

Итоговая форма: редактирование **структурное, а не текстовое**. Query-строка и JSON-контейнеры
парсятся и редактируются по канонизированному имени на любой глубине; всё остальное — XML,
`print_r`, свободный текст, скалярный JSON — маскируется целиком. Шестой круг (`e2b5e39`, запушен)
не латал механизм, а **удалил** его: воркер прогрепал все вызовы
`set_request_content_type_header()` — везде `application/json`, аналога `Woodev_API_Form_Request`
нет, аксессора content-type нет, то есть **достоверного объявления формата в кодовой базе не
существует**, а выводить тип формы из синтаксиса тела нельзя (на этом карточка падала дважды).
Проверено **вызовом** через рефлексию всеми пятью формами утечки — все вернули маркер.

**⚠️ Шестой критик ЗАПУЩЕН и ОСТАНОВЛЕН на середине — вердикта по `e2b5e39` НЕТ.** Отсутствие
отказа за одобрение не считать. Проверить стоило две вещи: не проглотил ли whole-mask заодно
**структурный** JSON-путь (массив секретов, секрет на третьем уровне — они должны редактироваться

# 🔑 Про оркестрацию — что подтвердилось

Форма из s83 держится: **воркер Sonnet, критик Codex, свою работу не принимает никто.** **Каждая**
карточка, прошедшая через критика, вернулась с чем-то настоящим. Рецепт, шаблон брифа, четыре
обязательные строки и потолки — `docs-internal/wiki/orchestrating-agents-with-orca.md`.

Пятая строка брифа окупается на всём нетривиальном: **«тебе разрешено противоречить этому брифу;
если код не согласен — прав код».** За ночь она вытащила четвёртый незакрытый AJAX-хендлер,
которого не было ни в одной карточке, pre-flight проверку, которая существовала, но не читалась, и
«базлайн устарел», оказавшееся настоящей дырой в оснастке.

**И приём, который стоит копировать:** два последних вердикта по #395 решились тем, что критик
**вызвал метод и вставил в отчёт возвращённое значение**, тогда как три предыдущих круга спорили по
чтению кода. Критик, который запускает код, стоит нескольких, которые его читают.

# ⚠️ Ловушки из прошлых сессий, всё ещё в силе

`ReflectionProperty::setValue()` — guard `setAccessible()` по версии PHP · WooCommerce определяет

съедает bash, тело писать через `--body-file` · закрывающие ключевые слова GitHub исполняются из
тела коммита буквально (гейт `.githooks` включён) · кросс-хендлерный `show_if` работает и на
сервере, но зажимать значение надо ПРИ ЧТЕНИИ · `docker exec … wp eval-file` требует
`MSYS_NO_PATHCONV=1` · читать чужую ревизию через `git show <ref>:<path>`, а `git checkout --` и
`git add -A` при живом воркере — как терять чужую работу.
