# Три вещи, о которые легко споткнуться

1. **T8 делает `default_location` обязательным аргументом `Pickup_Handler`** и осознанно ломает каждый
   существующий тест, который его конструирует. Это не регрессия, это смысл задачи.
2. **T17 шаг 0 — проверить на риге, что `ObjectManager` вообще есть в `load=package.standard`.**
   Состав пакетов Яндекс не публикует. Если его там нет — убрать параметр `load` совсем.
3. **Правило экранирования не перепутать в обратную сторону.** Поля точки приходят уже
   `esc_html()`-экранированными и идут в `innerHTML` как есть; строки i18n и `selectable.reason` — нет,
   их экранирует JS. Обе ошибки тихие: в первом случае покупатель видит `&quot;`, во втором — дырка.

# Найдено в чужом репозитории, доски у него нет

При разборе `plugins-reference/woocommerce-edostavka/assets/js/frontend/woodev-yandex-map-plugin.js`
нашлись два реальных дефекта в живом плагине СДЭК. Спросить оператора, куда их деть:

- строки 327–331: `mapper.set( hash, mapper.get( elem.hash ) + 1 )` — `elem` это строка с id
  контейнера, у неё нет `.hash`, поэтому `undefined + 1 = NaN`. Должно быть `mapper.get( hash )`.
  У второй и всех последующих точек с одинаковыми координатами `orderNumber` становится `NaN`.
- строки 318–361: в `.map()` ветка «код уже был в `setter`» ничего не возвращает, и в массив,
  уходящий в `objectManager.add()`, попадает `undefined`.
