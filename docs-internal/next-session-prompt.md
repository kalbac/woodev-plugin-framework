# Ловушки

1. **`worker-start` может отдать `input_accepted` и НЕ запустить воркера.** У меня так умер один
   из трёх: `dispatch-show` показал `status: failed`, `last_failure: agent_prompt_stalled`,
   `completed_at` через 10 секунд после `dispatched_at`. Я этого не проверил и **10 минут ждал
   мёртвого воркера**. После каждого `worker-start` читать `dispatch-show`, а не приёмный статус.
   Лечится `worker-start --retry-of <старый ctx>`.
2. **`check --wait --timeout-ms` больше 10 минут бесполезен из Bash** — инструмент режет вызов на
   600 с. Ставить таймаут не больше 540000 и делать несколько ожиданий подряд.
3. **Три воркера в ОДНОМ дереве работают, если файловые множества не пересекаются И им запрещены
   git и гейты.** Проверено на двух волнах по три. Гейты гоняет координатор — иначе тот самый OOM.
4. **Bash-heredoc с закавыченным маркером СЪЕДАЕТ одинарный уровень экранирования** — двойной
   обратный слэш доезжает как одинарный. Python-скрипты с обратными слэшами писать raw-строками.
5. **`git stash push -- woodev/` ничего не сташит, если правки УЖЕ закоммичены** — фальсификация
   тогда «проходит», ничего не доказав. Откатывать `git checkout <base> -- woodev/` и проверять
   замером (`grep -c`), что откат состоялся, ДО прогона.
6. **`Woodev_Payment_Gateway` абстрактный, а свойство `id` объявлено в `WC_Payment_Gateway`**, в
   юнит-тестах это голая заглушка без свойств. Двойник должен объявить `public $id;` сам, иначе
   рефлексия падает с `Class "" does not exist`.
