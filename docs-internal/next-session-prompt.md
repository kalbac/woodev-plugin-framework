# Что доказано замером

Подробности — `sessions/s132.md`.

1. **Четыре числа страницы СОШЛИСЬ**: «Всё время» даёт 134 / 134 / 134 при 101 новых, и бейдж в
   меню показывает те же 101; «С начала года» двигает все вместе в 110 / 110 / 110 и 83.
2. **У `wc.date` нет пресета «всё время», свой не подсунуть, `period=custom` требует ОБЕ даты, а
   любой неизвестный период БРОСАЕТ и роняет всё приложение wc-admin.** Поэтому «всё время» —
   отсутствие параметра, и оно переживает навигацию: `getPersistedQuery` это `pick`.
3. **`wc.components.DateRange` — только календарь**, без пресетов и без «compare to».
4. **`wc_admin_register_page()` не читает `order`**, а `position` — индекс, который у их
   собственных пунктов случаен.
5. **`Shipping_Admin_Order` не строится НИКЕМ** — поиск ссылок пуст, и наш же тест это документирует.

# Ловушки

Только новое за s132; прежнее — по тегам в `GOTCHAS.md`.

1. **Широкая ячейка ВНУТРИ `woocommerce-segmented-selection` ломает их разделители** (чётность
   потомка) и **`react-dates` рисует месяц жёсткими 300 px** — обе с готчами.
2. **`check --json` мешает однострочные keepalive с МНОГОСТРОЧНОЙ доставкой**: построчный парсер
   три ожидания подряд рапортует «пусто», пока воркер жив.
3. **`worker-start` без `--model` берёт модель КООРДИНАТОРА**; квитанция пишет `model: null` с обеих
   сторон. Ставить `--model sonnet` явно и сверять по экрану терминала.
4. **Файлы каталога переводов — CRLF**, и вставка по якорю с `\n` честно не находит его.
   **`lint:i18n-sources` читает СОБРАННЫЙ бандл** — после правки разметки гонять каталожные гейты,
   а не только typecheck/build/jest. Ровно на этом CI поймала s132.
5. **Центрирование попапа по кнопке — поведение WooCommerce, не дефект** (их пикер перевозчиков на
   той же странице торчит за края так же).

⚠ **Читать доску по полю «Приоритет».** Считать с `--limit 300` для issue и **`--limit 1000` для
`project item-list`**.
