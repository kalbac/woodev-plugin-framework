# Семь дефектов, найденных только на риге — не тестами

1. **Два `.woodev-pickup-map` на странице.** Провайдер строил собственный канвас-сиблинг в теле
   модалки, хотя T5 уже дал панелям свой элемент карты внутри сцены. Правила CSS совпадали
   дважды. Исправлено: мост передаёт `panels.getMapElement()`.
2. **Кнопка сайдбара внутри списка.** `right: calc(...)` мерил `100%` от 320px-бокса СПИСКА
   (288px вместо 336px) — кнопка садилась на панель, а не рядом. Стала сиблингом на сцене.
3. **`focusGroup()` двигал камеру только для точки внутри кластера.** Хелпер строился под другую
   задачу (уйти от кластера) и был переиспользован для паритета клика без проверки, что охват уже
   другой — обычный видимый маркер вообще не зумил. Готча
   `focusgroup-only-moved-for-clustered-points`.
4. **`objectManager.setFilter()` берёт ОДИН аргумент, не `(objectId, object)`.** Выбор конкретного
   типа прятал ВСЕ маркеры, не только несовпадающие — юнит-тест звал сохранённую функцию с той же
   неверной сигнатурой, ничего не спорило. Подтверждено на живом `ymaps.ObjectManager` в консоли.
   Готча `ymaps-objectmanager-setfilter-single-argument`.
5. **`setAnchor()` пересортирует список, но не открывает его.** Выбор адреса при открытой карточке
   оставлял её на экране поверх корректно отсортированного, но невидимого списка. Добавлен
   `Panels.prototype.openList()`.
6. **Два мобильных дефекта**, видимых только на реальном узком экране: инлайновый
   `dialog.style.minWidth='920px'` бил медиа-запрос (та же коллизия, что T19 уже чинил для высоты
   тела, только на соседнем свойстве не починил); зум-контрол плавал поверх карточки на всю ширину.
7. **Враждебная тема `button{display:none!important}` прятала ВСЕ кнопки модалки**, включая
   закрытие — у сброса стилей намеренно нет `!important`, но `!important` бьёт что угодно кроме
   `!important`. `display` — единственное исключение из правила «без `!important`»: потерять шрифт
   кнопки — декорация, потерять факт её существования — сломанная функция.

Плюс: `.woodev-pickup-overlay[hidden]` не работал (найдено при код-ревью T17, не на риге) — тот же
класс бага, что и №7: авторское `display:flex` побеждает UA-таблицу `[hidden]` при равной
специфичности.

# Что уже работает — проверено мной на риге 04.08.2026

- Модалка открывается на полный размер сразу, спиннер до карты, спиннер поверх карты при загрузке
  точек — карта не перетаскивается в этот момент.
- Клик по маркеру и по строке списка/поиска — одинаково: камера едет к точке, открывается наша
  карточка, **балун Яндекса не открывается никогда**.
- Поиск: свой шаблон (не английская плашка Яндекса), мгновенные совпадения по загруженным точкам,
  геокод только по submit, **жёстко ограничен границами загруженных точек** («Тольятти» из чужого
  города — ничего не находит; «Москва, Кремль» — находит и открывает список по расстоянию).
- Фильтр типов: скрыт при одном типе, бейдж со счётчиком, последний тип нельзя снять.
- Совпадающие координаты → таббар в карточке между точками одного адреса.
- Кластер с бейджем счётчика.
- Заблокированная кнопка выбора с причиной (проверено на точке без COD при выбранной оплате при
  получении).
- Сайдбар: без заголовка, иконка+адрес жирным+название серым, нижний отступ не даёт копирайту
  съесть последнюю строку.
- Карточка: чип, секции с разделителями, липкий футер.
- Кнопка сворачивания/разворачивания: квадратная, акцентная, прячет и список, и карточку разом,
  разворачивается обратно в список (не в карточку).
- Мобильный (390–500px): диалог и панели на всю ширину, зум и переключатель корректных размеров.
- Враждебная тема (`button{display:none!important}`, `h1,h2{font-size:34px;text-transform:uppercase}`,
  `input{border:4px solid red;height:80px}`) — всё выживает.
