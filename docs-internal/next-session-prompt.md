# 🎯 Что брать

## #337 — блокировать поле адреса, пока не выбран НП

**Решение: ТОЛЬКО блокировка. Обратный матчинг НП из адреса НЕ делаем** (рассмотрен и отклонён —
рассуждение сохранено в карточке, в работу не идёт). Блокировка закрывает сценарий по
построению: напечатать адрес, не выбрав НП, станет нельзя, поэтому выводить НП неоткуда и незачем,
и не надо угадывать между `city_fias_id` и `settlement_fias_id`.

**Правило сужено оператором — это главное.** Блокировка включается, только когда выполнены ОБА
условия:

1. НП и адрес **связаны** (у поля адреса есть `depends_on` на поле НП);
2. провайдер **даёт подсказки для уровня `address`**.

**Во всех прочих случаях поле адреса — обычный инпут**, никакой блокировки: если адресных
подсказок нет, покупателю НП для ввода адреса не нужен.

Тонкости: заблокированный контрол **не поясняем** (ни `title`, ни aria, ни подписи — стоячее
правило оператора); условие 2 читается ПОУРОВНЕВО из возможностей провайдера, а не из факта «он
активен»; блокировка и разблокировка — оба перехода под тест; при уже выбранном НП поле обязано
быть активным сразу после перезагрузки, а не после первого события.

## #343 — фикстура провайдера СДЭК, ЖИВОЙ тестовый контур

**Источник: живой API СДЭК**, не зафиксированные ответы. Блокера по ключам нет: у СДЭК
**тестовый контур `https://api.edu.cdek.ru/v2/`** (боевой — `api.cdek.ru/v2`), OAuth на
`/v2/oauth/token`, и по их же FAQ тестовые аккаунты используют **общие учётки из документации** —
заказы с тестовыми ключами не обрабатываются. Утечки тут нет по определению.

**Документацию читать через Context7, не фетчем.** Портал <https://apidoc.cdek.ru/> — SPA, простым
фетчем отдаёт пустой заголовок. В Context7 есть `/websites/apidoc_cdek_ru` (478 сниппетов) и —
отдельно ценное — **`/cdek-it/wordpress`, официальный плагин СДЭК для WooCommerce**, то есть
готовый референс того, как они сами встраиваются в WC.

Уже выяснено: `GET /v2/deliverypoints` в `location` отдаёт `city_code`, `city_uuid` **и
`fias_guid`** — значит идентичность города у СДЭК может выражаться через ФИАС, и вопрос «как она
ложится на `Locality_Key`» решается замером, а не догадкой.

Смысл карточки: сейчас на риге один провайдер, который умеет всё, поэтому многопровайдерность
непроверяема вживую, а самодельные фикстуры проверяют мои допущения, а не контракт (готча
`an-invented-fixture-tests-your-assumptions-not-the-carrier`). Два сценария: **(А)** СДЭК активен и
уровень `address` не поддерживает — поле адреса остаётся обычным инпутом (ровно правило из #337 в
живом виде); **(Б)** СДЭК держит НП/регион, DaData даёт suggest только на `address` — проверить
поуровневый арбитраж, корректный `within` и что ключи разных провайдеров не смешиваются
(`Locality_Key` несёт `provider_id`). Смежно с **#333**.

## #325 — мультипакетная корзина: НЕ делаем, оставляем шов

**Решение: YAGNI, потребителей нет.** Полноценную мультипакетность не строим. Но шов под будущую
реализацию оставить — «нет потребителя» не аргумент против точки расширения.

Задача сводится к тому, чтобы односоставность слоя §8 была **следствием конфигурации, а не зашитым
допущением**: проверить места, где «один» зашито неявно (ключи сессии, идентификатор слота, поиск
поля ПВЗ), оставить фильтр/действие на границе и явно записать в докблоке, что это принятое СЕЙЧАС
ограничение с известной точкой расширения — иначе следующий агент прочитает его как недоделку и
пойдёт «чинить». Карточка остаётся открытой как место для этой работы.

# ⚠️ Ловушки, купленные этой сессией дорого

1. **Правило, записанное текстом, не исполняется само.** Три правила из `DOCS-SCHEMA.md`
   нарушались 14 сессий подряд, причём агентами, которые эту схему читали. Работает только
   механическая проверка. Аналогия оператора: доска с карточками дала прирост качества именно
   потому, что у карточки ОБЯЗАН быть статус, а не потому, что она удобнее файла.
2. **Гейт находит то, что ручной разбор пропускает.** Мой фильтр по 150 записям пропустил две
   штуки, которые гейт нашёл с первого прогона: запись, разъехавшуюся на две строки (внутри
   inline-кода стоял литеральный перенос), и запись без детального файла.
3. **Прежде чем удалять текст — доказать, что он дублируется.** Дифф пометил 44 записи из 150;
   7 проверок по ГРАНИЦЕ правила (числа-замеры — самое вероятное место потери) дали форматный шум,
   и один реальный пропуск нашёлся и был дописан в файл ДО сжатия.
4. **Гипотезу оператора проверять замером, а не соглашаться.** Предложение по #339 звучало
   стройно и было неверным по четырём независимым причинам сразу. Он сам просил проверить до
   принятия — и это оказалось единственным способом узнать.
5. **Спрашивать «где ломается», а не «работает ли».** Первый замер #339 (аккуратные адреса с
   запятыми) выглядел терпимо. Обрушила гипотезу строка в РЕАЛЬНОЙ форме карьера, без запятых:
   `Москва Внуково Центральная 6` → `г Москва, ул Центральная, д 6`, `qc=3`. Готча
   `an-invented-fixture-tests-your-assumptions-not-the-carrier` — ровно про это.
6. **Контроль в том же прогоне превращает «стало зелено» в утверждение.** По #339 в одном
   прогоне: объявленная запись → запись НП цела и `within` уходит; правка города рукой сразу
   после → сброс есть, `within` пропал. Без второй половины фикс мог оказаться «выключил каскад».
7. Прежние в силе: поднятие `VERSION` на `main` публикует релиз (#285),
   `rig-serves-the-working-tree-branch-switch-reverts-fixes`,
   `phpunit-defects-cache-hides-cross-test-session-leaks`,
   `powershell-drops-the-roots-flag-from-the-jest-command` (JS-тесты гонять из bash),
   `git add -A` подметает чужое — перечислять файлы явно.

# Как оператор работает — что подтвердилось в s75

Дал задачу одной фразой, потом уточнял по ходу короткими репликами, а не переписывал постановку.
Считает **ведение доков инфраструктурой качества**, а не бюрократией: сам назвал переход на доску
с карточками тем, что «дало качественный прирост», и просил, чтобы с остальными доками был такой
же порядок. Свою же гипотезу просит **проверять до принятия** и спокойно принимает опровержение,
если оно с замером. Визуальную проверку делает сам, но не всегда за компом — если его нет,
задачи, упирающиеся в глаза, лучше не начинать.
