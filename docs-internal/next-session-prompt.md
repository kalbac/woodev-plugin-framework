# Что доказано замером

1. **Владение методом ПВЗ из хендлера вывести НЕЛЬЗЯ.** `Shipping_Method::get_plugin()` —
   `abstract protected`; токен хендлера (`$hook_prefix`) со списком его методов не связан:
   `woodev_realistic_shipping` против id плагина `woodev-realistic-shipping`, и
   `woodev-test-shipping-method` против метода `woodev_test_shipping`. Любой план «отфильтровать по
   плагину» упирается в это — проверять ДО начала работы.
2. **`private static` в классе, который каждый плагин строит себе сам, отвечает за ФЛОТ.** Флаг
   «уже сделал» на нём проверяет только первый плагин, молча. Готча
   `a-process-static-once-per-request-gate-checks-only-the-first-plugin`.
3. **Слой `checkout/` конфликты билдера РЕПОРТИТ, а не бросает:** 17 `_doing_it_wrong()` против
   одного `throw`, и тот — провал поиска. Прецеденты, когда уведомление уместно и когда нет,
   записаны в `class-checkout-handler.php:2469-2473` и `class-field.php:113`.
4. **Модалка ПВЗ не шлёт `locality`, пока регион и населённый пункт НЕ СОГЛАСОВАНЫ.** Значения
   `select`'а региона — ЗАГЛАВНЫМИ (`МОСКВА`, `КРАСНОДАРСКИЙ КРАЙ`), поэтому запись туда строки в
   обычном регистре делает поле ПУСТЫМ и параметр молча исчезает: пустой список на здоровом 200.
   Установка одной только записи через `set_customer_record()` не меняет ничего — запрос ведут
   ПОЛЯ. Готча `the-pickup-modal-s-locality-comes-from-the-resolved-record-not-the-city-field`.
   ⚠ Первая редакция этой готчи (02.09) винила не то и породила ошибочную #741 — обе исправлены.
5. **`boundsChange` эмитится только на стратегии `viewport`.** Любой замысел «следовать за картой»
   на `bulk` не работает — именно поэтому живой центр карты в #163 отвергнут.
6. **Дефект очереди платёжной формы (#738) унаследован, а не привнесён v2** — в отгруженном v1 то
   же расхождение и тот же набор файлов на диске.
7. **`test-cdek` — не фикстурный словарь, а клиент живого тестового контура СДЭК**
   (`https://api.edu.cdek.ru/v2`). Греп по файлу НЕ говорит, какие города он знает.

# Ловушки

1. **Сверять «риг не тронут» надо ПО СЕССИИ WooCommerce, а не только по user meta.** В s113 первая
   сверка сказала «байт-в-байт», а в сессии остался чужой `billing_city`, и следующий замер показал
   0 точек — что читалось как сломанный фикс. Запись потом восстановлена из бэкапа.
2. **Архивную спеку правит ПОМЕТКА, а не переписывание.** `docs-internal/archive/` — снимок того,
   что решили тогда. Воркер переписал §7.1, пришлось возвращать. Писать это в бриф.
3. **Тело PR закрывает карточки ЧЕРЕЗ ОТРИЦАНИЕ.** Шаблон `Refs #N — <что осталось>`, и
   **проверять после каждого мержа**: `gh issue view N --json state`. В s113 сработало правильно
   четыре раза подряд — шаблон в брифе работает.
4. **`gh project item-list` по умолчанию отдаёт 300 элементов, а на доске их 344** — свежие
   карточки в выдачу НЕ попадают, и это читается как «карточки нет на доске». Всегда
   `--limit 1000`. (Отдельно от известной ловушки, что `item-add` может вернуть 0 и не добавить.)
5. **`git stash` в ворктри с CRLF-мусором не возвращается по `pop`** — правки остаются в стеше, а
   `pop` молча делает вид, что применил. Доставать явным `git checkout stash@{0} -- <файлы>`.
6. **Serena игнорирует** `tests/** docs/** .github/** .ai/** .serena/** .claude/**` — там встроенные
   инструменты ЕДИНСТВЕННЫЕ, и это не нарушение правила. Вписывать в каждый бриф.
7. **Ворктри стартуют грязными с СЕМЬЮ CRLF-файлами**; удалять только через Orca.
   `worker-release` штатно отвечает `identity_unproven` и терминал оставляет — это документированная
   граница, а не сбой.
