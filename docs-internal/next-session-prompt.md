# Доказано замером

1. **Вердикт провайдера о сужении НЕ всегда известен до запроса.** DaData ветвится детерминированно,
   а ветка компонентов CDEK уходит в `region_code_for_name()`, которая обходит словарь наверх. Это
   выбраковало целый класс решений («пусть провайдер объявит заранее») до первой строки кода.
2. **Контроль решает исход замера.** Первый браузерный проход «показал возврат записи» — но это
   отрабатывала `fixed`-политика магазина (`implicit: true`), а не память о покупателе. Только
   повторный замер явно записанным Санкт-Петербургом (`implicit: false`) доказал настоящее.
3. **`clearCountryScope()` чистит поля WooCommerce, и тот сохраняет очистку у себя** — а цепочка
   woodev оставалась. Два серверных хранилища противоречили друг другу: доставка считалась по
   Санкт-Петербургу, покупатель видел пустое поле.
4. **`woocommerce_delete_inactive_accounts` на риге лежит как `['number' => '', 'unit' => 'months']`** —
   форма «не настроено». Явная запись покупателя пережила перезагрузку: правило «не удалять по
   сроку, который магазин не выбирал» подтверждено живьём, а не только юнитами.
5. **`woodev_location_default_locality_record` хранит ЦЕЛУЮ запись**, а не ключ `test-cdek:44`, к
   которому её сокращали доки. Готча
   `the-default-locality-option-stores-a-whole-record-not-a-key`.

# Ловушки

1. **`docker cp` В контейнер на этом риге не работает** (бинд-маунт), а `wp eval-file` потом
   докладывает обычное «does not exist» — и это читается как неверный путь. Заливать пайпом:
   `docker exec -i "$C" sh -c 'cat > /tmp/probe.php' < probe.php`. И `--user=N`, когда проба трогает
   что-то пользовательское. Готча `docker-cp-into-the-wp-env-container-fails-pipe-the-probe-instead`.
2. **`phpstan --memory-limit=2G` локально падает по памяти и выглядит как находка анализатора.**
   Локально `4G`.
3. **Бандл критику больше ~32 КБ не влезает в argv** — `Argument list too long`. Класть в файл,
   канарейку внутрь файла. Готча `a-codex-bundle-over-32k-needs-a-file-and-an-in-file-canary` (s85)
   это уже знала, а s106 переоткрыл на своей шкуре: читай тег `[tooling/*]` ДО круга критика.
4. **Инжект в Codex теряется, пока стартуют MCP-серверы** — композер оказывается пустым. Перечитать
   экран и доставить бриф повторно через `terminal send`.
5. **CRLF-шум в ворктри Orca ломает `git rebase`, включая `--autostash`.** Ребейзить ворктри не
   надо — открывай PR как есть, CI гоняет на merge-ref.
6. **Интеграционные тесты воркер написать может, а прогнать — нет** (в ворктри нет wp-env). Гонять
   их обязан координатор; «написаны» это не «зелены».
7. **Serena ИГНОРИРУЕТ `tests/`** — там `Read`/`Edit` единственный инструмент, это не нарушение.
8. **Serena переводит КАЖДЫЙ тронутый production-файл в CRLF** — чинить до коммита.
9. **Старт воркера проверять ПО ТРАНСКРИПТУ** (`worker-read`), не по `input_accepted`.
10. **Фоновый `orca orchestration check --wait` захватывает ожидание Run** — не запускать в фоне.
