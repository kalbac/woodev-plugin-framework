## Эталон

`plugins-reference/woocommerce-yandex-delivery` — карта, которую оператор считает своей лучшей по UI/UX.
Ключевые файлы: `assets/js/frontend/wc-yandex-delivery-widget-map.js` (620 строк — кластеризация, drawer,

Две вещи оттуда, которые обязательно воспроизвести: **список синхронизирован с вьюпортом карты**
(`boundschange` → `geoQuery`) и **балун знает про способ оплаты** (COD не принимается → кнопка выбора
заблокирована с объяснением).

Копировать как есть **нельзя**: эталон тянет точки из своего AJAX-слоя, а наш провайдер получает
`dataSource` в `init()`.

## Уроки s44 (применить)

- **Проверять вывод «это ограничение инструмента» перед тем, как принимать его.** s42 списала
  несработавший сабмит заказа на харнесс и оставила самый рискованный путь непроверенным; это оказался
  конкретный MCP-драйвер. То же самое случилось с «Почте нужен iframe».
- **Критика Codex перепроверять по коду.** В s44 из 6 находок одна была неверна по механике (но привела
  к настоящему багу рядом), две недостижимы. И **re-critic на свои же фиксы** — поймал незакрытый край.
- **Интеграционные тесты, написанные «под CI», обычно не работают.** Один неверный `dirname(__DIR__, N)`
  роняет весь сьют ещё на сборке, до запуска тестов.
- **Живая проверка ловит то, что не ловят ни тесты, ни критик** — s44 нашла языковую несогласованность
  только на отрендеренной странице.
- Codex inline-bundle ≤ ~12KB (15KB не влез, 8-11KB стабильно).
- `git commit -m` с бэктиками/скобками ломает bash-парсинг — писать в файл + `git commit -F`.
