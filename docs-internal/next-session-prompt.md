# 🚧 Что осталось в работе — одна ветка

**`fix/395-mask-license-key-in-logs` — ключ лицензии в debug-логе.** Самая тяжёлая карточка ночи:
**три круга воркера и три прохода критика, все три — REJECT**, и каждый по делу.

1. Первый круг сделал редактирование **opt-in** — всё, что не реализовало хук, логировало секрет по
   умолчанию, а фильтр URI отрабатывал ПОСЛЕ маскирования.
2. Второй матчил только литеральное `name=`, поэтому `token%5Bprimary%5D=` (ровно то, что выдаёт
   `http_build_query()`), `licenseKey` и `apiKey` проходили насквозь, а тела запросов не
   редактировались вообще, хотя докблок обещал обратное.
3. Третий переписал матчер на канонизацию имён, но читает только ПЕРВЫЙ сегмент скобок, поэтому
   `a[token]=SECRET` (секрет под несекретным именем) по-прежнему течёт. И тот же regex теперь
   портит валидный JSON, в тексте которого встречается `token=`.

4. Четвёртый круг перешёл на парсинг (`parse_str()` + рекурсивный обход + `http_build_query()`
   для query, `json_decode()` для JSON) и закрыл всё это — но осознанно НЕ стал маскировать
   нераспознанные форматы целиком, сославшись на зелёные тесты. **Четвёртый критик опроверг это
   вызовом:** метод с телом в форме `print_r` вернул `super-secret-token-value` дословно.
5. Пятый круг добавил `UNPARSEABLE_BODY_MASK`. **Пятый критик — снова REJECT, снова вызовом:**
   `is_form_encoded_body()` доверяет произвольным байтам значения, поэтому URL-подобная строка с
   `token=SECRET` и свободный текст с переводом строки проходят проверку и парсятся с секретом
   внутри; и валидный скалярный JSON, который САМ является секретом, возвращается без изменений.

**Шестой круг запущен** с обеими находками и указанием проверять вызовом, а не чтением.
**PR #433 открыт, CI зелёный, но мержить его нельзя** — вердикт и обе находки в комментарии к PR.
Ключевой вопрос, который может потребовать твоего решения: тип формы **нельзя** выводить из
синтаксиса тела, значит либо маскировать любое недоверенное не-JSON тело целиком (и терять в логе
безопасные соседние поля), либо опираться на объявленный content-type запроса.

# ⚠️ Ловушки из прошлых сессий, всё ещё в силе

1. `ReflectionProperty::setValue()` — guard `setAccessible()` по версии PHP.
2. WooCommerce определяет страну свежего гостя ГЕОЛОКАЦИЕЙ с фолбэком `US`.
3. `Woodev_Setting::get_value()` кэширует — хендлер строить ПОСЛЕ подмены `get_option`.
4. JS-тесты ИЗ BASH, никогда `npx jest`.
5. `billing_city` на риге — select2 старого демо §8, источник ничего не отдаёт.
6. Бэктики в `--body "$(cat <<'EOF' …)"` съедает bash — тело писать через `--body-file`.
7. Закрывающие ключевые слова GitHub исполняются из ТЕЛА коммита буквально; гейт `.githooks` включён.
8. Кросс-хендлерный `show_if` работает и на сервере, но зажимать значение надо ПРИ ЧТЕНИИ.
9. `docker exec … wp eval-file` требует `MSYS_NO_PATHCONV=1`.
10. Читать чужую ревизию: `git show <ref>:<path>`, `git ls-files --eol`. `git checkout --` и
    `git add -A` при живом воркере — как терять чужую работу.
11. **`@since` — ПЛАНИРУЕМЫЙ релиз (`2.0.2`)**, не `VERSION` и не инкремент на коммит. Двое воркеров
    за ночь уехали в `2.0.3`, обоих поймали критики.
12. **Serena переводит файл в CRLF** при `replace_symbol_body` / `insert_before_symbol`. Смотри
    `git diff --stat` перед `git add`.
