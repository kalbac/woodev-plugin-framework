# Что доказано замером

1. **Базовые линии не зависят от платформы** — на Маке те же, что на десктопе (таблица в шапке);
   единственное расхождение — **e2e 7 тестов за 15.7 с** против ~2.5 мин.
2. **Экспорт→импорт рига работает МЕЖДУ машинами** — 301 заказ, `/` → 200, `/wp-admin/` → 302.
3. **`grep -q` под `set -o pipefail` — ГОНКА:** шесть одинаковых проб дали `255 255 0 0 0 0`.
4. **`npx wp-env` — заглушка на npm**, выходит с нулём и ничего не запускает; надо
   `npx @wordpress/env`. CI пишет голую форму и зелёная — не трогал.
5. **`sharedDirectories` на macOS СИМЛИНКУЮТСЯ**, вопреки `orca.yaml`: хук `pre-push` тут же
   пересобрал в ворктри пять посторонних бандлов.
6. **Метабокс на риге виден в обоих состояниях**, данные совпадают с метой заказа дословно.
7. **Codex и Sonnet под Orca на macOS стартуют ОДНОЙ командой** — рецепта из четырёх шагов не надо.

# Ловушки

1. **`orca` на PATH сломан** (root-овый симлинк `lrwx------`) — зови
   `/Applications/Orca.app/Contents/Resources/bin/orca`. ⚠ Воркер этого не знает: клади полный путь
   в бриф, если ему самому звать `orca`.
2. **`worker-start --worktree new-child` требует `--name`**, иначе `invalid_argument`.
3. **`node_modules` в ворктри — UNTRACKED** (`/node_modules/` матчит каталог, а не симлинк):
   `git add -A` закоммитил бы симлинк с абсолютным путём.
4. **Воркер не прогонит каталожные гейты** — они ходят в риг за wp-cli. Новые msgid дописывает в
   `.pot` И `.po` координатор, иначе `lint:i18n-sources` красный (в s136 — пять msgid метабокса).
5. **Спека оператора на #856 лежит ДВУМЯ КОММЕНТАРИЯМИ**, а тело карточки описывает старое
   состояние. Читать с `--comments`. То же и у других старых карточек.
6. **Диалог Codex «Approaching rate limits» прилетает В СЕРЕДИНЕ прогона** и роняет `worker_done` в
   `dispatch_capability_invalid`; `terminal send` его не гасит, но отчёт ЦЕЛ под `Original body:`.
