# Ловушки — новое в s93

1. **Засевать настоящие `<option>` в ajax-режиме НЕДОСТАТОЧНО.** Так написано и в карточке #530, и
   в моём брифе — и это неверно. `related-list` рисует DOM-опции потому, что он ЛОКАЛЬНЫЙ select2;
   ajax-стратегия использует свой data-adapter, DOM-опции для отрисовки игнорирует и держит
   `minimumInputLength`. Решение в #535: скоупить порог до 0 для уровня с популярным списком и
   отвечать на пустой запрос ЛОКАЛЬНО, без сети.
2. **Список-подсказка не должен приезжать ВЫБРАННЫМ.** Браузерный алгоритм reset-selectedness сам
   выбирает первый `<option>`, если ни один не помечен; пустой option, вставленный ПОСЛЕ, уже не
   отыграет. Вставлять пустой первым и явно ставить ему `.selected`.
3. **`terminal wait --for tui-idle` у Codex возвращает `satisfied: true`, когда диалог обновления
   ещё на экране.** Готча утверждала обратное. Единственный надёжный гейт — прочитать экран и
   грепнуть. Enter в этом диалоге означает «Update now» и теряет вложенный бриф.
4. **Провалившийся `worker-start` метит задачу `failed`, а не `blocked`** — восстановление то же
   (`task-update --status ready`), но искать надо другой статус.
5. **`worker-release` вернул `release_unknown` и всё равно закрыл терминал.** Считать, что воркер
   после этого мёртв; для следующего круга поднимать новый на том же ворктри.
6. **На риге `woodev_location_allow_custom_settlement` = `yes`.** Пока она включена, tag-строка #528
   занимает слот нулевого результата, и строку «ничего не найдено» не увидеть вообще. Мерять пустое
   состояние только при `no`, потом вернуть `yes`.
