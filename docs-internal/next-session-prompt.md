# Что доказано замером

Скрипты переигрываются: `research/2026-09-26-928-form-measurement/` (с разделом независимой проверки).

1. **Стена — маркерная область, а не отрицание.** OR из `EXISTS` по N ключам даёт N джойнов без
   предиката по ключу: 4 джойна 5 678 мс, 2 — 110 мс, 1 с ключом в `ON` — 10,7 мс (10 тыс. заказов,
   6,8 строк меты на заказ; 51× ≈ 6,8²). Страница без фильтра при 4 перевозчиках — 11,7 с / 10 тыс.
2. **Запрос id ≡ старой форме.** Временная MariaDB: 112/112 случаев «SQL = обход дерева»; риг (HPOS, 294
   заказа, 2 перевозчика): 19 запросов, итоги `main` и ветки совпали до единицы; `unknown` 113 → 5,6 мс.
3. **Пустой `post__in` пропускает ВСЁ на обоих хранилищах** (`OrdersTableQuery.php:27`, `:1443-1445`;
   `class-wp-query.php:2248`) — поэтому пустой список маппится в сентинел.

# Ловушки

1. **Pre-push хук отказывает КАЖДОМУ пушу воркера с PHP-правкой** — бандлы в ворктри не воспроизводятся.
   Воркер коммитит и останавливается; пушит координатор из основного чекаута:
   `git push origin <sha>:refs/heads/<ветка>`. `--no-verify` запрещать по имени. Готча
   `local-npm-run-build-is-not-assets-parity-evidence`, раздел s140.
2. **Хартбиты Orca будят координатора на каждое сообщение**, а типизированный ожидатель их не видит.
   Фоновый цикл без `--types`, который ack'ает пачки из одних хартбитов, — в
   [wiki/orchestrating-agents-with-orca.md](wiki/orchestrating-agents-with-orca.md), раздел s140.
3. **OR из `EXISTS` по нескольким мета-ключам — никогда.** Готча
   `an-or-of-exists-meta-clauses-joins-the-meta-table-once-per-key-unpredicated`.
4. **В брифе всегда `--testsuite=Unit`**, полный путь до `orca` в `Orca.app/Contents/Resources/bin/`,
   запрет интеграционной сьюты.
