# ⚠️ Прочитать до первой JS-команды

**Запускать JS-тесты только через `npm run test:js`. Никогда `npx jest`.**

В репозитории нет собственного jest-конфига вообще — им владеет `wp-scripts test-unit-js`, и
именно он даёт jsdom. `npx jest` откатывается на node-окружение и печатает **194 упавших из 472**
на дереве, где на самом деле **631 из 631**. Подсказка — упавший ИТОГ: сюиты, не сумевшие
загрузиться, не отдают свои тесты вовсе.

Опасно это тем, что сигнал ложный, но правдоподобный: он называет твои же файлы и показывает
похожие на настоящие диффы. В s52 это поймали только потому, что сессия была чисто PHP-шная и
внезапные 194 падения в JS были невозможны физически. Флаги jest прокидываются после `--`:
`npm run test:js -- tests/js/x.test.js -t "имя"`. Готча `npx-jest-bypasses-wp-scripts-jsdom`.

флаг падает в дефолт. С `||` явный `false` молча превратится в `true` — это ровно тот баг, что
чинили в s40.

# Чему научила s52 — читать до правок плана

**План был неправ четыре раза, и каждый раз это ловилось до кода. Не считай его истиной.**

1. **`require_once` в `includes()`** — план назвал это критичным. По факту из SP-5-дерева там не
   требуется ничего: `Constraint_Checker`, `Pickup_Handler`, `Point_Query` резолвятся рантайм-
   автолоадером по class-map. Поймал исполнитель, проверено, откачено.
2. **Способ доставки из `WC()->session` в контроллере** — контроллер намеренно не читает ни одного
   глобала WooCommerce, на этом держится его тестируемость. Стал пятым инжектируемым колбэком.
3. **`Woodev_API_Exception` ронял бы фаталом** запрос, которого ждёт покупатель. Оба соседних
   обработчика его переводят в 502, новый не переводил. Поймал исполнитель.
4. **`npx jest`** — см. выше. Самая дорогая из четырёх.

Плюс исполнители нашли то, чего в плане не было: **нормализация `:instance_id`** (в s44 ровно
рассогласование точек входа по этому суффиксу было настоящим багом) и **отсутствие rate-limit** на
единственном маршруте, который пишет и ходит к перевозчику.

**Вывод для следующей сессии:** явно проси исполнителя возражать. Формулировка, которая сработала
четыре раза: «если что-то в инструкции противоречит тому, что ты видишь в коде, скажи об этом, а не
следуй молча — предыдущие исполнители ловили настоящие ошибки в моих инструкциях, и это было самым
ценным, что они сделали».
