# Что доказано замером

1. **Критик — kilo, и Orca его НЕ супервизирует.** `dispatch --inject` набирает бриф, kilo его
   получает и работает, а Orca объявляет `agent_prompt_stalled`, закрывает диспатч и **отзывает
   capability** — `worker_done` прилетает обратно отказом. **Оператор проверил это через UI Orca**
   (путь, недоступный агенту): поведение идентично `worker-start --agent kilo`, значит дело НЕ в
   способе запуска. Отброшено замером, а не рассуждением: `--timeout-ms 240000`, ожидание
   `tui-idle`, свежий терминал, kilo 7.5.5, `autoupdate: false`, повторный инжект.
   **Рабочий рецепт — диспатч БЕЗ `--inject`**, целиком в
   `wiki/orchestrating-agents-with-orca.md`. Не искать «правильное заклинание запуска».
2. **Модель называть С ПРОВАЙДЕРОМ.** `kilo/openai/gpt-5.6-sol-discounted` работает,
   `openai/gpt-5.6-luna` отвечает `token is expired` — это ДВА РАЗНЫХ маршрута к одной модели, и
   kilo без явного указания берёт последний использованный. Указание оператора: предпочитать
   модели со скидкой, `kilo models | grep -i discount`.
3. **`git push` здесь виснет молча.** Git Credential Manager ждёт GUI-диалог, которого агент не
   видит; `fetch` при этом работает и прячет проблему. Рабочая форма:
   `GIT_TERMINAL_PROMPT=0 git -c credential.helper='!gh auth git-credential' push`. И никогда не
   заворачивать push в `| tail` — `$?` станет кодом `tail`, и упавший push прочитается как `exit=0`.
4. **`@since` = `2.0.2` и остаётся им** (решение оператора, #546). Всё, что было выше, приведено
   вниз в #555. `2.0.0` (219 шт.) и `2.0.1` (1 шт.) — историческая разметка v2, НЕ трогать без
   отдельного решения.
5. **Бюджет стартового чтения 176 KB — это РЕШЕНИЕ ОПЕРАТОРА, а не выведенный предел.** Доля 25 %
   и 3,5 байта на токен — допущения, токенайзер не запускался. Так и записано в
   `scripts/lint-docs.mjs` и `DOCS-SCHEMA.md`. Не цитировать как доказанный порог.

# Ловушки

1. **`pull_request`-воркфлоу может просто не запуститься на живом CLEAN PR** — видно только
   `PR Triage`. Три раза за s97. Лечится close/reopen. **Считать джобы, а не смотреть на цвет:**
   19 у кодового PR, 20 если затронут `.md`. Готча
   `a-pull-request-workflow-can-simply-not-fire`.
2. **`terminal create --command "bash"` на Windows уводит в WSL** (`bash` = `System32\bash.exe`),
   и последующее `fatal: not a git repository` читается как «Orca работает в WSL» — это ложь,
   дефолтный терминал Orca это PowerShell. Готча
   `orca-terminal-command-bash-lands-in-wsl-on-windows`.
3. **Ветка PR может быть отрезана ДО половины работы, а `mergeable=CLEAN` этого не скажет.** Перед
   риг-проходом: `git log --oneline HEAD..origin/main`, и если не пусто — ребейз ПЕРЕД тем, как
   звать оператора.
4. **Проверять отдаваемое ригом надо В КОНТЕЙНЕРЕ, а не на диске.** Путь внутри —
   `/var/www/html/wp-content/plugins/woodev-test-shipping-method/…`, структура НЕ повторяет репо.
5. **`HTTPError: 429` на `npx wp-env start` — инфраструктура, не код.** Контроль: другие
   интеграционные джобы на ТОМ ЖЕ коммите. Но лог прочитать — s87 принял настоящий провал за флак.
6. **`orca worktree rm` отказывается удалять ворктри из-за CRLF-грязи, с которой она и рождается.**
   Нужен `--force`, но **список путей в ошибке читать обязательно**: проверь
   `git -C <wt> diff --ignore-all-space --stat` — если пусто, это EOL и только EOL.
7. **`composer check` и jest — не одно и то же дерево.** `rm -f .phpunit.result.cache` перед каждым
   замером; jest только из bash с `--roots`, никогда `npx jest`.
