# 🎯 Главное: бери #334 и #330 ОДНИМ блоком — решение оператора уже принято

Обе карточки — один корень. Оператор дал по нему решение, замер под него сделан, развилок не осталось. Это самая весомая работа на входе.

## Корень

`Provider_Selection_Scope::current_locality()` (`woodev/shipping-method/pickup/class-provider-selection-scope.php:146`, код фреймворка, объявлен `final`) отдаёт ключ ТЕКУЩЕЙ записи покупателя — какого бы уровня та ни была:

```php
final public function current_locality(): string {
    $current = $this->location_service->get_customer_record();
    return null !== $current ? $current['record']->key() : '';
}
```

А `/location/select` шлётся на КАЖДЫЙ уровень цепочки, включая адрес (`location-cascade.js`, `onSelectFor`). Значит стоит покупателю выбрать адрес — «где я нахожусь» меняется, и всё, что ключевалось населённым пунктом, отваливается:

- **#334** — выбранный ПВЗ становится недостижим (кнопка возвращается в «Выберите ПВЗ», текст адреса пункта исчезает);
- **#330** — поиск адреса теряет скоуп и молча уходит по всей России.

## Решение оператора (записано в #334)

> Для ПВЗ левел должен всегда оставаться на уровне settlement/city, смена адреса (внутри НП) никак не должна влиять на выбранную точку.

## Замер, который делает это дешёвым

Главный аргумент против («`Location_Record` не несёт ключей предков») **опровергнут замером на риге**:

```
адресная запись:      key          = dadata:6f91f7e9-bd59-4bb2-9b8f-8b963dc01576
её raw:               city_fias_id = 0c5b2444-70a0-4932-980c-b4dc0d3f02b5
выбор ПВЗ лежит под:                 dadata:0c5b2444-70a0-4932-980c-b4dc0d3f02b5
```

`city_fias_id` адресной подсказки — байт в байт нативный id записи НП. **Вывод точный, сопоставлять названия не нужно**, значит готча `a-locality-display-name-is-not-an-identifier` этой правке не мешает. И правило «адрес внутри НП не влияет» выполняется само: адрес в ДРУГОМ городе даст другой `city_fias_id`, локальность честно сменится.

## Что решить при реализации (всё записано в карточках)

1. **Фреймворк не должен лазить в `raw`** — это словарь провайдера. Ancestor-идентичность выкладывает САМ провайдер: например опциональный `key` внутри компонента (`settlement: { name, type, key }`). Сегодня компоненты несут только `{name, type}` — замерено.
2. **У DaData два поля.** В замере заполнен `city_fias_id`, а `settlement_fias_id` пуст — она различает город и НП, для села будет наоборот. Маппинг обязан покрыть оба, иначе для сёл баг останется.
3. **Вне РФ идентичность другой природы** (`relation:`/`way:`/GeoNames, `fias_level` всегда `-1`). Решить деградацию при отсутствии ancestor-ключа. Молча падать на ключ текущей записи нельзя — это и есть нынешний баг.
4. **Обе половины #330 независимы.** Даже с починенным клиентом сервер отвергнет корректный `within=<ключ НП>`, пока текущая запись адресного уровня (`build_scope()` сравнивает с ТОЧНЫМ текущим ключом) — измерено отдельно. Чинить обе.

# ⚠️ Ловушки, купленные этой сессией дорого

1. **Не зови оператора на риг, не проверив сам.** Позвал дважды; во второй раз он ответил: «ты тесты гоняешь, они тебе показывают одно, а по факту другое». Правило уже лежало в локальной памяти (`feedback_self_e2e_verify_before_merge`) и было нарушено. Проверять реальным HTTP со своей кукой или пробником — образцы в логе s73.
2. **Мутация, про которую не проверено, что она ПРИМЕНИЛАСЬ, не доказывает ничего.** Три случая за сессию, три разных слоя экранирования; дважды зелёный сьют читался как «строка не закреплена». Готча `a-mutation-you-did-not-confirm-applied-proves-nothing`.
3. **Интеграционный сьют ВСЕГДА имеет `WC()->session`, даже у гостя** — под PHPUnit `$_SERVER['REQUEST_URI']` не REST-адрес. Гостевой `/select`-тест был зелёным с самого написания, пока живой запрос отвечал `persisted: false`. Ловится только воспроизведением КОНТЕКСТА (`WC()->session = null` перед dispatch). Готча `the-integration-suite-has-a-wc-session-a-rest-request-does-not`.
4. **Шов, описанный через вызывающих, скрывает того, кого не хватает.** `bridge_wc_session()` был подключён ко всем маршрутам, которые ЧИТАЮТ запись, и не подключён к единственному, который ПИШЕТ. Докблок перечислял тех, что были, — и читался как полный список. Шестой случай `built-on-both-sides`, третья форма.
5. **Цитата может быть настоящей и при этом подпирать неверное утверждение.** Сослался на `class-woocommerce.php:315` как на гейт сессии: строка реальна, код процитирован верно, но это гейт `WC_Site_Tracking`. Настоящий — `:891`, `is_request('frontend')`, исключает ВСЕ REST-запросы. Днём раньше в готче была прямо выдуманная строка. Проверять не «есть ли такая строка», а «что она охраняет».
6. **`npm run test:js -- --roots …` под PowerShell теряет сам флаг** — гонять JS-тесты из bash. Готча `powershell-drops-the-roots-flag-from-the-jest-command`.
7. **`git add -A` подметает чужие временные файлы** — в коммит уехал `probe-324.php` от параллельного диагностического агента.
8. Прежние в силе: поднятие `VERSION` на `main` публикует релиз (#285), `rig-serves-the-working-tree-branch-switch-reverts-fixes`, `phpunit-defects-cache-hides-cross-test-session-leaks`, Codex по-прежнему не запускается (лечится `winget install --id Microsoft.PowerShell` из-под администратора).
