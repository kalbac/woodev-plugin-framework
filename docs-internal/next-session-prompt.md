# Что доказано замером

Подробности — `sessions/s129.md`; у каждого пункта своя готча или карточка.

1. **Каждое отрицание проверено как ДОПОЛНЕНИЕ на риге** (HPOS, 2 перевозчика): `has_pickup_point`,
   `has_tracking`, `delivery_status` в четырёх состояниях, `status`, `is_exported` — **каждая пара
   даёт полный набор**. Форма дефекта, дважды доехавшая до тебя, измерена отсутствующей.
2. **`is_exported` измерен с подсадкой и уборкой**, риг оставлен байт в байт.
3. **Канонический `pending` недостижим ПО КОДУ** — ни один `status_map` в него не отображает.
   Это был дефект 4 карточки #837, закрыт мержем #847.
4. **«Выгружен» = `carrier_order_id`**; `Orders_Provider` его не объявлял — общая дырка под
   #841 И #834.
5. **#838 воспроизводится только по SPA-маршруту** — роутер дописывает `period` в адрес.
6. **#842:** метод-сирота не встречается в дереве вообще; неполный `get_method_ids()` **портит
   колонку типа, а не выкидывает строки**.
7. **`AdvancedFilters` рисует селект правила только там, где заголовок просит `{{rule /}}`**, но
   ключ адреса И чтение фильтра ОБРАТНО берутся из `rules`. Поэтому «просто убрать правило»
   ломает возврат по ссылке, а верный ответ — убрать токен. Готча заведена.
8. **У WooCommerce нет ни одного фильтра с ОДНИМ правилом** — перебраны все восемь в их
   «Аналитике» на риге.

# Ловушки

Только новое за s129; прежнее — по тегам в `GOTCHAS.md`.

1. **Два параллельных интеграционных прогона делят ОДНУ тестовую базу** — проигравший рапортует
   это ТВОИМИ падениями. Ворктри не изолирует: приватен код, а не база.

   пяти это не гейт; CI упал ровно на этом.
3. **`wc-admin` дописывает параметры даты, которых нет в `href`** — мерить кликом, не `goto`.
4. **Fable 5.1 упирается в лимит СЕССИИ, Codex — в лимит АККАУНТА.** Критиком работал Sonnet;
   упавший диспетч Orca помечает `failed` сама, замена через `worker-start --retry-of`.
5. **`.pot`/`.po` здесь CRLF**, а бэктики в `git commit -m` исполняются шеллом — сообщение писать
   файлом через `-F`.
