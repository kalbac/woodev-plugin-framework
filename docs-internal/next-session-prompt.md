# Что доказано замером

Полностью — в `sessions/s128.md`. Шесть фактов, нужных сразу:

1. **`addHistoryListener` шлёт событие ДО смены адреса**, поэтому `getQuery()` внутри слушателя
   читает ПРЕДЫДУЩИЙ URL: адрес меняется, таблица нет. Поднимать флаг, читать запрос отдельным
   эффектом. **Найдено только живым ригом.** Готча `addhistorylistener-fires-before-the-url-changes`.
2. **Опция фильтра у WooCommerce — `{ value, label }`, не `{ key, label }`:** ошибка формы делает
   «Filter» **disabled**, а выбранный пункт шлёт ЛЕЙБЛ.
3. **WooCommerce ХАРДКОДИТ имя параметра `filter`** и задаёт `FilterPicker` ФИКСИРОВАННЫЕ 430px.
   ⚠ Всё, что ДОБАВИТ контрол в ряд фильтров (#841 — следующий), обязано перемерить высоту ряда.
4. **«Совпадать ни с чем» — ровно ОДИН верный механизм:** `Orders_Query::NO_MATCH_META_QUERY`.
   Пустой массив статусов HPOS разворачивает во ВСЕ валидные, выдуманный слаг бездействует на CPT.
5. **Агрегат с ОДНИМ источником — не малое N, а другая форма**; скрыл два дефекта подряд (s127
   `has_tracking`, s128 `delivery_status=unknown`). Тест на агрегат — минимум два перевозчика.
6. **Замеры на риге (HPOS, 2 перевозчика, 71 заказ):** `delivery_status=unknown` 71 → **9**,
   мусорный `status` 71 → **0**; контроли `in_transit` 19 и `has_tracking=false` 24 не менялись.
