# Что доказано замером

1. **Диагноз s107 по Codex опровергнут контрольным запуском (31.08.2026).** Нативный
   `worker-start --agent codex`, одна команда: `state: ready`, `orca status --json` из воркера
   отработал, tool-шелл — **PowerShell 7.6.5**, `git rev-parse --show-toplevel` работает **без
   правки `.git`**. Обрезание брифа было ТОЛЬКО на устаревшем Codex 0.150.1 с апдейт-диалогом.
   ⚠ Обновление изменило и диалог, и версию сразу — замером их не разделить.
2. **Канарейка последней строкой брифа обязательна.** Четыре запуска за s108, каждая процитирована.
3. **Флаг `truncated` не читает ни одна строка JS** (сплошной поиск по `src/` и
   `woodev/**/assets/js/`) — #411 умер сам собой. **`/location/list` зовёт только режим
   «Предустановленный список»** (`location-select-modes.js:30`), поэтому снятие `LIST_HARD_CAP`
   безопасно ровно после ухода этого режима с оси НП.
4. **`is_numeric()` — не проверка целого.** `is_numeric('0.5')` → true, `(int) '0.5'` → 0; в #686 это
   удаляло куку, которую велено хранить до 2031. Готча `php-stdlib-traps-that-survive-tests`, №4.

# Ловушки

1. **Рабочий каталог Bash-инструмента ЖИВЁТ между вызовами.** Один `cd "$WORKTREE" && <гейт>`
   уводит туда все последующие, и правка по ОТНОСИТЕЛЬНОМУ пути ляжет в ворктри, а
   `orca worktree rm` унесёт её. В s108 так пропала готовая правка готчи. Правки — **по абсолютному
   пути**; проверка: `git status` в ОСНОВНОМ чекауте не показывает файл, который точно правил.
   Готча `serena-activate-path-must-be-the-worker-s-worktree`.
2. **`orca orchestration check --wait --json` отдаёт ПОТОК склеенных JSON-объектов, а не один.**
   `json.load()` падает с «Extra data». Разборщик лежит в скратчпаде сессии; проще декодировать
   `raw_decode` в цикле.
3. **`register_control()` — единственный признак, что настройка рисуется.** Ни `'name'`, ни
   членство в `get_owned_setting_ids()` этого не значат (оно пропускает четыре рисующиеся опции).
   Готча `a-registered-setting-without-a-control-never-renders`.
4. **Хук `commit-msg` ловит закрывающее слово GitHub в СЕРЕДИНЕ предложения** — «PR #688 resolved
   #686» отвергается. Писать «PR #688 landed #686» либо `Closes #N` отдельной строкой.
5. **Три круга на карточку — потолок, и в s108 он сработал.** Четвёртый проход критика вернул одну
   LOW-находку: отклонена по существу и заведена карточкой (#689), а не превращена в пятый круг.
