# С чего начать

## 1. #207 — в табах «Пункт выдачи заказов N» вместо «ПВЗ N»

**Механизм исправен, не чини его.** Подпись таба берётся как `point_short_name || type.label`
(это #199, смерджено). Живой источник Яндекса просто **не задаёт** `point_short_name`, а его
`TYPE_MAP` даёт длинную подпись:

```php
'label' => 'Пункт выдачи заказов',   // pickup_point
'label' => 'Постамат',               // terminal
```

Правка на одну строку в
`tests/_fixtures/woodev-test-shipping-method/class-test-live-yandex-point-source.php`:
задать `point_short_name` = `ПВЗ` / `Постамат`. Это доменные данные — ровно то, ради чего поле
и заводилось: **фреймворк нумерует, домен называет**.

Проверять на совмещённых точках одного типа — на живых данных Яндекса их хватает.

## 2. #208 — проверить каскад цвета на ЖЁЛТОМ

Каскад `accent → fill → contrast` (#203) на риге проверен только на бирюзовом, где сработала
ветка «затемнить заливку, текст белый». **Вторая ветка правила — «цвет светлый, текст чёрный» —
на риге не проверялась ни разу**, только юнит-тестами.

Яндекс даёт идеальный случай: брендовый цвет жёлтый, а тестируем мы сейчас именно на Яндексе.
Задать акцентом жёлтый и замерить, что:

1. заливка **НЕ** затемняется (жёлтому для белого нужно −50%, порог 30% это отсекает);
2. контраст переворачивается в **чёрный**;
3. на кнопке и бейдже проходит 4.5:1 (на `#ffeb3b` чёрный даёт 17.20:1);
4. маркеры, обводки и фокус остаются чистым жёлтым.

**Наблюдение оператора, которое стоит проверить заодно:** на бирюзовом обводка кластеров
осталась бирюзовой, а кнопки сайдбара стали заметно синее. Это ожидаемое следствие расщепления
«идентичность / заливка», не дефект — но посмотреть глазами, не читаются ли два оттенка как
рассогласование. На жёлтом вопрос снимется сам: заливка не изменится и оба оттенка совпадут.

# Чему научила сессия

**Право исполнителя противоречить заданию окупилось четвёртую сессию подряд** — и поймало, что
целого пункта очереди не существует: шов 2GIS в PHP был готов с #149, хэндофф ошибался.
Примечательно, что в s52/s53 ошибался мой ПЛАН, а здесь — проектный ДОКУМЕНТ. Доки не
безопаснее плана, они стареют.

**Утечка токена — из-за моей формулировки ТЗ.** «Не коммить как будто это наш секрет» —
предложение, которое разрешает коммитить. Безусловная форма единственно безопасная. Severity
утечки требует ДВУХ фактов: игнорируется ли каталог-источник И публичен ли репозиторий. И
удаление ветки объект не убирает — коммит оставался доступен по SHA. Готча
`public-repo-third-party-credentials`.

**Три раза первый замер выглядел как дефект и им не был:** глиф 0×0 (мерил при закрытом
сайдбаре), «постамат не получил глиф» (в выборку попали одни ПВЗ), 2 падения jest (чужое
воркдерево). Каждый раз спасала перепроверка гипотезы ДО отчёта.

**Оператор поправил по хукам:** YAGNI не аргумент против фильтров и экшенов во фреймворке.
Правило s32 было про доменные ВОЗМОЖНОСТИ. Хук стоит одну строку, его отсутствие — слом API у
отгруженных плагинов.

**Пороги надо обосновывать, а не подбирать.** Порог затемнения 30% проверен перебором 140 608
цветов: случаев, где ни белый (в пределах порога), ни чёрный не дают 4.5:1, — ноль.

**Одинаковый синтаксис — не одинаковое решение.** По `??` против `||` исполнители трижды пришли
к РАЗНЫМ выводам для разных типов данных (булев флаг, URL, отображаемая строка) и каждый раз
обосновали в докблоке, вместо копирования прецедента.
