**Правила работы с ним** (готча `codex-shell-sandbox-broken-windows`, память
`feedback_codex_is_a_second_worker_not_just_a_critic`):

- он **второй воркер**, не только критик — оператор оплачивает Pro и просит загружать;
- **никто не принимает свою работу**: код Claude → критик Codex, код Codex → критик я;
- промпты **на английском** (он subagent), вердикт просить **в файл** — TUI перерисовывается и
  читается плохо;
- `terminal wait --for tui-idle` **врёт**: он считает диалог простоем. Проверять поле `satisfied`
  и читать буфер перед отправкой `--enter`, иначе промпт ответит на диалог обновления (уже
  случилось — Codex обновился до 0.148.0 сам).

# ⚠️ Исправленное заблуждение: дерево LF, а не CRLF

Прошлый хендофф (и три моих брифа) утверждали «perl молча не мутирует CRLF-дерево». **Дерево LF** —
`.gitattributes` ставит `eol=lf`, `git ls-files --eol` показывает `w/lf`. Файл становится CRLF
только после того, как его тронула Serena (`replace_content` переворачивает весь файл). Поэтому
`warning: CRLF will be replaced by LF` — не шум, а **указание, какие файлы Serena перевернула**;
снимать `sed -i 's/\r$//'`.
