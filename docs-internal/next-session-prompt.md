# Что доказано замером

Полностью — в `sessions/s127.md`. Шесть фактов, нужных сразу:

1. **На риге теперь ДВА перевозчика**, проверено настоящим REST-маршрутом страницы:
   `providers=2`, `total=8` (5 + 3), образец `canonical=unknown / raw=Утерян при перевозке`. До #830
   провайдер был один, и половина решений SP-10 в браузере не воспроизводилась.
2. **`wc-settings` НЕЛЬЗЯ объявлять зависимостью скрипта** — он регистрируется условно, а
   неизвестная зависимость заставляет WordPress выбросить весь бандл МОЛЧА. Готча
   `declaring-wc-settings-as-a-script-dependency-silently-drops-the-bundle`.
3. **Палитра статусов WooCommerce — ПЯТЬ тонов, и это единственная, что она возит**;
   `@woocommerce/components` цветного статусного бейджа не отдаёт вовсе. Точные значения —
   комментарием на **#829**, оттуда же их берёт бриф волны 2.
4. **`npm run build` в основном чекауте даёт нулевой git diff** — то есть он воспроизводит
   закоммиченные бандлы точно, и это и есть доказательство паритета, которого ворктри дать не может.
5. **Каталог расширяют, а не пересобирают.** `wp i18n update-po` перестраивает `.po` из `.pot` и
   оставляет только то, что назвал `.pot`. Точечное добавление: 769 → **782**, переведённых **429**
   без изменений.
6. **Свободная RAM падала до 0.55 ГБ из 15.3 при ОДНОМ воркере плюс Docker**, и ОС убила фоновый
   `check --wait`. Потолок из s84 приезжает намного раньше трёх агентов.

# Ловушки

Только новое за s127; прежнее — по тегам в `GOTCHAS.md`.

1. **`git worktree remove` на Orca-ворктри ОПУСТОШАЕТ `node_modules` основного чекаута.** Падает
   через час словами `wp-scripts is not recognized`. Готча
   `git-worktree-remove-empties-the-primary-checkouts-node-modules`. **Удалять ворктри через Orca**;
   её отказ — информация (ворктри грязный на CRLF-файлах), а не препятствие.
2. **Run держит ОДИН активный `check --wait`**; второй возвращает `ok:false` без `result`, и это
   неотличимо от чистого таймаута. **Проверять `ok` прежде `result`.** Готча
   `one-check-wait-per-run-and-a-second-one-fails-invisibly`.
3. **`gh project item-list` может отдать имя поля искажённым** (`'��риоритет'` вместо «Приоритет»),
   и наивное чтение по ключу объявит ВСЕ карточки без приоритета. Матчить ключ по суффиксу.
   Настоящий ответ был: без приоритета — ноль.
4. **`gh pr view --json statusCheckRollup` смешивает завершённый прогон с начавшимся** — показывал
   пять упавших джоб при `pending: []`, пока текущий прогон был `in_progress`. Честный взгляд —
   `gh run list --branch`, ключом по SHA.
