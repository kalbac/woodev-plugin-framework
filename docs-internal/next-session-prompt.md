# Что доказано замером

1. **Astra против luna на одном брифе:** +36 п.п. session и +6 п.п. weekly против +4 и ~0, при
   3,68 млн токенов против 7,28 млн. Дороже ~в 9 раз за круг, ~15–20× за токен — и глубже.
2. **Дефолт стоял на astra**, то есть на дорогой модели шёл каждый запуск. Правило «когда брать
   astra» не изменило бы ничего — чинить надо было дефолт.
3. **`post-merge` срабатывает при `git pull --ff-only`** (песочница + настоящий мерж). Переключение
   веток без изменений в `woodev/**` — 47 мс против 2,2 с полного обновления.
4. **Все хуки лежали `100644`, а POSIX git такой хук игнорирует МОЛЧА.** `commit-msg` не работал на
   Linux с s81; на Windows `core.fileMode=false` это прячет.
5. **PCRE2 10.44 `\s` под `/u` ловит U+0085 и U+180E, ECMAScript `\s` — нет.** Любое сокращение
   (`\s`, `\p{Z}`, `trim()`) расходится между PHP и JS; набор выписан по кодовым точкам.
6. **Половины границы ПВЗ совпадают на 154 входах из 158.** Остаток — одиночные суррогаты UTF-16;
   ЗАПИСАНЫ предусловием, а не починены: корректный JSON их в PHP не принесёт.

# Ловушки

Только новое за s122; прежнее — по тегам в `GOTCHAS.md`.

1. **`orca account list` отдаёт лимиты из КЭША** — читанный сразу после прогона показывает состояние
   ДО него. Смотреть `updatedAt`; авторитет — ролл-аут самого Codex, и под Orca он лежит в её HOME,
   разбитый на ДВА файла на один запуск.
2. **Хук, закоммиченный `100644`, на POSIX не работает и не жалуется.** `git update-index --chmod=+x`,
   проверять `git ls-tree`, а не `ls -l`.
3. **CRLF-хук ломается под WSL** (`set: Illegal option -`), git-bash его терпит. `.gitattributes`
   теперь пинует `.githooks/**` на LF.
4. **Три открытые карточки без «Приоритета»** — #247 #285 #567, все релизные. Правило `AGENTS.md`
   требует поле у каждой открытой; расхождение НЕ исправлено, потому что очередь у них решает он.
5. **Утверждение «две половины эквивалентны» проверяется ЗАМЕРОМ по пространству входов, а не
   чтением.** Три круга критики подряд нашли, что оно неверно, каждый раз по новой причине.
