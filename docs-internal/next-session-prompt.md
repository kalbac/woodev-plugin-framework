# ⚠️ Ловушки, до первой команды

**1. Serena: «сервер поднялся» ≠ «работает».** Нужен ручной `activate_project('woodev_framework')`.
Проверяй **символьным вызовом** (`find_symbol Woodev_Plugin/get_file` → должен дать
`class-plugin.php:1040-1047`), а не наличием инструментов в списке. В s63 сработало с первого раза.

**2. НОВОЕ, стоило падения двух посторонних тестов: Serena вписывает CRLF в PHP-файлы, которые
репозиторий держит как LF.** Проявляется не конфликтом переводов строк, а падением тестов, которые
сверяют подстроки с литеральным `\n` в исходнике (`UpdaterKeylessPollingTest`,
`BoxPackerDispatcherWiringTest`). После каждой правки PHP через `replace_symbol_body` /
`replace_content` / `insert_after_symbol` нормализуй: `sed -i 's/\r$//' <файл>`. Готча:
`gotchas/serena-replace-content-eol-flip.md`.

**3. Риг отдаёт РАБОЧЕЕ ДЕРЕВО.** Прежде чем просить кого-то посмотреть — назови ветку И константы,
и убедись, что дерево на ней. Эта ловушка сработала в s62 на том, кто её же и записал.

**4. Город на риге надо задать руками, иначе пикер пуст** (кроме embedded-режима, где точки грузит
сам карьер). Порядок: `$('#billing_state').val('77').trigger('change')` → дождаться →
`$('#billing_city').val('Москва').trigger('change')`.

**5. wp-env — ТОЛЬКО из корня репозитория.** `MSYS_NO_PATHCONV=1` обязателен для путей внутри
контейнера. `wp config list` из корня — единственный честный способ узнать состояние рига.

**6. Достоверный jest только так:** `npm run test:js -- --roots "<rootDir>/tests/js"`. Никогда
`npx jest`. И `<rootDir>` в **PowerShell** ломается: `<` там оператор перенаправления — эту команду
запускай из Bash.

**7. Зелёная консоль — не доказательство.** У cross-origin фреймов ошибки в
`list_console_messages` не видны. Каждая проверка должна давать положительный артефакт
(скриншот, список запросов, возвращённое значение), а не отсутствие жалоб.

## 3. #259 — дешёвая правка с неочевидной ценой ошибки

В `map-provider-embedded.js` `init()` вешает слушатель `message` **после** `appendChild` фрейма.
Сейчас безопасно и только потому, что обе строки в одной синхронной задаче. После #251 у провайдера
появилось рукопожатие (`initAdapter` отвечает на сигнал готовности карьера), и **пропуск первого
сообщения означает уже не «поздний select», а мёртвый пикер** — замерено: без `postData` карта Почты
пустая навсегда. Симптом при поломке будет мерзкий: пустой фрейм без единой ошибки в консоли.
Правка: слушатель до `appendChild` + комментарий, что порядок несущий.

# Что сделано в s63 и почему это важно знать

**#251 — embedded-шов впервые заработал на живом карьере.** Развилку («адаптер поверх iframe» против
«script-режим») оператор делегировал словами «реши сам, но не догадками, а замерами». Решило ровно
одно измерение: **наша песочница виджет Почты не ломает** — а это был единственный аргумент за
script-режим. Полный разбор с числами → `docs-internal/specs/2026-08-10-embedded-map-provider-adapter-seam.md`.

**Что теперь умеет `Embedded_Map_Provider`:** два опциональных хука-адаптера от плагина, заданных
как точечные пути к глобалам (`initAdapter` — что послать ВНУТРЬ фрейма по сигналу готовности
карьера, `selectAdapter` — как перевести сообщение карьера в нашу точку). Оба вызываются **только
после** гейта `origin` + `event.source`, который остаётся во фреймворке. `lat`/`lng` в
`normalizePoint()` стали опциональными-но-валидируемыми, потому что реальный карьер их не шлёт;
`Pickup_Point::from_array()` НЕ тронут — REST-путь кормит нашу собственную карту, ей координаты
нужны по-настоящему.

**Как поднять embedded-режим на риге** (пригодится для #259 и вообще):
`wp config set WOODEV_TEST_PICKUP_EMBEDDED 1 --raw --type=constant`. Креды Почты уже лежат в
wp-config контейнера (`WOODEV_TEST_POCHTA_ACCOUNT_ID` / `_TYPE`, выданы оператором, в git их нет).
Снимается `wp config delete WOODEV_TEST_PICKUP_EMBEDDED`. Есть ещё
`WOODEV_TEST_PICKUP_SELECTION_CLOSE` / `_REFRESH_CHECKOUT` — ими достаётся путь «модалка остаётся
открытой после выбора», который раньше приходилось патчить прямо в браузере.

**Замеренные факты про виджет Почты, чтобы не перезамерять:** `https://widget.pochta.ru/map/`
отдаётся без `X-Frame-Options` и без CSP `frame-ancestors`; рукопожатие — фрейм шлёт
`{isMapLoad:true}`, родитель отвечает `{postData:{…}}`, фрейм отдаёт `{pvzData:{…}}`, оба конца в
`"*"` и без проверок origin; в `pvzData` **нет ни координат, ни имени** (совпало и с живым замером,
и с вендорскими доками); `pvzType` бывает только `russian_post` и `postamat`; виджет сам блокирует
свою кнопку «Забрать здесь» после выбора.

# Что нового знаем после s63

- **Постановку карточки надо проверять ДО запуска исполнителя, а не после.** Из четырёх взятых
  карточек **три** оказались с неверной премисой: #251 обещал фреймабельный URL (оказался шим вокруг
  iframe), #158 был уже отгружен посторонней работой три дня спустя после заведения, #244 описывал
  «не сделано» там, где стояло документированное CANCELLED с живыми причинами. Ноль потерянных
  прогонов — ровно потому, что каждая сверялась с кодом.
- **Безобидное расхождение становится боевым от соседней правки.** Hex-строку в координатах знали
  ещё с #201 и осознанно оставили как недостижимую — послабление `lat`/`lng` сделало её достижимой и
  поменяло режим отказа с «отвергнуть» на «тихо поставить точку в нулевой меридиан».
- **Отменённое решение стоит перепроверять построением, а не рассуждением.** Экстракцию #244
  собрали целиком — и она сама показала, что база растёт (1514 → 1520), то есть отмена 04.06 была
  права по причине, которую голым рассуждением было не увидеть.
- **Докблок может скрывать дыру убедительнее, чем её отсутствие.** Фикстура утверждала, что под
  embedded `Point_Source` «никогда не используется». Неправда: `fetch_details()` зовётся при
  подтверждении всегда, независимо от провайдера карты, — и из-за этой фразы два только что
  добавленных переключателя были мёртвыми, а первый прогон дал 404.
- **Отклонить находку критика — законно, если есть чем.** Low от Codex про `null`-координаты
  отклонён: `from_array()` проверяет наличие через `isset()` (для `null` → `false`), а живой payload
  Почты сам шлёт `"areaTo": null`. Спека была недоопределена, а не нарушена; решение записано в неё,
  а не оставлено в переписке.
