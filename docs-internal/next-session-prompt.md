   опция `woocommerce_edostavka_1_settings` записана и прочитана обратно, три id писем на месте, id

2. **Объём каркаса вдвое больше ручного обзора:** механический диф дал **13 фаталов и 8 абстрактных**

6. **На стенде пилота НЕТ учётных данных СДЭК:** `is_configured()` = нет, `deliverypoints` → **0**.

# Ловушки

1. **`register_shipping_methods()` — `final`, и молча выбрасывает** класс, не прошедший
   `is_subclass_of( $class, Shipping_Method::class )`. Метод, оставленный на `WC_Shipping_Method`,
   исчезает с чекаута без фатала и без строки в логе.
2. **`Shipping_Rate` бросает `InvalidArgumentException`** на пустом `label` и нестроковом `cost` — на
   пути расчёта доставки. Нормализовать НА ВЫЗЫВАЮЩЕЙ СТОРОНЕ, пока #766 не закрыта.
3. **Единицы веса расходятся:** `weight_max` СДЭК в килограммах, `max_weight` фреймворка — в граммах
   (`Constraint_Checker` делит на 1000 только для текста). Без перевода постамат на 30 кг отказывает
   корзине в 31 грамм, и точка просто показывается недоступной.
4. **У плагина НЕТ поля чекаута с выбранным ПВЗ.** `checkout_create_order()` берёт точку из
   собственного стора по паре «код города + тип» и пишет в мету заказа **сырой объект СДЭК**, из
   которого заполняет адрес, город и индекс. Мету `_wc_edostavka_chosen_delivery_point` придётся
   собирать из id точки через `fetch_details()`, сохранив форму байт в байт.
5. **`resolve_destination_location()` берёт код города СДЭК из того же стора**, а `Location_Record`
   его не несёт: без провайдера локаций CDEK замена стора роняет расчёт тарифа на поиск по имени
   города. Это и есть шаг **4b**.
6. **node-скрипт с обратными слешами инлайном в bash молча ничего не заменяет** — heredoc их съедает,
   скрипт рапортует успех. В s116 это дало ЛОЖНЫЙ замер, чуть не засчитанный. Только файлом.
7. **`Stop-Process` над фоновой задачей даёт `completed, exit 0`** от раннера. Это не зелёный гейт.
8. **phpstan плагина гонять В КОНТЕЙНЕРЕ** — на виндовой ФС не уложился в 25 минут, в контейнере
   минута: `MSYS_NO_PATHCONV=1 docker exec -w /var/www/html/wp-content/plugins/woocommerce-edostavka
   <cli> sh -c 'vendor/bin/phpstan analyse --memory-limit=2G --no-progress'`. ⚠ Чистый контроль
   (один процесс на Windows) не доведён, причина не установлена: свободной памяти было 2,9 ГБ.
9. **У репозитория плагина `core.autocrlf=true`** и не было правила для `*.php` в `.gitattributes`:
   любой `checkout`/`stash pop` делал файл CRLF и валил phpcs на файле, который никто не трогал.
   Правило добавлено в s116; во фреймворке оно было всегда.
