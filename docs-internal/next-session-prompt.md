# ⚠️ Ловушки, до первой команды

**1. Serena ОБЯЗАТЕЛЬНА (решение оператора, s60) и сейчас НЕ подключена.** На старте проверь
наличие `find_symbol`/`get_symbols_overview` (включая отложенный список инструментов). Нет —
**доложи до любой PHP-работы**: это дефект окружения (отвалилась незаметно, примерно когда и
obsidian в s55). Каждый бриф субагенту с PHP обязан повторять правило. Полный текст:
`AGENT-RULES.md` → "Use Serena MCP".

**2. wp-env команды — ТОЛЬКО из корня репозитория.** Из поддиректории — ложное «Environment not
initialized» при живых контейнерах. Именно это в s59 выглядело как «токен не читается» и зря
блокировало #214. И `MSYS_NO_PATHCONV=1` обязателен для путей внутри контейнера. Готчи
`wpenv-resolves-environment-from-cwd`, `wpenv-windows-gitbash-path-mangling`.

**3. Состояние рига живёт в wp-config КОНТЕЙНЕРА, не в файлах.** `wp config set` переживает
`npx wp-env start`; `.wp-env.override.json` лишь зеркалит. Проверять:

```bash
git branch --show-current
MSYS_NO_PATHCONV=1 npx wp-env run cli wp config list --fields=name,value | grep WOODEV_TEST
```

Прецеденс источников: `LIVE_YANDEX` > `LIVE_POCHTA` > `STRATEGY`. Сейчас: `LIVE_YANDEX=1`,
`LIVE_POCHTA=false`, `STRATEGY=viewport` (игнорируется). Вернуть фикстуру = оба live-флага в `false`.

**4. Риг отдаёт РАБОЧЕЕ ДЕРЕВО.** Чекаут другой ветки мгновенно откатывает правки. Прежде чем
просить кого-то посмотреть — назови ветку И константы. Готча
`rig-serves-the-working-tree-branch-switch-reverts-fixes`.

**5. Достоверный jest только так:** `npm run test:js -- --roots "<rootDir>/tests/js"`.
**Никогда `npx jest`.** В бриф исполнителю — ВЕСЬ набор проверок перечислением: `composer
test:unit` + `composer phpcs` + `composer phpstan` + jest с `--roots`.

**6. Codex НЕ ЧИТАЕТ ФАЙЛЫ.** Диффы — только инлайном, бандл ≤ ~12 КБ, через скретчпад. И
формулируй бандл так, чтобы «этого ещё нет» было видно (s59: три HIGH-находки оказались артефактом
склейки «текущий код + дизайн»).

**7. Доки после аудита s60 — источник истины, но утверждения об ИСТОРИИ проверяй по SESSION-LOG.**
s59 записал в хэндофф неверный факт о самих доках («аудит был s39»), и он бы поехал дальше.
Числа и «когда это было» не переписывать из хэндоффа в хэндофф.

# Очередь

## 1. #243 — последнюю включённую галку фильтра делать `disabled`. **Решено, можно брать**

Решение оператора принято в s59 (разбор «наш фильтр против фильтра Почты»). Сейчас снятие
последней галки молча возвращает её — тот же класс, что забракованные в s56 «мёртвые» кнопки зума.
**Семантику НЕ менять** (галка = «показывай тип», снять все нельзя; модель Почты «пусто =
показывать всё» отвергнута осознанно). Ловушка из карточки: правило «хотя бы один»
пересчитывается и при ДОБАВЛЕНИИ типа — `setTypes()` вставляет новый код включённым, ранее
заблокированная галка обязана разблокироваться. Типы полностью за доменом; фильтр виден с двух
типов, числовой значок — с трёх (`FILTER_BADGE_MIN_TYPES`).

## 2. #238 — `getSession()` не вызывается из продакшена. **Нужен дизайн, потом код**

`refresh()` достижим только из тестов ⇒ `forgetPointDetails()` из #232 (инвалидация вердикта при
смене корзины) в проде не работала никогда. Радиус мал: сессия пересоздаётся на каждое открытие
модалки; окно — смена корзины при ОТКРЫТОЙ модалке. Наивно подписать `updated_checkout` на
`refresh()` нельзя — под viewport это живой вызов перевозчика 6–13 с на частое событие. Нужен
разбор: обновлять только открытые сессии + дебаунс.

## 3. #214 — дубль префикса «стрстр.1». **Ждёт оператора, но замер РАЗБЛОКИРОВАН**

Карточка ждала «разрешить живой Яндекс на один прогон ИЛИ закрыть not planned». Теперь риг УЖЕ на
живом Яндексе (812 точек) и токен читается (ловушка s59 была cwd-эффектом wp-env). Если оператор
скажет «меряй» — прогнать разброс форм `address` по 812 точкам и вывести правило; вариант 2 из
карточки не покрывает её же примеры (три из четырёх — `стр` перед `к.`, то есть не дубль).

## 4. #244 / #245 — долги, вскрытые аудитом s60 (Бэклог)

- **#245 (release-blocking для v2):** дефолтный `WOODEV_LICENSE_AUTHORITY_PUBKEY` в
  `class-license-envelope-verifier.php:25` ≠ прод-ключ издателя. Перед релизом вшить прод-ключ
  (или решить механику доставки ключа).
- **#244:** `Plugin_Action_Links_Handler` и `API_Logger` так и не извлечены из базы
  (`class-plugin.php:860`, `:896-932`), хотя гейт P4 числился пройденным. Доделать или закрыть
  осознанно.
