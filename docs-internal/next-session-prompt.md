# Что доказано замером

1. **Пустой список ПВЗ на здоровом 200 приходит ДО источника.** `get_points_data()` выходит на
   `from_request() === null` (нет ни `locality`, ни валидного `bbox`) или на рассогласовании
   стратегий, а `attach_location_context()` идёт ПОСЛЕ этого гейта — значит сохранённая запись
   покупателя неадресованный запрос не спасает. Отсюда #744 закрыта как не-дефект.
2. **У подключённого перевозчика ЗНАЧЕНИЕ `locality` инертно** — сервер разрешает запись покупателя
   и она старше параметра. Важно только НАЛИЧИЕ параметра. Чтобы проверить город, менять надо
   запись, а не URL.
3. **Источник первого перевозчика игнорирует НП полностью** — несуществующий город даёт тот же
   набор из 815 точек, сверены id (#747).
4. **`Woodev_Loader` действительно один на запрос** (`final` + `class_exists( …, false )`), поэтому
   статик в нём общефлотовый — в отличие от `Pickup_Handler`/`Checkout_Handler`, где каждый плагин
   строит свой объект.
5. **Владение методом ПВЗ из хендлера вывести НЕЛЬЗЯ** (s113, подтверждено при #745), и
   **`test-cdek` — клиент живого контура СДЭК**, а не словарь: греп по файлу не говорит, какие
   города он знает.
7. **Хук, зарегистрированный как `[ $this, … ]` из класса, который каждый плагин строит себе сам,
   срабатывает ОДИН РАЗ НА ПЛАГИН.** WordPress ключует колбэк через `_wp_filter_build_unique_id()`,
   и для объектного колбэка туда входит `spl_object_hash()`. Статический колбэк схлопывает все
   регистрации в одну. Готча
   `a-hook-registered-from-a-per-plugin-object-fires-once-per-plugin`.
8. **Интеграция = 129/506**, измерено 03.09.2026 на `702adda` — не перенос из прошлого хендоффа.

1. **`@since` в новом коде — `2.0.2`, не `2.0.3`.** За ночь нарушили два воркера из четырёх.
   Теперь есть гейт (#752), но он сканирует только `woodev/` — **писать правило в КАЖДЫЙ бриф.**
2. **`gh auth setup-git` на машине может быть НЕ выполнен**, хотя это стоячее правило с 27.08.2026.
   В s114 в SYSTEM-конфиге стоял `credential.helper = manager` без github.com-скоупа, и `git push`
   из основного дерева завис молча. Проверять `git config --global --get-regexp credential` ДО
   первого пуша, а не после зависания. Готча
   `git-credential-manager-hangs-silently-in-an-agent-session`.
3. **Док-гейты сработают, и не по одному разу.** Строка индекса `GOTCHAS.md` — максимум 400
   символов (в s114 резала трижды), `CURRENT-STATE.md` — 28 КБ, хендофф — 16 КБ (пробиты оба).
   Вытеснять ИСТОРИЮ и пересказ, не живой факт и не номера обязательств.
5. **Совет в готче устаревает от СВОЕГО ЖЕ мержа.** В s114 запись стала неверной через час
   после #746. После мержа, меняющего поведение, перечитать написанное до него.
6. **Прежде чем брать карточку — сверить её с кодом.** #106 описывала работу, сделанную три месяца
   назад и помеченную прямо в коде идентификаторами находок. Это дешевле реализации.
7. **`gh project item-list` по умолчанию отдаёт 300, а на доске их 352** — всегда `--limit 1000`.
8. **Ворктри стартуют грязными с СЕМЬЮ CRLF-файлами**; удалять только через Orca, доказав пустоту
   `git diff --ignore-cr-at-eol`. Осиротевший каталог `s87-critic-472r3` там же — git о нём не знает.
9. **Serena игнорирует `tests/`, `docs/` и др.** — правило с исключением в `AGENT-RULES.md`.
10. **Оркестрация, два новых капкана s114:** `orca` может пропасть из PATH одного вызова Bash, и
    грепы съедят `command not found` — молчащая команда это не вывод о рантайме; и
    `agent_prompt_stalled` лечится `worker-stop` → `task-update ready` → `worker-start` →
    `terminal send --text "" --enter`, потому что `--retry-of` по settled-диспатчу отказывает.
