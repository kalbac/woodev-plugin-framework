4. **DaData clean API ≠ suggest API**: другой хост, токен+секрет, платный — capability `normalize`
   появляется только при настроенном секрете (задача 7).

# Что нового знаем после s67

- **Чужой готовый API проверяется по исходникам ДО того, как лечь в основу идеи.** «Возьмём за
  основу WC Autocomplete» превратилось в «скопируем форму, заглушим механику» после одного захода
  в trunk. Форма идеи при этом ПОДТВЕРДИЛАСЬ их же архитектурой (общая настройка провайдера,
  per-country арбитраж).
- **Дилемма из N взаимоисключающих вариантов часто растворяется разделением данные/презентация** —
  три режима СДЭК оказались тремя рендерерами над одним источником с разными требованиями к нему
  (capability-гейт вместо выбора).
- **Референс в боевом коде оператора сильнее рассуждений** — дуальный стор, `update_checkout`
  после персиста, `set_customer_location` — всё это уже было в его плагинах, и дизайн просто
  обобщил проверенное.
- **Брейншторм-протокол работал**: короткие сообщения, один вопрос за раз, каждое возражение —
  замером (исходники WC, отчёт сабагента по `plugins-reference/`, живость suggestions-js).
