# Что доказано замером

1. **`wp i18n make-pot` не требует ни WordPress, ни wp-env** — потому гейт «исходники против
   каталога» встал шагом в существующую джобу `lint`, а не в контейнер; wp-cli приколот на **2.12.0**.
2. **`lint:i18n` отвечал про КАТАЛОГ, а не про код** — 28 msgid жили в исходниках и не доехали до
   `.pot` при зелёном гейте. Закрыто `lint:i18n-sources` (#791); доказано враждебно — краснеет и на
   склеенном msgid, а без wp-cli падает, а не пропускает.
3. **Замысел #144 был структурно нереализуем:** оба вызывающих (`class-pickup-handler.php:1760`,
   `class-pickup-controller.php:569`) передают голый `$point_id` без `Point_Query`.
4. **Фикстуры богаче условия заморозки:** четыре `STRATEGY_BULK`-реализации, оба типа точки,
   структурное расписание от живой песочницы Яндекса.
5. **Версия `2.3.0.0` годится:** выше `2.2.5.5` не установлено нигде, `2.3.2` не выкладывалась;
   `version_compare('2.3.0.0','2.2.5.5')` = БОЛЬШЕ, проверено запуском.

# Ловушки

Только новое за s121; прежнее — по тегам в `GOTCHAS.md`.

1. **Критику НЕЛЬЗЯ давать свежее ворктри под ветку автора** — git отказывает во втором чекауте, и
   критик молча уходит работать В ДЕРЕВО АВТОРА, где пишет зонды. Отдавать **detached-чекаут по
   SHA**. Готча `a-critic-cannot-get-a-fresh-worktree-for-a-branch-already-checked-out`.
2. **Скопированный classmap не знает класса, которого не было при создании ворктри** — и это бьёт не
   только от чужого переименования, но и когда ТЫ САМ добавил класс, включая ГЛАВНЫЙ чекаут после
   мержа. Готча дополнена; там же разведены composer'ов classmap и `woodev/class-map.php`.
3. **`--terminal` без `--worktree`** даёт `terminal_worktree_mismatch` — нужны ОБА флага.
4. **`agent_prompt_stalled`** лечится рецептом s114: `worker-stop` → `task-update --status ready` →
   обычный `worker-start`. `--retry-of` отказывает.
5. **Строка индекса в `GOTCHAS.md` — максимум 400 символов**; и не начинай перенесённую строку
   пункта обязательств с даты — `/^\d+\./` считает её новым элементом (`DOCS-SCHEMA.md`).
