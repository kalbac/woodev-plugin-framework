# Что доказано замером

1. **#541 — причина асимметрия рендереров, не очередь.** Перехват до загрузки, инкогнито, холодный
   путь: клик `+0`, `→ /list +4 мс`, **спиннер `+10 мс`** (было `+10 558`), `← /list +9 724 мс`,
   `← /select +15 932 мс`. Контроль на той же ветке с откаченной правкой (`servedHasFix: false`
   проверено ДО выводов) на отметке +800 мс: спиннера нет, `aria-disabled` = `null`. ⚠ У контроля
   `/list` вернулся быстрее (сервер прогрет), то есть его окно было КОРОЧЕ — сравнение
   консервативное.
2. **select2 не заменяет список во время запроса, а ДОПИСЫВАЕТ «Searching…» сверху** — 9,6 с поле
   предлагало «Санкт-Петербург» и «Репино» тому, кто набрал «Пушк». И наоборот: `append()`
   начинается с `hideLoading()`, поэтому любой наш `success()` этот индикатор снимает.
3. **Двойной `success()` за один запрос — конструкция, а не удача** (`selectWoo.full.js:3586-3600`:
   колбэк → `results:all`, который ЗАМЕНЯЕТ список). Прочитано в вендоренном исходнике рига.
4. **`woodev_location_allow_custom_settlement` на риге = `no`.** Хендофф s93 записывает `yes` — это
   неверно. Поэтому ряд-тег #528 отсутствует правильно, а не как регрессия.
5. **`/suggest` на риге 6–10 с, `/select` 13,6–14,1 с, `/list` для холодного региона 9,7 с.**
   Ждать по факту появления строки, никогда по таймеру.

# Ловушки

1. **Закрытый PR с удалённой базовой веткой восстановить НЕЛЬЗЯ.** `gh pr reopen` требует живую
   базу, `gh pr edit --base` требует открытый PR. Мерж базового PR с `--delete-branch` закрывает
   весь стек навсегда. Профилактика: мержить базу БЕЗ `--delete-branch`, перенацелить нижний PR
   пока он открыт, ветку удалить последней. Готча `stacked-pr-github-mechanics`, Symptom 5.
   ⚠ **Эта готча уже существовала, и я не прочитал её перед мержем.** Перед мержем стека — читать
   `[tooling/git-merge]` в `GOTCHAS.md`.
2. **Ранняя отрисовка в ajax-транспорте select2 стоит ОБОИХ честных состояний.** Пустой список
   рисуется как «не найдено» (`noResults` знает только «пуст ли»), а ЛЮБОЙ `success()` снимает
   строку загрузки (`append()` начинается с `hideLoading()`) — то есть индикатор надо нести самому.
   Готча `an-empty-list-while-the-search-runs-is-not-a-zero-result`.
   ⚠ Первую половину я починил, вторую этой же правкой сломал, и нашёл её оператор: проверял по
   описанию карточки («стаяли строки ушли»), а не по тому, как выглядит кадр целиком.
3. **Хук `language.noResults` надо спрашивать ВО ВРЕМЯ отрисовки, а не после возврата транспорта** —
   иначе тест не отличает правильный порядок от неправильного и пробник остаётся зелёным.
4. **Считать готчи по `ls gotchas/*.md` нельзя** — там лежит `README.md`. Верить гейту
   `npm run lint:docs`.
5. **Изолированный контекст Chrome + `initScript` — рабочий способ поймать холодный путь.**
   `new_page` с `isolatedContext` даёт свежего покупателя, `navigate_page` с `initScript` ставит
   перехват ДО загрузки. Но контрольный `fetch` из консоли ПРОГРЕВАЕТ серверный кеш — контроль
   гонять в отдельном контексте и после замера, не до.
