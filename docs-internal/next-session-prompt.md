## ⚠️ Блокер мерджа — авария GitHub, а не наш код

PR #177 стоит с пустым `statusCheckRollup` при `mergeStateStatus: CLEAN`. **Это НЕ повод мержить** —
у `main` нет обязательных проверок, поэтому CLEAN означает лишь «конфликтов нет». На этой самой
комбинации проект уже обжигался (s29, мердж на красном PHPStan).

Причина установлена и она внешняя: **GitHub Actions был в Major Outage с 06.08.2026 15:22 UTC**,
вебхуки throttled до ~15%. Их собственная формулировка: «many events such as pushes and pull
requests are not triggering workflow runs». Три попытки перевыпустить событие (close/reopen PR,
пустой коммит, обычный пуш) утонули там же — **это не признак поломки в репозитории**.

**⚡ Обновление на конец s54: запуски ПОШЛИ.** Последний пуш (`cf06da0`, 06.08 23:41 UTC) породил
все три воркфлоу — CI, Integration Tests, Markdown Lint, — хотя компонент Actions на статус-странице
всё ещё `major_outage`; вебхуки к тому моменту стали `operational`. На момент конца сессии они были
`in_progress`, результат не дождался. **Первым делом посмотри их исход:**

```bash
gh run list --branch feat/pickup-selection --limit 5
gh pr view 177 --json statusCheckRollup --jq '.statusCheckRollup[] | "\(.name): \(.conclusion)"'
```

Если какая-то джоба не породилась или упала по инфраструктуре — перевыпусти пустым коммитом, это
всё ещё последствия аварии, а не наш код. Критерий прежний: **pass по каждой джобе отдельно**, потом
squash-мердж.

**Если запуски снова пропали — проверь, закрыт ли инцидент:**

```bash
curl -s https://www.githubstatus.com/api/v2/summary.json | python -c "import json,sys; d=json.load(sys.stdin); print([c['name']+': '+c['status'] for c in d['components'] if 'Action' in c['name']])"
```

Если Actions `operational` — один пустой коммит, затем **pass по каждой джобе отдельно**, и только
потом squash-мердж (**никогда** `gh pr merge --auto` — в s11 смерджило на рассинхроне).

Локальные проверки уже пройдены и зелены, но они не заменяют CI: другая ОС, другая матрица PHP, а
jest в CI не гоняется вообще (#146). Готча `empty-status-rollup-can-be-a-github-actions-outage`.

# Чему научила s54

**Пустой список джоб при `CLEAN` — не обязательно наша конфигурация.** Триггеры, дифф `.github/`,
`gh workflow list`, `actions/permissions`, публичность репозитория — всё было чисто, а причиной
оказалась авария платформы. Дешёвые локальные проверки сначала, потом **статус-страница**, и только
потом подозревать воркфлоу. И помнить: когда события отбрасываются, **лечение тоже молча не
срабатывает** — два неудачных перевыпуска читаются как «сломано глубже», хотя сломано не у нас.

**Эталон надо читать целиком, а не по месту.** «Захват N ближайших точек» при поиске оказался нашей
выдумкой — у Яндекс.Доставки нет ни строки собственного кода камеры для поиска. При этом оператор
верно поправил меня по ходу: облако точек эталон всё-таки использует, но для `boundedBy` —
**какие кандидаты предлагать**, и никогда для выбора кадра. Формулировать это различие точно.

**`!important` поймал в ТРЕТИЙ раз** (готча `hostile-theme-button-display-none-needs-important`,
дополнение s54). Правило при специфичности (0,4,0) против (0,2,0) не срабатывало, потому что ресет
держит `display: inline-flex !important`. Внутри `.woodev-pickup-stage` считать `display`
свойством «только через `!important`» и проверять замером (`getComputedStyle`,
`document.elementFromPoint`), а не перечитыванием селектора.

**Проверять заявления по первоисточнику, даже свои.** Оператор потребовал подтвердить, что
`ymaps.suggest()` не отдаёт координат — подтвердилось по официальной документации 2.1 (ровно два
поля, `displayName` и `value`). А зум 16 после поиска чуть не был записан как «сработал фолбэк»:
трасса показала, что `setBounds` получил коробку дома, а `setCenter(…, 16)` — это внутренняя
делегация ymaps (готча s52). Совпадение с константой было случайным.

# ⚠️ Про JS-тесты, до первой команды

**Только `npm run test:js`, никогда `npx jest`.** Своего jest-конфига в репозитории нет, им владеет
`wp-scripts test-unit-js`, и именно он даёт jsdom. `npx jest` откатывается на node-окружение и
печатает фантомные падения. Подсказка — упавший ИТОГ. Готча `npx-jest-bypasses-wp-scripts-jsdom`.

**Коммитить до прогона мутаций** — готча `git-checkout-destroys-uncommitted-mutation-revert`.

**Бэктики в `gh issue create --body` и `git commit -m`** уходят в подстановку bash и молча съедают
кусок текста. Использовать heredoc с `<<'EOF'` или `--body-file -`.
