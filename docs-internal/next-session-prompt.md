# Ловушки

Только новое за s124; прежнее — по тегам в `GOTCHAS.md`.

1. **Незамапленная фикстура кладёт ВСЮ интеграционную сьюту, а не свои тесты.**
   `Framework_Resolver::load_plugins()` требует `<plugin_path>/woodev/class-plugin.php` у того
   плагина, до которого дойдёт ПЕРВЫМ (гвард `class_exists( '\Woodev_Plugin', false )`). Сообщение
   называет `class-plugin.php` и читается как сломанный `vendor`. Три правильно замапленные соседки
   не спасают. Готча `wpenv-resolver-fixture-mapping` (расширена).
2. **Зелёная сьюта — не доказательство отсутствия загрязнения.** Зондовые подклассы в тесте s124
   оставляли в приватном `$methods` синглтона записи без `class_name`, который
   `get_shipping_method_class_names()` читает без защиты; сьюта была ЗЕЛЁНОЙ, потому что туда
   сегодня никто не ходит. **Перед «заведу свою фикстуру» перебрать существующие.**
3. **Сеттер, пересчитывающий производное состояние, не должен делать это ВНУТРИ пересчёта.** Колбэк
   фильтра `..._form_fields`, зовущий `add_support()`, получал контрол, который внешний проход
   затирал своим до-фичевым массивом. Готча
   `a-base-constructor-that-assigns-what-the-subclass-just-set` (расширена).
