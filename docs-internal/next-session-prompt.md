# ⚠️ Ловушки, до первой команды

**1. Serena: «сервер поднялся» не значит «работает».** `MCP_TIMEOUT=120000` из s61 сработал, сервер
живой — но первый же вызов вернул `No active project` со списком из 14 known projects. Нужен
**`activate_project('woodev_framework')`** руками. Хэндофф s61 обещал «нужен только рестарт» и был
неполон. Проверяй **символьным вызовом** (`find_symbol Woodev_Plugin/get_file` → должен дать
`class-plugin.php:1040-1047`), а не фактом наличия инструментов в списке.

**2. Правка `woodev-modal.js` не доедет до браузера — это #250, ещё не починено.** Файл
регистрируется с голой `self::VERSION` (`class-plugin.php:521-526`), а не через
`get_assets_version()`. Между релизами версия не меняется → браузер держит старую копию. В s62 это
стоило ложного сигнала: `isOpen()` лежал в файле на диске и отсутствовал на живом прототипе, рабочая
правка читалась как сломанная. **Признак:** символ есть в файле и отсутствует в рантайме. **Действие:**
перезагрузить с `ignoreCache: true`, а не лезть в исходник. Проверить одним вызовом:
`await (await fetch(url,{cache:'no-store'})).text()` против `typeof window.WoodevModal.prototype.isOpen`.

**3. Штатная конфигурация рига не покрывает половину путей пикера.** `selection: { close: true,
refreshCheckout: false }` — значит выбор точки ЗАКРЫВАЕТ модалку, и путь «модалка остаётся открытой»
(а с ним всё эхо-подавление #238) фикстурой недостижим. В s62 конфиг менялся прямо в браузере
(`window.woodev_pickup_config_*.selection`) — это легально (объект читается заново на каждое
открытие), но помни, что из коробки этого нет. Заведено внутри #251.

**4. Город на риге надо задать руками, иначе пикер пуст.** `bulk`-запрос адресуется `locality` из
`#billing_city`, а поле стартует пустым. Порядок: `$('#billing_state').val('77').trigger('change')`
→ дождаться загрузки городов → `$('#billing_city').val('Москва').trigger('change')` → и только потом
открывать пикер. Пустой ответ `{"points":[]}` — это не поломка источника.

**5. wp-env — ТОЛЬКО из корня репозитория**, иначе ложное «Environment not initialized» при живых
контейнерах. `MSYS_NO_PATHCONV=1` обязателен для путей внутри контейнера. `wp config list` из корня —
единственный честный способ узнать состояние рига (константы живут в wp-config контейнера, не в
`.wp-env*.json`).

**6. Риг отдаёт РАБОЧЕЕ ДЕРЕВО.** Прежде чем просить кого-то посмотреть — назови ветку И константы.

**7. Достоверный jest только так:** `npm run test:js -- --roots "<rootDir>/tests/js"`. Никогда `npx jest`.

## 2. #250 — версионирование модалки, однострочная правка

`wp_register_script( 'woodev-modal', …, self::VERSION )` → `…, $this->get_assets_version()`.
`get_assets_version()` уже содержит ветку `time()` под `SCRIPT_DEBUG`/`WP_DEBUG`, так что это чинит и
ловушку разработки, и релизное поведение для неизменного файла не меняет. Логично делать вместе с
**#247** (минификация — там всё равно будет один хелпер суффикса подключения). Готча:
`gotchas/modal-script-versioned-by-version-constant-not-filemtime.md`.
