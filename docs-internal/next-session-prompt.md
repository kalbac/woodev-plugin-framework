# Что доказано замером

1. **«Любое» ≡ формула оператора на реальной БД, оба хранилища** — `OrdersIdResolverDatastoresTest`:
   57 заказов × 720 запросов, три мутации красные; на риге (HPOS) 34 + 69 − 6 = 97 точно.
2. **Сужение запроса id по статусу/периоду не окупается** — замедляет вид без фильтра на +26 % (HPOS) /
   +16 % (CPT) на 100 тыс.; выигрыш только на узком периоде (458 → 22 мс). Сырые данные —
   `research/2026-09-27-935-id-narrowing/results/`.
3. **Пагинация точек на уровне фреймворка ничего не даёт** — провайдер грузит все точки bbox одним
   вызовом; 1 МБ ответа ≈ 830 точек, реальный максимум 113 (#151).
4. **Мак: 64 ГБ, ~33 ГБ свободно при четырёх агентах двух проектов** (s141) — памяти не предел.
