# ⚠️ Что важно знать перед кодом

Две готчи, каждая стоила дефекта в уже «отгруженной» фиче. Читать ДО, а не после:

1. `js-hidden-checkout-field-is-still-required-server-side` — WooCommerce валидирует НАЛИЧИЕ, а не
   видимость. Что браузер прячет — то сервер обязан перестать требовать, в том же условии.
2. `wc-address-i18n-reshows-fields-with-an-inline-display-block` — `.show()` пишет инлайновый
   `display:block`, бьющий класс без `!important`. Коварство в тайминге: сразу после переключения
   строка прячется, возвращается на следующем проходе локали.

**Про зонды в браузере** (я наступил дважды за одну сессию):
- select2 слушает `keydown`/`keyup`, а не только `input` — синтетический ввод одним `input` даёт
  ложное «ничего не найдено»;
- ссылку на поле брать ЗАНОВО после каждого `update_checkout` и доказывать, чей виджет открылся
  (`.select2-container--open` → `previousElementSibling.id`), иначе откроешь осиротевший;
- прежде чем заводить карточку на «дефект вёрстки» — проверить, не WooCommerce ли это. Класс
  `undefined` на `#shipping_state` оказался их `country-select.js:138`.

**Про параллельность:** риг отдаёт рабочее дерево, снапшота нет. Реализация и риговая проверка
сериализуются. Готча `rig-serves-the-working-tree-branch-switch-reverts-fixes`.
