# Что доказано замером

1. **#405 был прав всё это время; неверен был ЗАМЕР s83.** Фикстура `test-cdek` читает ключи через
   `get_integration_option()` → массив `woocommerce_woodev_test_shipping_method_settings`.
   Отдельная опция **`woodev_location_cdek_client_id` — обманка, её не читает НИКТО.** Все прежние
   пробы правили её. Записанный по правильному адресу неверный ключ роняет провайдера ровно как
   обещает контракт. Две маски сверху: `token()` отдаёт закешированный транзиент ДО проверки ключей,
   а уровень РЕГИОНА отвечает из `woodev_test_cdek_regions_ru` и в сеть не ходит — на этом риге
   (ось региона `related-list`) регион **в принципе не может** показать сбой ключей. Таблица из
   четырёх замеров с контролем — готча
   `the-cdek-fixture-credentials-are-not-the-option-they-look-like`.
2. **`related-list` для НП недостижим не «по недосмотру», а дважды:** `offered_field_modes_for()`
   его не предлагает, и `get_field_mode_settlement()` зажимает сохранённое значение
   **безусловно, на чтении**. Проверено перед мержем удаления (#550).
3. **`Locality_Key`: `compose( ...parse( $k ) )` НЕ тождество для производного ключа** — теперь
   задокументировано на обоих методах и **прибито тестом** (#548). Длина под `VARCHAR(191)` замерена
   и закрыта без ограничителя: единственный поставляемый провайдер минтит FIAS UUID (36 символов),
   запас 100+ символов даже в худшем экранированном случае.
4. **Мутационное тестирование нашло то, чего не нашли ни автор, ни ревью:** удаление проверки
   `$section` из `settlement_field_id_for_section()` (#545) не краснило **ни одного из 13** тестов.
   Закрыто двумя тестами, где обе колонки несут поле с разными непустыми значениями.

# Ловушки

1. **`orca worktree rm` отказывается удалять ворктри из-за CRLF-грязи, с которой ворктри и
   рождается.** Нужен `--force` — но **список путей в ошибке читать обязательно**: `--force`
   правилен ровно для этих четырёх файлов и уничтожает настоящую работу для любого другого списка.
   Готча `an-orca-worktree-starts-dirty-with-crlf-churn`.
2. **Воркер, отрезанный от `main` до мержа, не узнает о мерже сам.** В s95 воркер #529 правил тот же
   тестовый файл, что и уже смерженный #549. Ловится по diff-stat (файл, который #549 ДОБАВИЛ,
   показывается как `-89` в дереве воркера). Когда волна переживает мерж — разослать выжившим
   `status` с указанием сделать rebase и сохранить обе стороны.
3. **`gh pr checks` в первые секунды показывает ОДНУ джобу.** Ждать нулевого pending. ⚠ И **джоб не
   всегда 20:** «Markdown Lint» запускается только при изменении `**.md`, поэтому у чисто кодового
   PR их **19**, и это полный набор. Считать pending, а не до двадцати.
4. **Codex не годится критиком по ворктри Orca** — его шелл не резолвит `gitdir: D:/…`. В s95
   критиком был свежий Sonnet-воркер с review-only брифом в своей ворктри; именно он нашёл дыру №4
   выше.
5. **Гейт сессионного чтения на 118,6 KB из 120.** Каждая новая строка в `GOTCHAS.md` его двигает.
   Следующему, кто добавит две-три готчи, придётся что-то ужать — закладывать это в план, а не
   упираться в красный гейт в конце.
