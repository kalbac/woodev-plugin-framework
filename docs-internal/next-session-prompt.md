# Что доказано замером

1. **Пустой список ПВЗ на здоровом 200 приходит ДО источника.** `get_points_data()` выходит на
   `from_request() === null` (нет ни `locality`, ни валидного `bbox`) или на рассогласовании
   стратегий, а `attach_location_context()` идёт ПОСЛЕ этого гейта — значит сохранённая запись
   покупателя неадресованный запрос не спасает. Отсюда #744 закрыта как не-дефект.
2. **У подключённого перевозчика ЗНАЧЕНИЕ `locality` инертно** — сервер разрешает запись покупателя
   и она старше параметра. Важно только НАЛИЧИЕ параметра. Чтобы проверить город, менять надо
   запись, а не URL.
3. **Источник первого перевозчика игнорирует НП полностью**: `Москва`, `Краснодар`, ключ и
   несуществующий город дают один и тот же набор из 815 точек — сверены id, не количества (#747).
4. **`Woodev_Loader` действительно один на запрос** (`final` + `class_exists( …, false )`), поэтому
   статик в нём общефлотовый — в отличие от `Pickup_Handler`/`Checkout_Handler`, где каждый плагин
   строит свой объект.
5. **Владение методом ПВЗ из хендлера вывести НЕЛЬЗЯ** (s113, подтверждено при #745):
   `Shipping_Method::get_plugin()` — `abstract protected`, токен хендлера с id плагина не связан.
6. **`test-cdek` — клиент живого тестового контура СДЭК**, не фикстурный словарь. Греп по файлу НЕ
   говорит, какие города он знает.
