# Ловушки

1. **Оркестрация: три ловушки s101** — `worker-start` может ответить `input_accepted` и НЕ
   запустить воркера (я 10 минут ждал мёртвого); `check --wait` больше 600 с бесполезен из Bash;
   три воркера в одном дереве работают, если файлы не пересекаются и им запрещены git и гейты.
   Замеры и команды — [wiki/orchestrating-agents-with-orca.md](wiki/orchestrating-agents-with-orca.md),
   раздел «Traps».
2. **`git stash push -- woodev/` ничего не сташит, если правки УЖЕ закоммичены** — фальсификация
   тогда «проходит», ничего не доказав. Откатывать `git checkout <base> -- woodev/` и проверять
   замером (`grep -c`), что откат состоялся, ДО прогона.
3. **Bash-heredoc с закавыченным маркером СЪЕДАЕТ одинарный уровень экранирования** — двойной
   обратный слэш доезжает как одинарный. Python с обратными слэшами писать raw-строками.
4. **`Woodev_Payment_Gateway` абстрактный, а свойство `id` объявлено в `WC_Payment_Gateway`**, в
   юнит-тестах это голая заглушка без свойств. Двойник должен объявить `public $id;` сам, иначе
   рефлексия падает с `Class "" does not exist`.
5. **Прежде чем нести развилку оператору — проверь, не измеряется ли она.** В s101 я вынес ему два
   вопроса; один снялся одним `docker exec` к исходникам WooCommerce в контейнере, второй был уже
   записан готчей тремя сессиями раньше. Оба выносить не следовало.
