лично. **План:** `docs-internal/plans/2026-08-12-location-provider-plan.md`. Обе читать до первой
строчки кода; исполнителям **явно разрешено противоречить плану, когда код с ним расходится** —
за s68 это сработало больше десяти раз, включая три случая, где план был просто неверен.

Режим: subagent-driven (worker Sonnet + критик Codex). Окупился однозначно: **9 находок критика за
три блока, все подтверждены замером до правки, ни одной отклонённой**, и две из них — дефекты,
внесённые предыдущей правкой по предыдущей находке.

# ⚠️ Ловушки, до первой команды

Ловушки s65–s67 в силе (пикер на `/classic-checkout/`, jest только
`npm run test:js -- --roots "<rootDir>/tests/js"`, wp-env из корня, оба мира событий jQuery, три
генерации таймеров в харнессе classic-адаптера, модульное состояние `pickup-mount.test.js`).
Новое, дорого купленное в s68:

1. **Три дефекта подряд были невидимы локально и видны только на CI.** «Зелено локально» на этом
   репозитории не является утверждением. Конкретно: рефлексия без `setAccessible` (локальный PHP
   8.5 против матрицы 7.4–8.3 — готча `reflection-setaccessible-version-guard`), gitleaks на
   правдоподобной заглушке (готча `a-no-leak-test-needs-a-low-entropy-placeholder`), и
   `do_action('init')` в интеграционном тесте (дополнение к
   `integration-test-global-admin-hooks-output-and-submenu-accumulation`).
2. **Записанное правило не путешествует в делегированную работу само.** Готча про `setAccessible`
   лежала в индексе с июня, и исполнитель наступил на неё снова — бриф на неё не ссылался. Правила,
   релевантные задаче, вписывать В БРИФ, а не рассчитывать на индекс.
3. **`within` в `/suggest` резолвится через ТЕКУЩУЮ запись покупателя,** а не по ключу — для каскада
   «регион → город» это корректно (каждый выбор персистится по D8), но в режиме связанного списка
   (задача 13) регион может быть не персистирован, и скоуп молча деградирует до общестрановой.
   Если задача 13 упрётся — вот сюда смотреть.
4. **Каскад чинить только гейтом запомненного значения родителя** — холостой программный `change`
   не должен разрушать значение потомка (готча
   `a-programmatic-parent-change-must-not-run-a-destructive-cascade`, куплена в s66 порчей сессии).
5. **select2 сообщает выбор через jQuery `.trigger('change')`, который НЕ создаёт нативного
   события** — привязка в обоих мирах, и хотя бы один jest-тест на путь продюсера через РЕАЛЬНЫЙ
   jQuery (готча `jquery-trigger-change-fires-no-native-event`; в s66 семь зелёных тестов
   промахнулись мимо этого).
