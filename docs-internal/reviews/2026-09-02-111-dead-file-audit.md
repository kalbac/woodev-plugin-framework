# Card #111 — dead-file sweep audit

> 2026-09-02. Audit-first per the card brief. Deliverable is this table plus the four
> deletions it justifies — everything else in `woodev/` is either wired, tested, documented,
> or a public extension seam, and stays.

## Method

Two independent sweeps, both bulk-scripted against the whole tree (`woodev/` + `tests/`),
not spot-checked file-by-file:

1. **Class-name sweep.** For every one of the 207 entries in `woodev/class-map.php`
   (generated by `bin/generate-class-map.php`, which enumerates every class/interface/trait
   in the tree), `rg -w` for the short class name across `woodev/` + `tests/`, excluding the
   defining file and `class-map.php` itself.
2. **Path sweep.** For the same 207 entries, `rg -F` for the file's **basename** across the
   same scope. This is the check the class-name sweep cannot do: `woodev/class-plugin.php`
   wires several framework files by `require_once` **path**, not by class name, so a class
   that is never instantiated anywhere can still be required unconditionally in the
   production bootstrap. Missing this distinction on the first pass nearly produced a false
   DELETE verdict (see "What the class sweep did NOT delete" below) — the second sweep is
   what caught it before anything was removed.
3. **Non-class PHP files.** The 15 `woodev/*.php` files absent from `class-map.php`
   (view templates, `index.asset.php` manifests, `functions-license-authority.php`) were
   grepped individually by basename; every one is `include`/`require`d by path from
   production code.
4. **Assets (JS/CSS/images/fonts).** Each JS/CSS file's basename was grepped across the
   whole repo. Several PHP files build the enqueued filename dynamically
   (`$handle . '.css'` etc.) rather than spelling it out — those were traced by hand to their
   `$handle` assignment rather than trusted on a bare zero-hit grep. Card-brand images
   (`assets/images/card-*.{png,svg}`) are resolved the same way, via
   `class-payment-gateway.php:1346` building `'images/card-' . $image_type . $image_extension`
   — confirmed as one mechanism, not enumerated file-by-file.

Not covered: `docs/`, `docs-internal/`, `.github/`, images/fonts other than the card-brand
set and `woodev-icon-16x16.png` (spot-checked, both wired), and anything under
`plugins-reference/` (excluded per the standing rule — it carries framework 1.3.3/1.4.0 and
predates every v2 API, so a hit there proves nothing about v2 aliveness).
