# Shipping model, rates, location, and pickup

## Methods and rate calculation

- Extend `Woodev\Framework\Shipping\Shipping_Plugin`; implement abstract `get_shipping_method_classes()` and `get_api()`. `register_shipping_methods()` is final. It keeps only loaded subclasses of `Shipping_Method`; include/require method classes before this list is read or an unloaded class is silently dropped. See `woodev/shipping-method/class-shipping-plugin.php` (`get_valid_shipping_method_classes()`, `register_shipping_methods()`).
- Implement these `Shipping_Method` contracts with the exact signatures below. A direct subclass also implements `get_delivery_type()`; `Shipping_Method_Courier`, `Shipping_Method_Pickup`, and `Shipping_Method_Postal` provide it as final. `calculate_shipping()` and `calculate_rate()` are final; `rate_package()` is the carrier rate seam. See `woodev/shipping-method/class-shipping-method.php` and `class-shipping-method-{courier,pickup,postal}.php`.

  ```php
  public static function get_method_id(): string;
  public function get_delivery_type(): string; // direct Shipping_Method subclass only
  protected function get_plugin(): Shipping_Plugin;
  protected function get_method_form_fields(): array;
  protected function rate_package( array $package, ?\Woodev_Packer_Result $packed ): ?Shipping_Rate;
  ```

- Return a `Shipping_Rate` or `null` when unavailable. Keep the carrier's total as returned; the framework does not sum parcel prices. See `woodev/shipping-method/class-shipping-rate.php` and `docs-internal/gotchas/shipping-rate-no-parcel-sum.md`.
- **One method id per delivery type.** The framework tells a pickup method from a courier one by its method id (`Checkout_Config::pickup_method_ids()`, `woodev/shipping-method/checkout/class-checkout-config.php:466`), so a single id cannot be both. A v1 plugin that served both from one id ships two (CDEK: `edostavka` → `edostavka_courier` + `edostavka_pickup`, spec decision s157) and its migration rewrites the zone instance rows while old orders keep resolving under the old id — see [settings and migration](settings-migration.md#splitting-a-v1-method-id).
- **"Not served" is `null`; "failed" is an exception.** Return `null` from `rate_package()` when the carrier legitimately does not serve the case: the destination, a door tariff with no usable sender address (CDEK hides modes 1, 2, 6 without one — edostavka#10), a tariff not allowed for the parcel. Never quote from a different origin silently. A carrier or transport failure is a thrown `Woodev_Plugin_Exception`: the framework logs it redacted at ERROR level, hides the method for this package, never rethrows, and fires `woodev_shipping_method_rate_calculation_failed` (`Shipping_Method::handle_rate_calculation_failure()`) so a site can add a fallback; it never renders the carrier's text.
- `Shipping_API` exposes `calculate_rates( array ): \Woodev_API_Response`, `get_pickup_points( array ): \Woodev_API_Response`, `create_order( \WC_Order ): \Woodev_API_Response`, `get_order( string ): \Woodev_API_Response`, `cancel_order( string ): \Woodev_API_Response`, `get_tracking( string ): \Woodev_API_Response`, `get_request(): \Woodev_API_Request`, and `get_response(): ?\Woodev_API_Response`. `get_api()` returns this interface; `Abstract_Shipping_API` supplies HTTP plumbing. Source: `woodev/shipping-method/api/interface-shipping-api.php`.

## Rate cache and packing

- Rate caching is opt-in. Override `get_rate_cache_context( array $package ): array`, call `$context = parent::get_rate_cache_context( $package );`, add every quote input the parent cannot see, then return it. The parent includes package/destination, method instance settings, packing, payment, and selected pickup point; add credentials, global account/origin settings, and other inputs read by `rate_package()`. Values must be finite scalars, `null`, or arrays of those; invalid context disables caching. See `woodev/shipping-method/class-shipping-method.php` and `class-shipping-rate-cache.php`.
- Declare features such as `FEATURE_RATE_CACHE`, `FEATURE_BOX_PACKING`, or `FEATURE_SHIPPING_CLASSES` after `parent::__construct()` with `add_support()`, or set `$this->supports` before the parent call. Calling `add_support()` before the parent leaves the method id unset and fires its hook under the wrong name. Box packing and shipping classes also shape instance fields. See `Shipping_Method::add_support()`.
- The framework supplies missing product dimensions through `Default_Dimensions_Settings`; treat these as fallbacks to catalog weight and dimensions. For parcel packing, use `FEATURE_BOX_PACKING` and the contracts in `woodev/box-packer/`; see `docs-internal/wiki/architecture.md` and `docs-internal/gotcha-index/box-packer.md`.
- Packing: `FEATURE_BOX_PACKING` adds the `packing_algorithm` select (`virtual`, `separately`, `boxes`; the retired `single` is read as `virtual`). The store's boxes live in «Доставка» → «Упаковка», the carrier's presets come from `get_box_presets()`, and both the virtual box and the `boxes` mode now rest on a REAL 3-D placement. Modes, units, parcel contents (`pack_order()`, `get_items()`), cache identity and the migration of a v1 box list: [packaging](packaging.md).
- Optional per-method features — cost limits, insurance, fee by payment method, city limit, additional services, instance `show_if` — and the traps each one brings: [method features](method-features.md).

## Location

- Location support is opt-in: override `Shipping_Plugin::needs_location_provider()` to return `true`, and then MUST override `get_location_adapter()` to return a `Location_Adapter`. Its `resolve( Location_Record )` maps the neutral record to an opaque carrier identity; return `null` when not served and throw only for a retryable failure. Resolve the carrier's city code through the CARRIER'S OWN lookup first. Only when that finds nothing, fall back to `$this->get_location_service()->get_delivery_ids( $record )` — DaData `findById/delivery`: Russian settlements only, a SECONDARY source whose ids DaData scrapes from carriers and so may be stale; verify any id it gives against the carrier before trusting it. It is keyed by FIAS only (`settlement_fias_id ?: city_fias_id`; KLADR is obsolete — rely on it nowhere) and never needs the DaData token or `raw()` read by the plugin. It answers `[ 'cdek_id' => '44', 'boxberry_id' => …, 'dpd_id' => … ]` (strings; absent carrier = absent key) and `[]` for a non-RU record, DaData not configured, a record not from DaData, or no answer; it throws `Location_Provider_Exception` only on a transport failure (retryable — let it propagate from `resolve()`). If the plugin returns true without the adapter, resolution reports `_doing_it_wrong()` and cannot produce the carrier identity. See `woodev/shipping-method/class-shipping-plugin.php` and `woodev/shipping-method/location/interface-location-adapter.php`.
- DaData is bundled in `woodev/shipping-method/location/providers/class-dadata-provider.php`. The shared layer owns locality inputs, search, popular settlements and the region → settlement cascade. Do not create a carrier city dropdown.
- **A carrier with its own dictionary ships a `Location_Provider`** (CDEK, #49; plugin `includes/location/class-cdek-location-provider.php`, commit `09cdd0c`). Extend `Abstract_Location_Provider` — it derives `get_capabilities()` from the methods you implement (`CAPABILITY_LIST` = region/settlement lists, which is what offers the «ready list» field mode; `LOCATE`, `NORMALIZE`, `RESOLVE_KEY`) — and add the instance through the filter `woodev_location_providers` (`Location_Provider_Registry::FILTER_PROVIDERS`; an entry that is not a `Location_Provider` is dropped with `_doing_it_wrong()`). The provider is active only while its `is_configured()` is true; a provider that reuses the carrier's API credentials declares no fields of its own and MUST override `is_configured()` (architecture, "Where a location provider's credentials live"). Without it a shop with no DaData key has no city suggestions at all.
- **Identity is the carrier's own and namespaced.** CDEK: region `cdek:r<region_code>`, settlement `cdek:<city code>`; the `r` keeps two integer spaces from colliding, and the delivery id of a picked settlement IS the carrier city code, so the adapter reads it off the key without a lookup. Records from another provider are matched by FIAS or by name — never by KLADR.
- **A failure throws `Location_Provider_Exception`; it never becomes an empty answer** — an empty list reads as «no such city» and silently removes the method from checkout. A search scoped to a region must read that region's LIST, not the carrier's name suggest (gotcha [list by region scope](../../../../docs-internal/gotchas/list-by-region-scope-not-suggest-by-name.md)); a record from another provider narrows by a unique name match and reports the `degraded` verdict.
- **Cache the dictionary small and check the write.** A region list is one transient of compact short-keyed rows; CDEK's largest region (≈ 6 000 settlements) is ≈ 0.9 MB, right at memcached's default 1 MB item limit, and `set_transient()` returning `false` is not checked — every keystroke would refetch the region. A paging loop with a ceiling must not store a truncated list as complete. These are the known limits tracked in edostavka#60; do not copy the pattern without a size guard.
- **A DaData record under a non-Russian user locale is transliterated** and never matches a Cyrillic carrier dictionary: ask `Location_Service::get_record_in_language( $record, 'ru' )` (DaData `findById/address` with an explicit language, cached, failure throws and is never cached) before matching names. Gotcha [an English-locale record cannot be matched against a Cyrillic dictionary](../../../../docs-internal/gotchas/an-english-locale-record-cannot-be-matched-against-a-cyrillic-dictionary.md) (#1152). Under `ru` DaData's carrier id was right in 13/13 localities on the CDEK contour (s159), but still verify it against the carrier.
- **The stored field mode outlives the chooser.** A stored `related-list` (e.g. carried over by a v1 migration) that the active provider cannot serve is clamped on READ at checkout and, since #1216, in the admin too (`Woodev_Abstract_Settings::get_display_value()`); the stored option is never rewritten on read, and a save persists what is displayed. Never write code that treats the stored value as the effective one, and guard checkout on `Location_Service::is_level_chooser_available()`, not on the stored mode alone — gotcha [a stored field mode outlives the chooser](../../../../docs-internal/gotchas/a-stored-field-mode-outlives-the-chooser-and-a-guard-keyed-on-it-blocks-checkout.md).
- Preserve the selected location's stable key and record; display names are not identifiers. See `Location_Service::resolve_for()`, `interface-location-provider.php`, and [shipping traps](traps.md).

## Pickup and checkout

- A pickup method implements `Shipping_Method_Pickup::get_point_source()` and returns a `Point_Source`; the inherited `get_pickup_point_source()` exposes it to the pickup REST and rate paths. Implement `fetch_points()` and `fetch_details()` with normalized `Pickup_Point` values. Bulk sources receive a locality query; viewport sources receive bounds and must honor point-type filters. See `class-shipping-method-pickup.php`, `interface-point-source.php`, `class-point-query.php`, and `class-pickup-point.php`.
- The plugin constructs and returns a `Pickup_Handler` from `Shipping_Plugin::get_pickup_handler()`. It has 14 positional constructor arguments; copy `init_realistic_pickup()` in the realistic fixture so the plugin is argument 14 and `Selection_Scope` is argument 13. Missing plugin context falls back to DOM place names; missing selection scope removes Store API transport and the block checkout pickup button. **Call `$handler->register()` yourself, once, from the memoised builder** — `Shipping_Plugin::add_hooks()` registers the checkout and webhook handlers for you but NOT the pickup handler; without the call there is no checkout button, no REST controller and no selection persistence, and no error. Do not call `register()` on the checkout handler — the framework already does.
- The plugin also constructs and returns `Checkout_Handler` from `get_checkout_handler()`. The fixture builds `Checkout_Fields`, a pickup field, and method scope there. If omitted, there are no managed checkout fields or `persist_values()` order-marker write. `Checkout_Field_Policy` handles shared fields. The framework supports classic and block checkout; do not duplicate the selector/map or rely on classic hooks for Store API behavior.
- `get_webhook_handler()` must return the constructed webhook handler or the framework does not register its route. See the override table below.
- Use loader `type => 'shipping'`; shipping defaults `blocks.cart` and `blocks.checkout` to true. Declare `supported_features['hpos'] => true` only when the plugin supports HPOS. See `Framework_Plugin_Loader_Definition::get_supported_features_for_definition()`.

- **A point's verdict**: `Constraint_Checker::check( $point, $payment_method, $cart_weight )` decides selectable/blocked from weight and cash-on-delivery; the filter `woodev_shipping_pickup_point_selectable` customises it and runs while the LIST is drawn, once per point — keep it to constants and stored data. CDEK uses it to keep offices and parcel lockers apart inside ONE pickup method (s157). Cell fit of a locker is not on `main` yet: [packaging](packaging.md#parcel-locker-cells--not-on-main-yet).
- **The point reaches the address through the framework** (`pickup_replace_address`, default on: address AND postcode). Hand it only a numeric postcode of 4–10 digits — CDEK's contour returned «Адрес» as a postcode and it broke the block form (edostavka#7; `Cdek_Pickup_Point_Mapper`, `preg_match( '/^\d{4,10}$/' )`).
- **Order data of a point**: keep the SCALAR point id where the retry guard, the orders filter and the export already read it, and the full snapshot in a NEW meta key (CDEK: `_wc_edostavka_pickup_point_data`); the row and the metabox show the snapshot only while the scalar still matches (edostavka#9).
- **Warehouses belong to the carrier, not the framework** (operator, #1147): a per-method override of a shop-wide sender address; no silent fallback to the seller's legal address (edostavka#10).

## Plugin override seams

`Shipping_Plugin` defaults the nullable handlers below to `null`; the framework does not construct them for you. See `woodev/shipping-method/class-shipping-plugin.php`.

| Plugin seam | What to return or implement | If omitted / fixture |
|---|---|---|
| `get_shipping_method_classes()` and `get_api()` | Abstract methods: return loaded method class names and the `Shipping_API`. | Methods are not registered or API operations have no carrier implementation. See `class-realistic-shipping-plugin.php`. |
| `needs_location_provider()` + `get_location_adapter()` | Opt in with `true` and return the required adapter. A carrier dictionary is added separately, through the `woodev_location_providers` filter. | Shared locality section and resolution stay inactive or carrier identity cannot resolve. See `class-test-location-adapter.php`, `class-test-cdek-location-provider.php` and, for a production provider, the CDEK plugin's `includes/location/`. |
| `get_checkout_handler()` | Return a configured `Checkout_Handler` with managed fields and pickup method IDs as needed. | No managed checkout fields, persistence, or marker write. See `class-realistic-shipping-plugin.php`. |
| `get_pickup_handler()` | Return a configured `Pickup_Handler` with source, scope, and owning plugin, and call its `register()` yourself (the framework does not). | No shared map/settings or proper selected-point cache context. See `init_realistic_pickup()` in `class-realistic-shipping-plugin.php`. |
| `get_webhook_handler()` | Return the handler instance. | `add_hooks()` cannot register its REST route. |
| `get_tab_settings_providers()` | Return `Settings_Provider` descriptors with plugin-global `Woodev_Abstract_Settings` handlers. | Plugin-specific global settings tab sections are absent. No carrier fixture overrides it yet: see `tests/unit/Shipping/Settings/CarrierSettingsTabTest.php` for the seam and `tests/_fixtures/woodev-test-plugin/woodev-test-plugin.php` (`Woodev_Test_Settings`) for the handler/section/connection shape. |
| `get_integration_handler()` | Optional legacy WooCommerce integration handler. | Only needed when preserving an existing integration surface; it is not the usual settings provider seam. |
| `is_configured()` | One line answering from the carrier's own settings. | The «<плагин> не настроен» notice never shows, or never goes away. See [SKILL.md](../SKILL.md). |
| `get_box_presets()` / `uses_boxes()` | The carrier's own boxes in cm/kg. | No carrier boxes. See [packaging](packaging.md). |
| `get_export_section_setting_ids()` / `get_export_section_extension()` | Own fields / cards / actions of «Выгрузка заказов». | Section carries the framework's cards only. See [settings and migration](settings-migration.md#framework-sections-of-the-carrier-tab). |
| `init_lifecycle_handler()` | A `Woodev_Lifecycle` subclass: upgrades, v1 migration, milestones. | No migration, no milestone text (see [orders and tracking](orders-tracking.md#milestones)). |
| `get_setup_wizard_handler()` | An onboarding / migration wizard on the Setup Wizard v2 engine. | No wizard. See [settings and migration](settings-migration.md#migration-wizard). |

## Checkout traps

- Never hide a required field only in JavaScript; server validation can still reject an invisible field. Block checkout uses Store API requests, not classic checkout hooks. See [shipping traps](traps.md).
- Managed custom checkout fields are intentionally blank on reload; persist the order data through the framework handler rather than assuming a field value will repopulate itself.
